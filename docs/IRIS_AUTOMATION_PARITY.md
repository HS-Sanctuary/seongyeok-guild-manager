## 구현된 오버레이와 구분

2026-10-04 최신: 현재 창은 커맨드센터/스테이터스/가공/게임 미션/생텀 연결·크로노스/독립 크로노스 체크보드다. 가공3×2 및 작업별 완료 표시가 로컬 후보이며 수령 버튼은 아직 없다. 게임 미션은 게임의 일·주간 합계, 체크보드는 생텀의 항목별 저장 상태로 서로 다르다. 체크보드에 저장 클래스 레벨 목록도 추가했지만 게임의 전체 클래스 자동 조회가 아니다. 에린 환경·음악회·미디어·자동 종료는 미구현이다.

한설은 이번 진행에서도 AI(아님)커넥터 전체 기능을 최종 목표로 재확인했다. 위 자동 작업 표는 전부 추적하며 읽기 위젯 완성을 자동화 완료로 간주하지 않는다. 다음 구현 후보는 시설별 수령의 명시 실행·중지·실패 재조회 경계다. 해당 상세 설계·테스트 계획과 게임 정책/지원 계약을 검토하고, 실제 게임 동작 수동 검증은 한설이 한다. 현재 `reader.mjs` 허용 명령을 넓히거나 실제 수령/채집/제작을 실행하지 않았다.

## 공식 수령 명령 계약 재확인

실제 game action 없이 CLI `capabilities`만 조회했다. 제한된 환경은 game_off를 반환했고 격리 밖의 메타데이터 조회로 계약을 확인했다. `complete_altering_work`는 완료된 작업의 DisplayName으로 시설을 선택해 이동과 해당 시설 완료품 전체 수령을 처리한다. accepted만으로 성공이 아니다: timeout/blocked/canceled/stopped_by_user를 분리하고 재조회해야 한다. 입력 원본문구는 동작 경계에서만 메모리 사용하고 공개 snapshot/문서/로그에 저장하지 않는다.

## 자동화 정책

자동 채집/가공/수령 설정은 기본 꺼짐으로 만들고, 사용자가 대상을 정하고 켠 범위에서만 동작한다. 명시 시작·중지, 한 게임 동작만 실행, 작업 상한/소모 안내, 게임 상태 차단, 실패 시 자동 반복 금지 및 정상 재확인이 필요하다. 실제 게임 조작을 Codex 검증으로 실행하지 않는다. 광범위 게임 정책/배포 가능성이 확인되지 않은 상태에서 공식 공개 허용을 단정하지 않는다. 운영 DB·RLS·배포는 이번 범위가 아니다.
