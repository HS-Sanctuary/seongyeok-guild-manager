# 영겁 ↔ 순월 Codex 릴레이

이 문서는 집 호스트 `영겁`과 사무실 호스트 `순월`이 Git을 통해 작업 맥락을 잃지 않고 이어가기 위한 대화 규약이다. 모든 작업 세션에서 `AGENTS.md` 다음으로 가장 먼저 확인한다.

## 수신함

- 영겁이 읽을 메시지: `docs/relay/TO_YEONGGEOP.md`
- 순월이 읽을 메시지: `docs/relay/TO_SOONWOL.md`
- ACK 완료 후 옮긴 기록: `docs/relay/ARCHIVE.md`

## 상태

- `EMPTY`: 전달할 메시지가 없음
- `WAITING`: 새 메시지를 상대가 아직 확인하지 않음
- `UPDATED`: ACK 전에 발신자가 새 작업을 추가함
- `ACKNOWLEDGED`: 수신자가 읽고 이해했다는 ACK를 남김
- `ARCHIVED`: 발신자가 ACK를 확인하고 기록을 보관함

## 누적 전달 규칙

1. 발신자는 공식 push 전에 상대 수신함을 갱신한다.
2. 기존 상태가 `WAITING` 또는 `UPDATED`라면 메시지를 새로 덮어쓰지 않는다. 같은 메시지 ID 아래 `누적 작업`에 새 항목과 커밋을 시간순으로 추가하고 상태를 `UPDATED`로 바꾼다.
3. 아직 ACK되지 않은 완료 작업, 실패 원인, DB·배포 여부, 다음 할 일, 금지사항은 삭제하지 않는다.
4. 수신자는 작업 시작 시 자기 수신함을 먼저 읽고, 이해한 범위를 `ACK`에 자신의 이름·KST 시각·확인 커밋과 함께 적은 뒤 상태를 `ACKNOWLEDGED`로 바꾼다.
5. ACK는 “읽었다”는 뜻이지 “후속 작업을 완료했다”는 뜻이 아니다. 후속 결과는 반대편 수신함에 새 메시지 또는 누적 업데이트로 보낸다.
6. 발신자는 상대 ACK가 Git에 올라온 것을 확인한 뒤에만 기존 메시지를 `ARCHIVE.md`로 옮길 수 있다. 이후 새 메시지 ID를 시작한다.
7. 양쪽이 동시에 수정해 충돌하면 어느 한쪽 내용을 버리지 않는다. 두 내용을 모두 보존해 시간순으로 합친다.

## 메시지 ID

- 순월 → 영겁: `SW-YYYYMMDD-NNN`
- 영겁 → 순월: `YG-YYYYMMDD-NNN`
- 같은 미확인 대화는 ID를 유지하며 누적한다.

## 메시지 필수 항목

- 상태, 발신자, 수신자, 최초 작성·최종 갱신 KST
- 관련 커밋과 배포 상태
- 누적 작업: 무엇을 왜 바꿨는지
- 현재 상태: 검증 결과와 데이터 영향
- 이어서 할 일: 우선순위가 있는 구체적 행동
- 주의·금지: DB 변경 승인, 비밀값, 미완료 위험
- ACK: 수신자·확인 시각·확인 범위

`docs/HANDOFF.md`와 내용이 일부 겹쳐도 괜찮다. HANDOFF는 전체 현황을 최신값으로 유지하고, 릴레이는 상대가 확인할 때까지 과거 전달분을 누적 보존한다.
