# SANCTUM 운영 결정 기록

되돌아봤을 때 "왜 이렇게 만들었는지"가 중요한 결정만 기록한다. 단순 UI 조정이나 일회성 오류 수정은 업데이트 노트에 남긴다.

## D-012 — 2026-09-25 KST (운영 SQL 적용, 앱 Preview 후보)

**결정:** LOGOS의 생텀 버그 제보·건의사항은 작성 60일 후 자동 삭제하지 않는다. 작성 시 삭제 가능성을 알리고, 60일이 지난 각 글을 길드마스터의 사이트 알림함·글 카드에 검토 대상으로 표시한다. 길드마스터가 삭제를 확인하면 글·답변·비공개 첨부 사진을 함께 정리한다. 보류하면 해당 글의 다음 검토일을 결정 시점에서 60일 뒤로 옮긴다. 미처리 글은 계속 검토 대상으로 남는다. 기존 1:1 문의는 이 60일 검토 대상에 포함하지 않는다.

**이유:** 미해결 제보가 자동으로 사라지지 않게 하면서 오래된 사진·글의 보존 여부를 글마다 판단한다. 현재 알림은 사이트 접속 중 표시되며, 앱이 닫힌 뒤 휴대폰 푸시나 이메일 발송은 제공하지 않는다. 운영 SQL·배포 전에는 백업 및 실제 권한 검증이 필요하다.

## D-011 — 2026-09-24 KST (로컬 설계, 운영 미적용)

**결정:** LOGOS의 생텀 버그 제보·건의사항은 기존 비공개 문의 기록을 재사용하되, 사진 원본/base64를 DB나 메일 첨부로 보내지 않는다. 브라우저에서 350KB 이하 WebP로 줄인 뒤 비공개 Storage에 최대 3장 보관하고 DB에는 경로만 저장한다. 일반 길드원은 자기 글, 길드마스터는 전체 제보·건의를 확인한다. 메일 알림은 제공자·수신 주소·실패 재시도·개인정보 범위가 정해진 뒤 링크 알림으로 별도 설계한다.

**이유:** 메일 첨부는 전달 실패와 중복·비밀 정보 유출 위험이 있고, base64 본문은 작은 DB에도 용량/백업 부담을 만든다. 비공개 저장소와 서버 권한 확인은 사진 읽기 범위를 통제할 수 있다. 운영 SQL·배포 전에는 한설 승인과 실제 권한 검증이 필요하다.

## D-010 — 2026-09-24 KST

**결정:** 크로노스의 상점 구매는 기존 물물교환과 별도로 골드 가격·일간/주간 초기화·캐릭당/계정당 상한을 유지한다. 즐겨찾기 품목을 앞에 보이고, 연속 클릭과 MAX는 원자적 묶음 저장으로 처리한다. 상한 도달 시 MAX는 MIN으로 바뀌어 한 번에 0으로 되돌리고, 전량 골드는 단가×상한의 고정 합계를 보여준다. 임무 게시판은 마을 탭 없이 전체를 보이며, 마을 이름도 검색하고, 즐겨찾기를 먼저 보인 다음 이멘마하→반호르→콜헨→던바튼→티르코네일 순으로 정렬한다.

**이유:** 상점 품목을 한 번에 여러 개 구매하는 실제 조작에 맞추면서 주기·범위별 기록을 섞지 않는다. 임무 수가 적어 마을 탭보다 검색이 간단하고, 즐겨찾기 탭 없이도 중요한 임무를 바로 볼 수 있다. 향후 GNOSIS 아이템 라이브러리에서 아이템 이름을 눌러 계정 창고 공유 가능 여부를 보여주는 구상은 기록만 하고, 데이터 출처·공개 범위가 정해지기 전에는 구현하지 않는다.

## D-009 — 2026-09-24 KST

**결정:** 한설이 한글 코드 직접 로그인에 성공해 영문 키 자동 변환은 채택하지 않았다. 좋아하는 것과 생일은 길드마스터 전용 명단의 별도 프로필로 신규 가입 때부터 저장한다. 기존 계정은 추측으로 채우지 않는다. 생일 배너는 공개 범위와 당사자 동의를 정한 뒤 별도로 구현한다.

**이유:** 로그인 실패 원인은 로컬 서버의 DB 연결이었고 코드 문자 종류가 아니었다. 기존 코드의 뜻을 임의로 바꾸지 않으며, 코드 문자열을 분석해 개인정보를 추출하지 않는다. 좋아하는 것과 생일은 접속 코드의 구성 요소이므로 부마스터·대행에게 동시에 노출하지 않는다.

## D-008 — 2026-09-24 KST

**결정:** 한설의 명시 요청으로 크로노스 상점·마을 임무·리마인드를 확장한다. 운영 DB 적용은 한설이 아침에 SQL Editor에서 실행한다. 임무 주간 기준은 월요일 06시 한국 시간이며 북마크·메모는 보존한다. 구매와 교환은 서로 다른 카탈로그/기록으로 분리한다.

**이유:** 물물교환은 아이템, 상점 구매는 골드를 소모한다. 기존 구매·임무 테이블의 미확인 컬럼/제약을 덮어쓰지 않기 위해 새 명시적 테이블을 추가하고 기존 테이블은 보존한다. 리마인드는 다른 숙제를 함께 조작해야 하므로 바깥 클릭으로 닫히지 않는 비모달 작업창으로 제공한다.
