# SANCTUM 운영 결정 기록

## 2026-10-08 — IRIS는 컴팩트 애드온 바를 기준으로 push, 실게임 검증은 분리

- 현재 IRIS는 모비노기 옆에 두는 애드온 바이며 완성된 게임 오버레이로 안내하지 않는다. 창 추적은 게임을 이동·크기 변경·입력 제어하지 않고 IRIS만 붙인다.
- 표시 테마는 IRIS 전용 경계를 사용하고, 계정별 재화 강조만 로컬에 저장한다. 재화 잔액·조회 시각·캐릭터별 재화 이력은 저장하지 않는다.
- 게임 종료 질문은 게임이 종료된 뒤 IRIS에서만 표시한다. 저장/보관 실패·불명확한 결과·인증 만료에서는 창과 보호 큐를 유지한다. 게임 종료 질문에는 버리기를 제공하지 않는다.
- 자동·합성 검증을 먼저 묶고 실게임 이동/DPI/최소화/종료는 집 호스트 영겁과 후속 수동 확인으로 분리한다. 이번 push는 후보 공유이며 실게임 성공을 의미하지 않는다.

## 2026-10-08 — 캐릭터 감지 지연 단축

- 한설이 실제 캐릭터 변경 추천을 확인했으나 약10초 지연이 길다고 제보했다. 운영 DB/Vercel 호출이 늘지 않는 조건으로 기존10초 간격을 로컬 CLI 평소3초/첫 안정 후보 이후1초 재확인으로 단축하도록 승인했다.
- 주기 DB 조회/자동 스탯 저장은 추가하지 않는다. 본인 카탈로그 재사용/없으면1회 fallback, 수동 선택·저장 계약을 유지한다. 서로 다른 신선한 관측2회는 유지하며 후보별 빠른 재확인은1회, 캐시 반복/실패는3초로 복귀한다. 조회 완료 뒤 다음 타이머를 걸어 느린 CLI의 겹침/누적을 막고 숨김·잠금·종료·계정/선택 변경 방어를 보존한다.
- CLI 실제 실행 횟수는 늘며 실게임 응답/부하에 따라 체감 시간은 달라진다. 1~4초는 의도된 대기 범위이며 실제 CLI 조회 시간이 더해진다. 게임 커넥터가 반드시10초 재연결을 요구한다는 근거는 확인하지 않았다.

## 2026-10-08 — IRIS 애드온 바 기반과 캐릭터 변경 추천

- 한설이 현재 IRIS를 게임 옆에 상주하는 컴팩트 애드온 바로 정의했다. 이 버전을 먼저 유용하고 안정적으로 발전시키고, 데이터 조회·추천·저장 기능을 공유하는 별도 오버레이 버전으로 확장한다. 현재 작은 창을 완성된 게임 오버레이로 안내하지 않는다.
- 승인: 숙제 분류 제목은 옅은 테마색 띠·왼쪽 강조 표시·완료 배지, 분류 사이 얇은 구분선을 사용한다. 두 열/횟수 행의 컴팩트함과 분류 표시 토글은 유지한다.
- 승인: 선택 후 약10초 간격 게임 스탯 읽기로 변경을 추측하되 다른 후보가 연속 두 번 확인될 때만 묻는다. 동일 관측 재사용·장비 한 스탯 변화·오래되거나 부족한 값·비슷한 후보는 전환 근거가 아니다. 네는 최신 게임 값을 재확인 후 선택만, 아니요는 현재 선택 유지/같은 후보 반복 억제, 다른 캐릭터는 기존 선택창을 연다.
- 추천은 UUID나 게임 신원 확인이 아니다. 추천/수락으로 스탯 DB를 자동 수정하지 않으며, 기존 캐릭터별 숙제/클래스 대기함 보존·직접 업데이트 확인 정책은 유지한다. DB 구조/권한/배포는 이번 승인에 포함되지 않는다.

## 2026-10-08 — IRIS 숙제 약칭 체크보드

- 최종 후속은 초기 아코디언 설계를 대체한다. 일일/주간/어비스/레이드를 모두 켜진 표시 토글로 제공하고 우측에 미완료만 체크를 둔다. 해제는 해당 분류만 숨기며 기록/대기 변경은 보존한다. 외곽 구분 테두리와 준비 중 보조3줄은 제거하되 준비 기능 버튼은 비활성 유지한다. 어비스·레이드는 전체 이름, 일일·주간만 기존 약칭을 사용한다.

- 한설 승인: 체크형은2열 약칭, 횟수형은 전체 폭 한 줄, 분류에는 완료 항목/전체 항목을 표시한다. 횟수 합산과 완료 항목 수를 혼동하지 않으며 남은 항목 필터는 합계/기록을 바꾸지 않는다. 보류 복구 행은 계속 보인다.
- 이름을 새로 임의 생성하거나 DB 원명을 바꾸지 않는다. 기존 mobile_name/short_name과 웹 cleanItemName을 표시용으로만 사용하고 원명/항목 ID/저장 계약은 보존한다.

## 2026-10-08 — IRIS 메뉴 계층과 선택 피드백

- 한설 승인: 상위는 크로노스/시낙시스/설정, 크로노스의 실제 기능은 숙제/클래스/스탯/재화. 물물교환/상점구매/임무게시판은 위치 확인용 비활성 준비 중 버튼만 제공하며 실제 기능으로 안내하지 않는다.
- 상단 생텀 선택 닉네임/직업은 스크롤 중에도 유지한다. 이는 사용자가 선택한 저장 대상이며 게임 닉네임·UUID 확인을 뜻하지 않는다. 저장 안내는 접고, 미저장 상태·오류·복구 경고는 유지한다. 메뉴 복귀는 마지막 하위 탭을 기억하며 조회는 기존 전환1회 규칙을 따른다.
- 재화는 현재 접속 게임의 읽기 전용 표시만 유지한다. 한설이 가치가 낮다고 판단한 다른 캐릭터 재화 이력/DB 저장은 만들지 않는다. 다음 작업은 시낙시스 읽기 연결이다.

## 2026-10-08 후속 — 로그인 추천과 저장 확인 분리

- 한설이 추천 목적을 재확인: 로그인 직후 현재 게임 직업/스탯과 본인 DB를 비교해 후보를 묻고 시작할 캐릭터를 선택한다. 단순 최상위 후보라도 비교 필드가 부족/큰 차이/비슷한 후보면 수동 선택한다. 4초 제한은 추천 UI 예산이지 CLI 자체 종료시간이 아니다. 추천 실패·늦은 결과가 앱 사용을 막지 않는다.
- 스탯 탭 상시 확인 카드를 제거한다. 업데이트 버튼 클릭 때만 현재 대상 닉네임을 확인하며, 네는 실제 게임 재조회/값 변경 시 재확인/소유권 CAS 저장, 아니요는 본인 캐릭터 선택. 추천 수락은 DB 저장 승인이 아니다.
- 짧은 계열 목록은 자연 높이, 전체/긴 목록만 내부 스크롤. 클래스 수동 저장과 15초 큐는 변경하지 않는다. 공식 capabilities와 재화 이름 확인 결과 공헌도/전체 클래스별 레벨 계약은 여전히 없으므로 자동 읽기 보류한다. 공헌도는 계정 공통값으로 향후 지원 계약이 생겼을 때 별도 연결한다.

## 2026-10-08 — IRIS 수동 스탯 연결과 묶음 검증

- 한설 승인: 직업·네 개 스탯 유사도는 본인 캐릭터 후보 안내에만 사용한다. UUID/해시/수치 조합은 게임 신원이 아니며 사용자가 현재 화면과 대상 닉네임을 확인한다. 유사 후보가 여러 명이면 자동 선택하지 않는다.
- 생텀 저장값 위 / 실제 인게임 관측값 아래 / 가운데 위쪽 화살표 수동 업데이트 버튼. 대상 확인·60초 이내 관측·업데이트 직전 동일 수치 재조회가 필요하다. 계정/캐릭터 변경·재조회·재시작은 확인을 해제한다.
- 기존 text 필드 전투력·생활력·마도저항·매력만 저장한다. 누락 유지, 실제 0·감소 허용, 세션 소유자 검증과 원본 CAS. 클래스별 레벨/공헌도/게임 조작/자동 저장은 제외한다. 응답 유실은 자동 재전송하지 않는다.
- 사용량 절약: 기능 묶음 단위로 구현한다. 작업 중에는 변경 관련 테스트, 완료 시 전체 회귀·타입·빌드를 한 번 묶는다. 반복 전체 검사와 불필요한 재조회를 줄이되 인증·소유권·충돌 검사는 생략하지 않는다. 운영 DB/배포/버전 변경은 별도 승인 사항이다.

## 2026-10-07 — IRIS 클래스 직접 수정으로 변경 (이전 가져오기 요청 대체)

- 공식 기능 목록에 전체 클래스 레벨 조회 계약이 없어 게임 자동 가져오기를 구현하지 않는다. 기본값은 캐릭터별 생텀 DB 저장값, 사용자가 직접 수정한다.
- 캐릭터를 선택했으므로 추가 닉네임 확인은 하지 않는다. 숙제와 같은 단일 대기 큐/15초 마지막 유효 조작 자동저장, 선택 캐릭터 지금 저장/버리기 사용. 캐릭터 이탈 후 이전 값은 별도 보존·전송한다.
- 빈칸/소수/범위 밖 초안은 해당 캐릭터의 전송·전환을 보류하며 정정 또는 입력 되돌리기를 요구한다. 다른 캐릭터의 유효 변경은 막지 않는다. 클래스 레벨은 숙제 초기화 시간의 영향을 받지 않는다.
- 기존 DB 구조를 유지하고 한 클래스 키만 원본 보존/CAS로 갱신한다. 구버전 보호 큐는 원본 암호문 백업을 남기며 전환 실패는 잠금. 실제 운영 데이터 쓰기는 사용자 수동 검증으로 구분한다.

## 2026-10-07 — IRIS 저장 피드백과 클래스 가져오기 요청

- 저장 피드백은 해당 실행에서 선택 캐릭터에 대해 서버가 성공을 응답하거나 원하는 저장값을 재확인한 시각을 표시한다. DB 실제 수정 시각 또는 앱 종료 전 이력을 추정하지 않는다. 기존 불명 결과 경고와 15초 저장 정책을 유지한다.
- 한설은 클래스 가져오기를 사용자의 명시적인 생텀 저장/대상 닉네임 확인 방식으로 요청했다. 이는 자동 신원 검증이 아닌 수동 연결 방향이며, 실제 게임 전체 클래스 읽기 계약 확인 전에는 생텀 기존 목록을 게임 관측값으로 간주하지 않는다. 전체 가져오기·서버 쓰기 경로 구현은 별도 설계 단계로 남긴다.

## D-020 — 2026-10-06 KST (IRIS 로그인·저장 편의 전환 후보)

- 한설이 매번 브라우저 읽기/쓰기 승인을 반복하는 방식 대신 생텀 계정 로그인, 캐릭터 직접 선택, 마지막 조작·캐릭터 변경 후 15초 저장과 별도 수동 저장을 승인했다. 기존 폴더의 미커밋 변경을 보존하며 진행한다.
- 새 내장 창의 로그인 유지에는 전용 HttpOnly 프로필을 사용하고 로그인 코드를 저장하지 않는다. 미저장 큐는 계정·캐릭터·기간별로 보호 저장하며 불명확 결과는 확인 없이 재전송하지 않는다.
- 실제 로그인·저장·게임 위 사용성 승인 전에는 기존 기본 실행기를 교체하지 않는다. 두 실행기를 공유 OS 잠금으로 막는다. 오프라인 보관 종료는 네트워크를 요구하지 않고, 실제 보관 실패에는 명시적 손실 경고 종료를 제공한다.
- 이번 구현은 로컬 후보이며 운영 DB/권한/배포 또는 게임 명령 실행 승인이 아니다.
