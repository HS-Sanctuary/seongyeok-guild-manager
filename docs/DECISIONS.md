# SANCTUM 운영 결정 기록

되돌아봤을 때 "왜 이렇게 만들었는지"가 중요한 결정만 기록한다. 단순 UI 조정이나 일회성 오류 수정은 업데이트 노트에 남긴다.

## D-001 — 2026-09-22 KST

**결정:** SANCTUM은 길드원 전용 폐쇄 베타로 운영하며, 개인정보 기반 계정 복구 대신 운영진의 입장 코드 재발급으로 복구한다.

**이유:** 길드 외부 공개 가입이 목적이 아니며, 운영자가 개인정보를 보관하지 않기를 원한다.

## D-002 — 2026-09-22 KST

**결정:** 탈퇴·추방 시 계정·캐릭터·파티 관련 데이터는 삭제하고, GNOSIS 게시물은 `탈퇴한 길드원`으로 익명화해 보존한다.

**이유:** 운영 데이터는 정리하면서도 길드 지식은 남긴다.

## D-003 — 2026-09-22 KST

**결정:** 공식 Git push 뒤 Vercel 배포가 성공한 경우, 향후 `SANCTUM 시스템` 작성자의 케리그마 업데이트 공지를 자동 게시한다. 가이드 공지는 실제 사용법/운영 규칙 변경 때만 게시한다.

**이유:** 길드원은 기술 문서 대신 자신에게 무엇이 바뀌었는지 쉽게 알아야 하며, 중복 공지로 피로를 주지 않는다.

## D-004 — 2026-09-22 KST

**결정:** 한설과의 Codex 협업 담당 작업명은 `영겁`으로 한다.

**이유:** SANCTUM의 분위기에 맞고, 길드원 대상 `SANCTUM 시스템` 공지와 내부 협업 주체를 명확히 구분한다.

## D-005 — 2026-09-22 KST

**결정:** 베타 오픈 24시간 전부터 기능 동결을 적용한다. P0/P1 문제만 수정하고, 새 기능·대규모 디자인 변경·DB 확장은 명시적 승인 없이는 미룬다.

**이유:** 소규모 길드 베타에서 오픈 직전의 새 변경은 안정성 검증 시간을 빼앗는다.

## D-006 — 2026-09-22 KST

**결정:** 매 공식 배포에는 직전 정상 배포 기준선을 남기며, 문제가 생기면 그 배포로 되돌리는 선택지를 우선 검토한다.

**이유:** 빠른 수정보다 빠르고 안전한 복구가 우선인 상황이 있다.

## D-007 — 2026-09-22 KST

**결정:** Supabase 구조의 기준 문서는 `docs/SUPABASE_SCHEMA.md`로 한다. DB 변경은 마이그레이션·스키마 문서·마스터 가이드·업데이트 노트·인계를 함께 갱신한다.

**이유:** 대화 기억이나 오래된 CSV가 아니라, 버전 관리되는 문서와 SQL을 단일 기준점으로 삼는다.
