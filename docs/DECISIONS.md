# SANCTUM 운영 결정 기록

## 2026-10-07 — IRIS 클래스 직접 수정으로 변경 (이전 가져오기 요청 대체)

- 공식 기능 목록에 전체 클래스 레벨 조회 계약이 없어 게임 자동 가져오기를 구현하지 않는다. 기본값은 캐릭터별 생텀 DB 저장값, 사용자가 직접 수정한다.
- 캐릭터를 선택했으므로 추가 닉네임 확인은 하지 않는다. 숙제와 같은 단일 대기 큐/15초 마지막 유효 조작 자동저장, 선택 캐릭터 지금 저장/버리기 사용. 캐릭터 이탈 후 이전 값은 별도 보존·전송한다.
- 빈칸/소수/범위 밖 초안은 해당 캐릭터의 전송·전환을 보류하며 정정 또는 입력 되돌리기를 요구한다. 다른 캐릭터의 유효 변경은 막지 않는다. 클래스 레벨은 숙제 초기화 시간의 영향을 받지 않는다.
- 기존 DB 구조를 유지하고 한 클래스 키만 원본 보존/CAS로 갱신한다. 구버전 보호 큐는 원본 암호문 백업을 남기며 전환 실패는 잠금. 실제 운영 데이터 쓰기는 사용자 수동 검증으로 구분한다.

## 2026-10-07 — IRIS 저장 피드백과 클래스 가져오기 요청

- 저장 피드백은 해당 실행에서 선택 캐릭터에 대해 서버가 성공을 응답하거나 원하는 저장값을 재확인한 시각을 표시한다. DB 실제 수정 시각 또는 앱 종료 전 이력을 추정하지 않는다. 기존 불명 결과 경고와 15초 저장 정책을 유지한다.
- 한설은 클래스 가져오기를 사용자의 명시적인 생텀 저장/대상 닉네임 확인 방식으로 요청했다. 이는 자동 신원 검증이 아닌 수동 연결 방향이며, 실제 게임 전체 클래스 읽기 계약 확인 전에는 생텀 기존 목록을 게임 관측값으로 간주하지 않는다. 전체 가져오기·서버 쓰기 경로 구현은 별도 설계 단계로 남긴다.

## D-011 — 2026-09-24 KST (로컬 설계, 운영 미적용)

**결정:** LOGOS의 생텀 버그 제보·건의사항은 기존 비공개 문의 기록을 재사용하되, 사진 원본/base64를 DB나 메일 첨부로 보내지 않는다. 브라우저에서 350KB 이하 WebP로 줄인 뒤 비공개 Storage에 최대 3장 보관하고 DB에는 경로만 저장한다. 일반 길드원은 자기 글, 길드마스터는 전체 제보·건의를 확인한다. 메일 알림은 제공자·수신 주소·실패 재시도·개인정보 범위가 정해진 뒤 링크 알림으로 별도 설계한다.

**이유:** 메일 첨부는 전달 실패와 중복·비밀 정보 유출 위험이 있고, base64 본문은 작은 DB에도 용량/백업 부담을 만든다. 비공개 저장소와 서버 권한 확인은 사진 읽기 범위를 통제할 수 있다. 운영 SQL·배포 전에는 한설 승인과 실제 권한 검증이 필요하다.

## D-010 — 2026-09-24 KST

**결정:** 크로노스의 상점 구매는 기존 물물교환과 별도로 골드 가격·일간/주간 초기화·캐릭당/계정당 상한을 유지한다. 즐겨찾기 품목을 앞에 보이고, 연속 클릭과 MAX는 원자적 묶음 저장으로 처리한다. 상한 도달 시 MAX는 MIN으로 바뀌어 한 번에 0으로 되돌리고, 전량 골드는 단가×상한의 고정 합계를 보여준다. 임무 게시판은 마을 탭 없이 전체를 보이며, 마을 이름도 검색하고, 즐겨찾기를 먼저 보인 다음 이멘마하→반호르→콜헨→던바튼→티르코네일 순으로 정렬한다.

**이유:** 상점 품목을 한 번에 여러 개 구매하는 실제 조작에 맞추면서 주기·범위별 기록을 섞지 않는다. 임무 수가 적어 마을 탭보다 검색이 간단하고, 즐겨찾기 탭 없이도 중요한 임무를 바로 볼 수 있다. 향후 GNOSIS 아이템 라이브러리에서 아이템 이름을 눌러 계정 창고 공유 가능 여부를 보여주는 구상은 기록만 하고, 데이터 출처·공개 범위가 정해지기 전에는 구현하지 않는다.
