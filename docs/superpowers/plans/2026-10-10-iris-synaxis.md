# IRIS 시낙시스 로컬 생성 연결

한설의 야간 위임으로 상점·임무 완료 후 이어서 진행한다. 운영 DB 시험 생성·삭제, SQL/권한 변경, push/배포/공지 없이 합성 검증한다.

## 설계 결정

- 작은 센터 안에서 일반 파티/길드버스를 선택하고, 활성 DB 컨텐츠·난이도·4/8인 정원·날짜·시간·공지를 입력한다. 어비스 통합은 세 던전을 전부 지원하는 난이도만 허용한다.
- 본인 캐릭터만 선택한다. 일반 파티는 한 캐릭터, 길드버스는 여러 본인 캐릭터와 반복 여부. 길드버스 생성은 기존 운영진 역할만 허용한다.
- 서버가 소유권·카탈로그·정원·역할·스탯·숙제 완료를 다시 읽어 기존 파티 형식으로 구성하고 기존 인증된 member-mutations 생성 경로를 호출한다. 공지는 memo/sub_content 둘 다 일치시킨다. 기존 웹 버스 엔진이 이후 가입/편성을 담당한다.
- 명시 생성 확인과 중복 클릭 방어. 생성은15초 자동저장에 넣지 않는다. 결과가 불명확하면 자동 재전송하지 않고 웹 파티 목록 확인을 안내한다. SQL 없는 이번 단계는 서버 간 exactly-once를 보장하지 않는다.
- 새 주기 조회/Realtime 연결을 만들지 않는다. 탭 첫 열기·사용자 새로고침·생성 직전만 조회한다. 현재 계정 변경/잠금/창 닫기 시 결과를 버리고 조작을 막는다.
- 생텀 기존 전체 파티 화면은 계속 사용한다. IRIS 내 참여/출발/회차 운영은 이번 생성 연결 범위 밖이다.

## 구현 순서

1. 순수 입력/활성 카탈로그/본인 캐릭터/서버 payload 테스트를 먼저 작성하고 실패 확인.
2. 제한된 GET/POST API와 기존 생성 경로 재사용, 인증·출처·크기·권한·실패 경계 테스트.
3. 좁은 UI/확인 단계/공지만 full-word wrap, 버튼 nowrap, busy/stale/unknown 제어와 합성 인터랙션.
4. 관련 테스트·타입·TSX 체크·최종 빌드. 문서에 로컬 후보와 실제 검증 제한 기록.
