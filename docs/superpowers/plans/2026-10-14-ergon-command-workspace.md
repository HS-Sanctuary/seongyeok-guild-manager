# ERGON 생활 관제실 구현 계획

한설 승인: 역할별 버튼색/선택 작업 중심/작은바+확장 작업화면 방향으로 ‘바로 구현시작’, 업데이트창은 이후. 기존 기능 checkout에서 직접 구현한다. 별도 에이전트별 구현은 하지 않는다.

## 범위와 계약

- 기존 계정/초안/작업계획/실행컴포넌트 수명·nonce·예산·원장·CLI를 보존한다. 새 게임 명령/원장 해제/DB·배포·공개버전 변경 없음.
- 현황/검색목록/선택 수량·부족재료·실행이 한 작업화면에 이어진다. 좁은 폭은 수직 재배치, 넓은 폭은 현황/목록/작업3영역. 역할별 금색 주요행동/청록 담기/무채색 조회/적색 현재중지, 상태는 텍스트와 표시를 병용한다. 모든 전역테마/320px/큰글자 대응.
- 넓은 모드는 고정 boolean UI bridge만 사용, 임의크기/경로/명령 입력 없음. 현재 모니터 작업영역 안에 배치, 닫으면 이전 좁은 창으로 복원. 기존 도킹폭 설정을 넓은 폭으로 덮지 않는다. 작은바 전환/문서이탈/메뉴이탈 시 복원. 구 native에는 불가 안내만, 게임 영향0.
- 미확정 기록은 ‘기록 확인’으로 실제 이력을 보여주되 해제 기능은 이번 범위에 넣지 않는다. 업데이트 노트창 변경은 후속.

## Task 1 — 회귀를 먼저 작성

- 실제 React에서 선택→수량→재료→준비 같은영역, 역할색/unknown→기록, 창펼침·복원·구앱 fallback, responsive/6테마/초안유지/추가소비0 검증.
- native 창영역 정책·bridge strictboolean/외부origin·epoch·게임작업중 거절 검증. 실패를 먼저 확인한다.

## Task 2 — 관제실 화면·역할색

- 기존 세션/실행 상태를 재사용하며 overview/material 분리·정렬/큰 수치 쉼표/짧은 상태·상세안내·실제 이력 연결.
- 수량/native확인/현재중지/메뉴왕복·느린준비·조회경합 기존 회귀 재검.

## Task 3 — opt-in 넓은 창

- native 범위제한 정책/bridge/store/화면토글. 도킹·컴팩트·저장폭은 보존. native 합성·컴파일 검증, 사용자 정상 종료 없이 재시작하지 않는다.

## Task 4 — 마감

- 독립 타입/lint/전체Node/관련React/native/격리빌드, 한 번의 최종 독립 리뷰·중요지적 한 번 수정. HANDOFF/구조/피드백/릴레이 기록. push는 별도 요청 전 금지.

## 판단 기록

- 사용자 ‘바로 구현’ 지시와 이미 승인한 대화 설계를 이번 구현 brief로 사용하며 추가 승인 대기를 반복하지 않는다. 기존 shared feature checkout 유지는 개인 변경과 경로가 겹치지 않고 실앱이 연결된 기존 작업방식이기 때문이다. 잘못 판단하면 해당 UI 재조정이 필요하므로 게임 실행 권한은 확대하지 않는다.
