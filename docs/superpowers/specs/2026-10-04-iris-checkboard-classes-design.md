# IRIS 독립 크로노스 체크보드·클래스 목록 설계

- 작성: 2026-10-04 KST, 영겁
- 단계: 한설의 설계/계획 inline 진행 승인 후 Task1~4 로컬 구현·자동 검증. 실제 사용자 새 체크보드 대조/DPI·장시간과 독립 리뷰는 대기다.
- 로컬 범위: 읽기 전용. commit/push/배포, 운영 DB·RLS 변경, 게임 조작은 포함하지 않는다. Git 승인 없이 문서를 커밋하지 않는다.

## 의도와 선택한 방향

한설은 실제 연결된 캐릭터의 숙제를 합계뿐 아니라 항목별로 확인하고 클래스별 레벨을 접어서 보고 싶다. 기존 독립 위젯, 테마·투명도·표시/숨김·클릭 통과 기능을 보존한다. 센터 안에 전체 목록을 넣으면 관리창이 커지므로 센터 상단의 숙제 진입점과 독립 크로노스 체크보드를 선택했다. 기존 생텀 연결 위젯은 연결·캐릭터 선택·요약 역할을 유지한다.

이번 성공 기준은 본인 캐릭터 확인 후 항목별 상태와 저장된 클래스 레벨 표시, 다른 캐릭터 선택 시 이전 정보 즉시 제거, 연결 만료 시 오래된 값 제거다. 체크보드라는 명칭은 이번 단계에서 조회용이며 체크 수정/저장은 아직 아니다.

## 화면

- 센터 상단에 `숙제` 버튼을 추가해 독립 `크로노스 체크보드`를 표시/복구한다. ×는 해당 위젯만 숨기고 프로그램 종료는 센터의 확인 절차를 유지한다.
- 체크보드 상단에는 선택한 캐릭터 전체 닉네임과 `생텀 기록 · 읽기 전용`을 표시한다. 게임 미션 위젯과 출처를 구분한다.
- 일일·주간·어비스·레이드는 각각 아코디언이다. 제목에는 완료/전체 합계, 펼친 목록에는 전체 항목명과 완료/미완료 또는 반복 완료 횟수/최대 횟수를 표시한다. 완료 항목은 조작 가능한 체크박스 대신 읽기 전용 상태 표시로 표현한다.
- `남은 숙제만` 필터는 표시만 바꾼다. 필터로 모두 숨겨졌을 때는 `남은 숙제가 없어요`, 카탈로그가 비었을 때는 `등록된 항목이 없어요`로 구분한다. 합계는 필터에 따라 바뀌지 않는다.
- 같은 창의 별도 `클래스 · 생텀 저장값` 아코디언에서 활성 클래스명과 저장된 레벨을 표시한다. 현재 선택한 캐릭터만 조회하고 캐릭터 전환은 기존 선택 UI를 사용한다. 항목이 없거나 저장되지 않은 레벨은 `미등록`으로 표시하며 임의 Lv.1을 채우지 않는다.
- 클래스 레벨과 게임 HUD의 캐릭터 레벨은 다른 값이다. 자동 읽기·현재 클래스 자동 식별·숙련/마스터·SSP 경험치 게이지는 구현하지 않는다.
- 긴 닉네임/항목명은 줄바꿈하고 창 높이는 화면 작업 영역 이내로 제한해 내부 스크롤한다. 기존 6대 테마와 투명도를 적용한다. 모듈이 닫혀도 추가 DB 조회를 생성하지 않는다.

## 데이터 흐름과 수정 경계

1. 기존 `/api/iris/kronos` GET의 세션 및 본인 소유 검증을 그대로 유지한다. 선택 캐릭터의 기존 `levels`와 활성 `nexus_classes`의 ID·이름을 추가로 조회한다. 클래스 목록은 현재 캐릭터 화면의 활성 필터·ID 정렬 기준을 재사용한다. 스키마와 권한은 바꾸지 않는다.
2. `lib/irisKronos.ts`에서 기존 체크 해석을 재사용해 `summary`와 같은 원본으로 일일/주간/어비스/레이드 상세를 만든다. 상세는 범주별 `{id,name,completed,total}` 배열이며 일반 항목 total=1, 반복 항목 total=기존 허용 횟수다. 내부 원본 체크 JSON이나 메모는 반환하지 않는다. 같은 ID가 다른 범주에 있어도 허용하되 범주 안 중복은 거부한다.
3. 클래스는 `{id,name,level}` 배열로 정규화한다. level은 저장값이 안전한 정수 1~1000이면 전달하고 미등록/비정상 값은 null로 표현한다. 범위는 전송 안전 상한일 뿐 게임 최고 레벨을 뜻하지 않는다. 카탈로그에 없는 JSON 키는 전달하지 않는다.
4. 응답은 기존 accountId/characterId/observedAt/summary와 추가 `details:{schemaVersion:1,tasks,classes}`다. 각 범주 최대 200항목, 클래스 최대 100개, 이름 최대 120 Unicode 문자, ID 최대 100문자, 반복 total 최대 1000을 적용한다. 초과·중복·비정상 카탈로그는 조용히 자르지 않고 조회 실패로 처리한다.
5. `lib/irisRelay.ts`는 기존 15초 직렬 갱신 안에서 같은 선택의 요약과 상세를 함께 전달한다. 위젯마다 별도 폴링하거나 모든 캐릭터 정보를 한꺼번에 가져오지 않는다. 기존 loopback summary 경로에 버전 있는 상세를 추가한다.
6. `iris/connection-state.mjs`, `connection-http.mjs`는 상세 스키마와 합계 일치를 검증하고 요약·상세를 원자적으로 적용한다. 기존 HTTP 본문 65,536바이트 상한을 유지하며 중계는 JSON의 UTF-8 크기를 전송 전에 검사한다. 항목별 상한 이내여도 합산 본문 상한을 넘으면 연결 실패를 명확히 안내하고 일부 항목만 전송하지 않는다. 기존 역할별 권한·Origin·토큰 만료·generation/selectionVersion 검사를 보존한다.
7. 구형 상세 없는 응답은 기존 요약만 허용하고 새 위젯에는 `상세 정보 연결 대기`를 표시한다. 신형 상세가 잘못됐으면 그 전달 전체를 거부하며 이전 상세를 정상으로 남기지 않는다.
8. native 표시 파서는 `iris/overlay-support.cs`에서 정규화하며 새 위젯은 별도 C# 파일로 분리한다. `iris/overlay.ps1`은 위젯 생성·복구·테마와 공유 연결 갱신을 배선한다. 원본 토큰/개인 값 로그나 새 디스크 저장을 만들지 않는다.

## 오류·기간·전환

- 기존 연결의 선택 변경/해제/로그아웃/소유권 상실/60초 freshness 만료에 요약과 상세를 함께 비운다. 늦은 이전 캐릭터 응답은 버린다. 아코디언 열림·필터 상태는 창이 살아 있는 동안만 유지한다.
- 타임스탬프 없는 구형 반복 체크의 기간 문제(BETA-065)를 임의 초기화하거나 수를 깎지 않는다. 기존 해석에서 모호한 경우 상세도 조회 실패를 표시한다.
- 저장 클래스 값은 최신 게임 수치라고 보장하지 않는다. observedAt은 생텀 조회 시각이지 클래스 수정 시각이 아니다. 클래스 카탈로그만 실패하면 계약상 전체 상세 갱신 실패로 다뤄 불완전한 화면을 정상으로 표시하지 않는다.
- DB 호출 수는 매 선택 갱신당 캐릭터 1회와 세 카탈로그 병렬 조회다. per-item/per-class/per-widget N+1 조회를 추가하지 않는다. 캐시·Realtime·DB 저장은 이번 범위에서 제외한다.

## 검증과 인계

- 합성 회귀를 먼저 실패시켜 항목 상태/반복 횟수·합계 일치·빈 목록·미등록 레벨·레거시 체크 해석을 검증한다.
- API 테스트: 미로그인·타인 캐릭터 거부, 대표 캐릭터 호환, 활성 카탈로그 필터, 불필요한 데이터 미노출, DB 오류와 상한 거부.
- 중계/HTTP/상태 테스트: 상세 누락 호환, 비정상·중복·초과·합계 불일치 거부, 선택 변경/늦은 응답/만료 비우기, Window fetch/timer receiver 회귀 유지.
- Windows 합성 테스트: 독립 창 생성/닫기·복구, 아코디언·필터 빈 상태, 클래스 미등록, 전환 시 잔존 정보 없음, 기존 테마·투명도·단축키 회귀. 실제 게임 조작이나 로그인 입력을 자동화하지 않는다.
- 구현 후 전체 Node 테스트, 타입 검사, Windows 컴파일/테스트 및 diff 검사. 실제 화면에서 한설이 숙제 항목과 클래스 저장값을 웹 `/character`와 대조하고 닫기/복구·스크롤을 확인한다. 자동 테스트 통과와 실제 UI 확인은 따로 보고한다.

## 자기 검토

독립 위젯/기존 인증 중계 유지, 읽기와 쓰기 구분, 캐릭터 레벨과 클래스 레벨 구분, 개인정보 최소화, 부분 갱신과 오래된 값 방어를 확인했다. 원본문구·개인 수치는 fixture나 문서에 저장하지 않는다. 항목별 제한과 합산 본문 제한을 함께 적용하며 넘치는 데이터를 부분 성공으로 표시하지 않는다. 새 게임 자동화·체크 저장·장기 기기 인증·배포는 별도 설계 범위다. 제품 코드는 아직 수정하지 않았다.
