# ERGON native 수량 재확인 계약 — 짧은 설계

상태: 기존 2026-10-21 결과 확인 설계의4.3/6절을 잇는 연결 설계. 이번 타임의15% 중단은 사용자 요청으로 해제됐다. N04 시험·보고와 개인 변경은 보존한다. 이번 문서는 설계이며 제품 구현 완료를 뜻하지 않는다.

## 목적·범위

0개, 예상보다 많은 산출, 기존 확인량의 정정을 기존 native 진행 저장 경계에서 안전하게 확인한다. React 결과 입력 화면·Q13 초안 UI·자동 생산은 만들지 않는다. 실제 게임/사용자 원장/DB/배포/공개 잠금/commit/push 제한은 유지한다.

## 접근 방식

권장: 이미 있는 비동기 Windows 확인 기능을 재사용한다. 브라우저가 보낸 confirmed=true나 완료 수량을 승인 증거로 받는 방식은 위조 가능하므로 제외한다. 별도 웹 확인 화면·영속 승인 토큰 저장소는3차 UI 범위를 키우고 이중 권위를 만들 수 있어 이번에는 추가하지 않는다.

## 연결 계약

1. 입력을 동결하고 정확한 소유 범위·goalId/requestId·operationId·quantity·revision·정정 대상/사유와 실제 native terminal 근거를 대조한다. 기존 사용자 확인량과 예상 산출을 별개로 표시한다.
2. 0개·초과 산출·정정에만 신뢰된 native 재확인을 요구한다. 정정은 이전 값·새 값·사유를 보여준다. 확인 취소·창 파괴·예외·잘못된 값은 저장하지 않는다. 일반 범위 최초 양수 확인의 기존 동작은 보존한다.
3. 승인 대기에는 actor mutation/Busy 및 기존 실행 lease 보호를 유지하되 공통 writer/Store 파일 잠금은 풀어 둔다. 기존 비동기 owner 파괴 처리를 재사용한다.
4. 확인 후 writer를 다시 취득하고 계정·캐릭터·epoch·문맥·요청·수량·revision·정정 최신 이벤트·native 원장을 다시 대조한다. 하나라도 달라지면 그 승인으로 저장하지 않는다. 확인 유효시간도 제한한다.
5. 승인 정보는 native 내부에서만 생성해 이번 요청/값/revision에 묶는다. 브라우저가 승인 객체를 만들거나 수정할 수 없다. 기존 Store의 의미별 Commit·CAS·operationId 멱등성·정정 이력을 재사용하며 저장 ACK 전에 성공으로 표시하지 않는다.
6. 같은 operationId/의미의 ACK 유실 재전달은 이미 저장된 결과를 대조하여 중복 반영 없이 최신 view로 응답한다. 다른 값·정정 대상의 operationId 재사용은 거절한다. 진행 이력·unknown을 승인으로 덮거나 성공 처리하지 않는다.

## 검증·제품 영향

관련 native 합성 시험부터0/초과/3→2정정, 취소/창 파괴, 승인 중 소유·revision 변경, unknown, 중복/늦은 ACK, 저장 실패를 검증한다. 기존 N04·저장34·A22·B-1 20·H22·R5 회귀를 유지하고 최종 전체 회귀를 수행한다. 실제 창/게임은 실행하지 않는다.

주요 영향은 desktop-life-progress-connection.cs의 native 승인 연결, desktop-webview.cs의 작은 native 확인 대화상자 연결과 관련 시험이다. 필요한 내부 승인 계약은 별도 작은 native 파일로 분리할 수 있으나 저장 형식/원장/공개 allowlist를 확대하지 않는다. ErgonAvailable=false, executionConnected=false를 유지한다.
