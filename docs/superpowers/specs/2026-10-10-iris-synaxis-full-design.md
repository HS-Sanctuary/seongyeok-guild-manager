# IRIS 시낙시스 공용 화면 이식 설계

작성: 영겁 / 2026-10-10 KST. 한설이 목록·가입·매칭·길드버스 운영까지 이식을 요청하고, 제안 범위를 승인하며 설계 정리 후 같은 세션에서 바로 구현하도록 위임했다. 별도 문서 승인 대기는 생략하되 변경 근거와 검증을 남긴다.

## 목적과 완료 기준

게임 옆 IRIS에서 생텀 시낙시스를 이용한다. 현재 게임 캐릭터가 아닌 본인 계정의 다른 캐릭터도 참가할 수 있다. 일반 길드원은 일반 파티와 예정/운행 중 길드버스를 보고 가입한다. 기존 운영진만 버스를 만들고, 해당 버스 담당 운행자만 기존 컨트롤러를 이용한다. 크로노스 완료 상태와 실제 회차 완료는 서로 다른 값으로 유지한다.

## 선택한 구조

생텀 PartyPage의 화면 구성을 공용 SynaxisSurface로 추출한다. 공용 PartyCreateForm, PartyCard, GuildBusCard, 가입·콘텐츠·달력·버스 생성/수정 모달과 usePartyManager 및 기존 서버 권한/편성 엔진을 사용한다. IRIS 전용 공급자는 검증된 DesktopAccount, 활성 탭, 잠금과 쓰기 상태를 제공한다. 웹 호출은 기존 기본 동작을 유지한다.

전체 웹페이지 iframe은 네이티브 보안과 폭/헤더 문제 때문에 사용하지 않는다. 별도 IRIS 매칭 엔진은 권한·편성 규칙의 중복을 만들기 때문에 사용하지 않는다. 기존 생성 전용 DesktopSynaxis 초안과 테스트는 보존하되 실제 desktop 진입은 새 공용 화면으로 연결한다.

## 화면과 조작

- 첫 화면은 목록이며 일반 파티/길드버스 두 탭으로 나눈다. 기존 일정 정렬, 검색, 콘텐츠·날짜 필터를 재사용한다.
- 스마트 매칭 리모컨은 접었다 열 수 있다. 길드버스 생성은 운영진에게만 표시된다. 생성·가입·편성·회차·설정·인계·해산은 기존 명시적인 버튼/확인 흐름을 따른다.
- 본인 캐릭터 전체를 선택 후보로 사용하고 레이드·어비스 완료 상태를 기존 CharacterCompletionStatus로 보여준다. 다른 계정 캐릭터는 가입 선택에 넣지 않는다.
- 콘텐츠 선택은 등록된 유효 난이도만 사용한다. 새 선택에서 어비스는 매우 어려움이 있으면 기본값으로, 레이드는 등록된 난이도 중 최고를 기본값으로 한다. 기존 파티의 난이도나 사용자가 선택한 값은 새로고침 때문에 바꾸지 않는다.
- 기존 ScheduleModal 달력을 사용한다. 버스 수정의 기존 신청 시간 보존·다른 참가자 보존·재편성 동작을 유지한다.
- IRIS 폭에 맞는 단일 열 카드와 줄바꿈/전체 닉네임, 줄어든 버튼 수평 폭, 제한 높이의 스크롤 모달을 사용한다. 배경 클릭·Escape·초점 유지·배경 조작 차단을 점검한다. 테마 변수와 rem 글자 크기를 사용한다.

## 계정·조회·쓰기 경계

- IRIS는 기억된 nexus_user나 게임 닉네임으로 계정을 추정하지 않는다. 로그인에서 받은 DesktopAccount를 공급하고 계정 ID 변경 시 화면 상태를 격리한다. IRIS 초안 키는 계정별이다.
- 로그인한 IRIS 계정의 Realtime 채널 하나로 파티 변경을 받는다. 활성 목록은 이벤트를 묶어 다시 읽고, 숨겨진 탭은 읽기 없이 새 일반 파티/길드버스의 빨간 점만 보관한다. 탭을 열면 최신 목록을 읽으며 해당 탭 표시를 확인 처리한다. 계정 해제/언마운트 때 채널을 정리하고 늦은 결과를 버린다. 별도 반복 조회를 추가하지 않고 카탈로그의 기존 캐시를 재사용한다. 이는 구현 중 한설이 추가 요청한 자동 새로고침·레드닷 범위다.
- 저장 요청은 기존 서버 경로로 보낸다. IRIS 요청은 expectedAccountId를 포함하고 서버 쿠키 계정과 일치해야 한다. 본인 소유권·운영진/운행자 판정과 권한을 서버에서 다시 확인하는 기존 방식을 유지한다.
- 요청 중 중복 제출과 계정/종료 전환을 막는다. 요청 전 결과 불명 표시를 계정별로 보관하며 네트워크 실패나 불명확한 서버 오류면 자동 재전송하지 않는다. 최신 목록 확인 후 명시적으로 해제해야 다시 요청할 수 있다. 기존 생성 결과 불명 기록도 무시하지 않는다.
- 기존 다중 행 작업의 비트랜잭션 제한을 이번에 SQL 없이 해결됐다고 주장하지 않는다. 실패 시 최신 목록을 확인하도록 안내한다.

## 변경과 비범위

변경 후보: components/party/SynaxisSurface.tsx 및 공급자, app/party/page.tsx, hooks/usePartyManager.ts/usePartyCatalog.ts, components/iris/DesktopSynaxisSurface.tsx와 CSS, desktop/page.tsx, 공용 mutation/버스 action/완료 요청의 계정 연결, 관련 회귀 테스트와 인계 문서.

운영 DB/Realtime publication/RLS/권한 변경, 운영 파티 시험 생성/삭제, 게임 입력/조작, 네이티브 탐색 정책 완화, 새 라이브러리 설치, 버전 상승·push·배포·공지 게시는 범위 밖이다. 기존 dirty IRIS/native 및 개인 파일 삭제는 그대로 보존한다.

## 검증

먼저 실제 함수/컴포넌트로 실패하는 테스트를 작성한다. 계정별 초안과 결과 불명, 다른 계정/숨김/잠금/중복 요청, 늦은 조회, 난이도 선택, 본인 가입·운행자 제한을 검증한다. 실제 React와 합성 IO로 목록·리모컨·달력·가입·버스 컨트롤러 및 초점을 확인한다. 320/390/768/1280px 및 PC 18/20/22px에서 넘침을 확인한다. 관련 테스트와 전체 Node, 독립 TypeScript, 분리 Production 빌드를 묶음 완료 시 실행한다. 실게임·운영 쓰기 확인과 합성 검증을 구분해서 보고한다.
