# IRIS 생활 작업 — 안전 경계 보관용 설계안

상태: 2026-10-11 검토안. 참조 ID: A01–A10. 사용자 게임 조작·자동화 승인 아님. 읽기 계약과 정책 확인 후 행동별 별도 계획·승인을 받는다.

## 도입 순서

1. A01 시설 하나의 수령: 명시 버튼·영향 확인·단일 실행·후속 조회부터 검증.
2. A02/A03 같은 품목 재등록/한정 반복: 재료·날개·시설 빈 칸 계약과 외부 작업 충돌 방어 후 검토.
3. A04/A05 채집/낚시/제작: 목표량·최대 횟수·무게·도구·산출 검증 후 검토.
4. A06/A10 제한된 생활 큐와 실행 원장, A07 선행 체인은 위 단일 행동이 안정화된 다음이다.

## 필수 실행 계약

- 행동은 공식 지원 명령을 개별 allowlist한다. 임의 명령/인자 입력·숨은 자동 클릭·정책 팝업 우회는 없다.
- A08 전투/대화/던전/연주 등 사전 상태를 조회한다. 감지할 수 없는 상태와 지원 범위를 보여주고 안전 여부가 모르면 실행하지 않는다.
- A09 대상·이동 영향·날개/재료/시간 상한·정지 범위를 확인창에 요약한다. 실패/응답 불명은 재실행하지 않고 조회 또는 사용자 확인으로 넘어간다.
- 초기 상태기계는 `검토→사용자 확인→사전 점검→실행 중→후속 조회→완료/실패/결과 불명`이다. 실행 중 또 제출할 수 없다. 결과 불명 상태는 자동 재시도와 다음 의존 작업을 차단한다.
- 중지 요청과 실제 중지는 다르다. 실행 종료 확인 전 성공으로 표시하지 않는다. 일반 stop 명령이 다른 앱/수동 작업을 멈출 수 있으면 자동 사용하지 않는다.
- 계정/캐릭터 전환·게임 종료·앱 재시작/업데이트 이후 작업을 자동 재개하지 않는다. 공식 1시간 재확인·사용자 승인 경계를 우회하지 않는다.

## 큐와 기록

생활 실행 큐는 SANCTUM 숙제 저장/보호 대기함과 완전히 다른 자료형·수명주기를 가진다. 실행 소유권을 한 번에 하나로 제한하되, 앱 내부 잠금이 타 앱 실행까지 막는다고 주장하지 않는다. 큐 편집과 실행은 별개다. 예상 소모 합계를 보여주고 승인된 범위 밖 재료/횟수를 늘리지 않는다.

A10 원장은 IRIS가 요청한 동작·관측 결과·예상 소모를 구분한다. 타 앱/수동 소비와 계정 총 소비는 포함하지 않는다. 보존 기간/개인정보/내보내기는 착수 설계에서 결정하며 운영 DB 자동 이력은 없다.

## 검증과 복구

모든 행동은 합성 응답으로 이중 제출·늦은 응답·타임아웃·부족 재료·상태 전환·중지 실패·후속 조회 불일치를 먼저 검증한다. 실제 게임 시험은 한설이 승인한 대상/소모 상한/복구 절차로만 수행한다. 수령/소모를 되돌릴 수 있다고 약속하지 않는다. 오류 때 행동 모듈을 비활성화하고 읽기 기능은 유지한다.

새 bridge 행동/설정/큐 설계는 공개된 고정 명령별 계약을 확인한 뒤 명시한다. 이 문서만으로 native 행동 경로를 만들거나 동작을 실행하지 않는다.
