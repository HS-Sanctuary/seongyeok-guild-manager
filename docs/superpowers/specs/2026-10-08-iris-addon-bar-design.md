# IRIS 애드온 바 · 창 연동 · 재화 강조 설계

상태: 2026-10-08 한설의 대화상 구성 승인(“진행해줘”)을 반영한 설계 검토본. 제품 구현 전 작성한 문서이며, 이 문서의 확인 뒤 구현 계획을 작성한다. 현재 미커밋 작업을 보존한다. push·배포·버전 상승·운영 DB 변경은 승인 범위에 포함하지 않는다.

## 1. 목적과 범위

게임 옆에서 캐릭터 정보와 숙제를 확인하는 작고 읽기 쉬운 **애드온 바**를 우선 완성한다. 오버레이는 향후 별도 표시 방식으로 발전시키되 기존 조회·캐릭터 추천·보호 보관·저장 모듈을 공유한다.

이번 범위는 통합 제목 줄, 테마 복원, 설정 정리, 게임 창 위치·높이·표시 상태 연동, 게임 종료 후 안전한 IRIS 종료, 재화 항목별 표시 강조다. 기존 숙제·클래스·스탯 저장과 캐릭터 추천 동작을 유지한다. 시낙시스 조회 구현, 재화 DB 저장/캐릭터별 재화 이력, 램 정리, 게임 조작, 공개 공지는 포함하지 않는다.

## 2. 기존 구조와 선택한 접근

- 네이티브 호스트는 `iris/desktop-webview.cs`의 WinForms/WebView2다. 현재 별도 회색 이동 손잡이·하단 크기 손잡이·내용 높이 자동 조절·전역 TopMost를 사용한다. 게임 창 추적 모듈은 없다.
- `DesktopCenter`의 제목 줄과 별도 이동 손잡이가 공간을 중복 사용한다. 현재 최소화처럼 보이는 버튼은 실제로 본문 접기다.
- 테마 버튼은 DOM의 `data-theme`만 바꾼다. 재실행 시 `app/layout.tsx`의 계정 테마/기본값 적용과 충돌한다.
- 재화는 `DesktopCurrencies`에서 탭 활성화 시 기존 직렬 CLI 조회를 사용한다. 이름/수치를 표시할 뿐 생텀에 저장하지 않는다.
- 종료는 기존 `DesktopCloseDialog` → controller의 shutdown → 보호 저장/네이티브 종료 흐름이 이미 있다. 새 창 연동에서도 이 흐름을 재사용한다.

접근 비교:

1. 게임 창의 자식/소유 창으로 IRIS를 연결하면 일부 표시 연동은 단순하지만, 게임 창 파괴 시 IRIS도 먼저 파괴될 수 있어 저장 확인에 부적합하다.
2. 항상 위에 표시만 유지하면 다른 앱 위에도 IRIS가 남아 “게임과 같은 층” 요구를 충족하지 못한다.
3. **독립 창을 유지하면서 Windows 창 상태를 읽고 IRIS만 제어한다.** 이 접근을 선택한다. 위치·표시 제어와 기존 데이터 저장 수명주기를 분리한다.

## 3. 통합 제목 줄과 설정 화면

- 제목 줄을 `IRIS for SANCTUM | 설정(톱니바퀴) | 최소화 | 닫기` 한 줄로 통합한다. 기존 회색 `:: 창 이동` 줄과 중복 제목을 제거한다.
- 제목/빈 영역에서 왼쪽 마우스로 실제 창을 이동한다. 설정·최소화·닫기 버튼은 이동 영역에서 제외한다. 제목의 단순 클릭으로 창 붙이기를 해제하지 않는다. 실제 드래그 이동 시에는 독립 창으로 전환해 다시 붙으려는 움직임을 막는다.
- 최소화는 실제 네이티브 최소화로 연결하며 기존 트레이 복구를 유지한다. 닫기는 기존 저장 확인을 거친다. 창을 조작하는 명령은 허용된 고정 명령만 브리지에 추가한다.
- 설정 진입은 제목 줄의 톱니바퀴로 옮긴다. 상위 메뉴는 크로노스/시낙시스 두 개를 유지하며, 설정을 닫으면 이전 내용 탭으로 돌아간다. 크로노스의 기존/예정 하위 버튼은 보존한다.
- 선택 캐릭터 피드백은 제목 아래에 유지하고 스크롤 중에도 읽을 수 있게 한다. 최대 12자 닉네임을 숨기거나 생략하지 않는다.
- 애드온 설정에는 계정, 창 붙이기, 테마, 사용 안내를 명확한 짧은 그룹으로 표시한다. 클릭 통과·불투명도·오버레이 단축키 안내는 제거한다. 애드온 모드에서 클릭 통과 단축키로 다시 입력 불가 상태가 되지 않도록 해당 기능도 비활성화한다. 트레이 입력 복구는 유지한다.
- 테마 표기는 Lumen, Elysium, Aureum, Nemeton, Vesper, Rosarium으로 바꾼다. 사용 안내는 조회 전용/직접 저장 항목/자동저장/초기화 기준을 짧게 나눈다. 새 항상 위 옵션은 이번 범위에 넣지 않는다.
- 전체 배경·테두리·텍스트·아이콘은 전역 테마 변수를 따른다. 남는 네이티브 테두리/크기 손잡이도 테마와 조화시키거나 제거해 회색 고정 띠가 남지 않게 한다. 글자는 기존 rem 체계와 최소 가독성 기준을 따른다.

## 4. 창 붙이기와 같은 층 표시

설정은 `창 붙이기: 오른쪽 / 왼쪽 / 끔`과 `게임과 같은 층으로 유지` 체크박스로 구성한다. 첫 실행 기본값은 오른쪽과 체크 켜짐이다. 각 설정은 이 PC의 해당 실행 환경에 저장한다.

- 붙이기는 게임 창 바깥쪽 옆에 IRIS를 배치하고 게임 창의 실제 표시 높이에 맞춘다. 게임 창은 이동/크기 변경하지 않는다. 붙어 있는 동안 내용 기반 자동 높이 조절을 멈추고 IRIS 본문만 세로 스크롤한다.
- 작업 표시줄·모니터 작업 영역·DPI를 고려한다. 선택한 쪽에 최소 폭이 없으면 반대쪽을 시도하고 실제 붙은 쪽을 표시한다. 양쪽 모두 공간이 없으면 붙이기를 일시 중단하고 화면 안의 독립 창으로 유지한다. 게임 위를 임의로 덮거나 게임을 축소하지 않는다.
- `끔`은 위치/높이 추적만 중단한다. 체크박스는 표시 순서만 제어한다. 최소화/복원 및 종료 확인 연동은 추적 중인 게임 세션에서 별도로 유지한다.
- 같은 층은 엄밀히 같은 Z-order 번호가 아니라 **게임과 가까운 표시 순서로 함께 보이고 다른 앱 위에 IRIS만 영구히 남지 않는 동작**이다. 전역 TopMost는 사용하지 않는다. 게임의 앞/뒤 이동에 맞춰 IRIS의 순서를 갱신하되 포커스를 빼앗지 않는다. IRIS를 직접 활성화해 조작하는 동안은 정상적인 창 활성화 동작을 허용한다.
- 체크 해제 시 IRIS는 일반 독립 창의 표시 순서를 따른다. 다른 앱보다 항상 위로 바뀌지 않는다.
- 창 모드가 우선 지원 대상이다. 독점 전체화면, 관리자 권한 차이, 창 후보가 여러 개인 경우에는 연동 실패를 표시하고 독립 창/트레이 복구를 유지한다. “항상 같은 층”을 모든 OS 표시 모드에서 보장한다고 안내하지 않는다.

## 5. 게임 창 수명주기와 안전한 종료

네이티브 추적기는 게임 창 후보의 프로세스 실행 파일·창 정보로 대상을 제한한다. 닉네임이나 게임 메모리를 읽지 않는다. 여러 후보가 모호하면 임의 창에 붙지 않는다. 실제 프로세스 이름과 메인 창 판별 조건은 읽기 전용 관찰로 확인하고 테스트에 남긴다.

| 상태/사건 | IRIS 동작 |
| --- | --- |
| 아직 게임을 찾지 못함 | 독립 창 유지. 게임 종료로 오판하거나 종료 확인을 띄우지 않음 |
| 게임 창 이동/크기 변경 | 붙이기 켜짐일 때 IRIS 위치/높이만 갱신 |
| 게임 최소화 | IRIS도 최소화. 그 원인이 게임 연동임을 기록 |
| 게임 복원 | 게임 때문에 최소화됐던 IRIS만 함께 복원. 직접 최소화한 IRIS를 임의로 다시 열지 않음 |
| 창 핸들 교체/일시 소실, 프로세스 생존 | 대상 재탐색. 캐릭터 선택/로딩을 게임 종료로 처리하지 않음 |
| 추적하던 게임 프로세스의 실제 종료 확인 | IRIS를 조작 가능한 상태로 보여주고 게임 종료용 저장 확인을 한 번 띄움 |
| 종료 확인 취소 | IRIS를 독립 창으로 유지. 같은 종료 사건으로 확인창을 반복하지 않음 |

- 종료 확인은 `게임이 종료됐어요. IRIS도 종료할까요?`와 **저장하고 종료 / 보관하고 종료 / 취소**를 제공한다. 이 게임 종료용 화면에는 버리기를 넣지 않는다. 기존 수동 종료의 버리기/복구 종료 정책은 바꾸지 않는다.
- 저장하고 종료는 기존 controller를 통해 해당 계정의 보관된 변경을 저장하고, 성공이 확인된 경우에만 종료한다. 충돌·유효하지 않은 입력·인증 만료·불명 결과·통신/보관 실패 시 IRIS를 유지하고 기존 해결 안내를 보여준다.
- 보관하고 종료도 보호 저장 성공을 확인해야 한다. 실패하면 종료하지 않으며 원본 보호 대기함을 덮어쓰지 않는다. 취소는 편집 화면으로 돌아간다.
- 확인창/저장 중에는 창 추적이 다시 최소화하거나 포커스를 옮기지 않는다. 새 게임 실행이 감지돼도 이미 진행 중인 저장/종료 선택을 중복 실행하지 않는다.
- UI 연결이 없으면 기존 네이티브 복구 확인을 활용하고 미보관 편집의 손실 가능성을 명시한다. 사용자 선택 없이 강제로 IRIS를 종료하지 않는다.
- 게임 종료를 사후 감지하는 기능이다. 게임 자체의 종료를 막거나 게임 종료 직전에 게임 안에서 질문을 띄우는 기능은 아니다. OS 강제 종료/전원 손실에서 저장 성공을 보장하지 않는다.

## 6. 재화 탭 배치와 항목별 강조

- 첫 행은 `인게임 재화 | 조회 HH:mm:ss | 설정(톱니바퀴)`다. 제목은 테마의 강조색, 조회 시각은 더 작은 보조 글자로 제목 오른쪽에 정렬한다. 한국 시간 24시간제를 사용하고 좁은 폭에서는 시각/버튼이 잘리지 않게 재배치한다.
- 안내 문구 `조회만 해요. 생텀 DB에는 저장하지 않아요.`는 목록 맨 아래로 옮긴다. 보조 크기를 사용해 통상 한 줄로 읽히게 하되 최소 글자 크기를 깨거나 화면 밖으로 잘라내지 않는다.
- 톱니바퀴는 재화 강조 설정창을 연다. 항목 선택 → 색상/굵게/기울임 → 미리보기와 적용으로 구성한다. 하나의 항목 설정은 항목명과 숫자에 함께 적용한다. 항목별 기본값 복원과 전체 기본값 복원을 제공하며, 전체 복원은 한 번 확인한다.
- 기본 색상은 테마를 따른다. 선택 색상은 검증된 색상 값만 허용하며 일반 CSS 문자열을 저장/삽입하지 않는다. 명암 대비가 낮은 선택은 안내한다. 굵기/기울임은 불리언으로 저장한다. 설정으로 재화 정렬/숨김/수량은 변경하지 않는다.
- 현재 계정의 이 PC·실행 환경에 강조 설정만 저장한다. 같은 계정의 캐릭터에는 같은 설정을 적용하며 다른 계정의 설정을 섞지 않는다. 재화 값/조회 시각/게임 상태는 영속 저장하지 않는다.
- 설정창은 테마를 따르고 높이를 제한해 내부만 스크롤한다. 바깥 클릭/닫기/Escape로 닫으며 초점 가두기와 호출 버튼으로 복귀를 제공한다. 설정 편집은 게임 재조회나 생텀 저장을 발생시키지 않는다.

## 7. 모듈·저장·보안 경계

- 새 네이티브 창 연동 모듈은 대상 탐색/표시·위치 상태와 설정만 담당한다. 실제 Windows API 호출을 감싼 어댑터와 순수 상태/배치 결정 로직을 분리해 합성 테스트한다. UI 스레드를 막지 않고 한 개의 제한된 감시 루프를 사용한다. 감시는 CLI/DB/네트워크를 호출하지 않는다.
- `desktop-webview.cs`와 실행기는 새 모듈의 수명을 소유한다. 원본 허용 목록·epoch·단일 실행·전용 WebView 프로필·현재 보호 대기함 schema2를 유지한다. 게임 창을 IRIS의 부모/owner로 연결하지 않는다.
- 네이티브 창 설정은 보호 대기함과 **별도**인 작은 환경별 설정 파일에 엄격한 타입/크기 제한과 원자 쓰기로 보관한다. 손상/쓰기 실패는 설정 오류와 기본값/현재 실행 값으로 처리하며 인증·큐를 수정하지 않는다.
- 테마와 재화 강조는 전용 WebView의 명시적인 환경/계정 범위 표시 설정으로 관리한다. 테마는 실행 환경별 공통 설정, 재화 강조는 계정별 설정이다. 서버 계정 테마나 Supabase에는 쓰지 않는다. IRIS 경로에서 전역 레이아웃의 테마 초기화와 경쟁하지 않도록 하나의 복원 경로를 사용한다. 웹 SANCTUM의 테마 동작은 보존한다.
- 저장소 접근 실패 시 화면 변경은 현재 실행에서만 허용하고 “재실행 시 유지되지 않음”을 안내한다. 잘못된 표시 설정을 인증/숙제/클래스 데이터의 손상으로 확대하지 않는다.
- 브리지에는 드래그/최소화/창 설정 조회·변경/게임 종료 확인 사건에 필요한 고정 계약만 추가한다. 임의 HWND·프로세스·파일 경로·명령을 웹에서 받지 않는다. 모든 응답/사건은 출처·현재 문서 epoch를 검증한다. UI 준비 전 게임 종료 사건은 한 번 보류해 전달하거나 네이티브 복구 확인으로 처리한다.
- 주요 변경 대상: `DesktopCenter`, `DesktopCurrencies`, 새 표시 설정/재화 편집 컴포넌트, desktop page/CSS, `app/layout.tsx`의 IRIS 한정 테마 경계, `irisDesktopStore`, native bridge/WebView/overlay/launcher 및 새 창 추적·설정 모듈. 보호 queue/controller의 저장 알고리즘과 서버 API는 이번 이유로 재작성하지 않는다.

## 8. 검증과 사용자 확인

위험도에 맞춰 변경 경계 테스트를 먼저 작성하고 실패를 확인한 뒤 구현한다. 관련 테스트·타입 검사와 한 번의 분리 빌드/묶음 브라우저 확인을 사용한다. 무관한 전체 화면/운영 DB 검증을 반복하지 않는다.

- 순수/네이티브: 창 후보 제한, 좌/우/공간 없음, 여러 모니터/DPI, 최소화 원인 구분, 복원, 핸들 교체와 프로세스 종료 구분, 중복 사건 방지, 감시 해제/Dispose, 원본·epoch 거절, 설정 손상/쓰기 실패.
- UI: 한 줄 제목/실제 최소화/설정 진입/드래그 버튼 제외, 테마 재실행 복원 및 일반 웹 영향 없음, 재화 항목별 강조·미리보기·복원·계정 격리, 설정 편집 중 추가 조회/저장 없음, 긴 재화명/큰 수치/미확인/빈 목록/오류, 모달 Escape/바깥 클릭/포커스.
- 종료: 저장 성공 후만 종료, 저장 실패/unknown/충돌/인증 만료/잘못된 입력 시 유지, 보관 실패 시 유지, 취소 후 반복 확인 없음, 게임 재실행과 종료 확인 경쟁. 실제 보호 파일/비밀값을 추출하지 않고 기존 합성 저장 자료를 사용한다.
- 눈으로 확인: 320/390px 폭과 밝은/어두운 테마의 상단·재화·설정, 본문 스크롤 중 선택 캐릭터 확인. 실제 게임 이동/최소화/복원/종료는 한설의 정상 종료와 재실행으로 확인한다. 실제 DB 쓰기는 자동으로 수행하지 않는다.
- 완료 판정은 자동 검증과 실제 게임 연동을 구분해 기록한다. 해당 UI 확인 경로는 `http://localhost:3000/iris/desktop`이며 네이티브 동작은 개발용 IRIS 앱에서 확인한다. 구현 확인 전까지 기존 실행 중 앱을 강제 종료/교체하지 않는다.

## 설계 자체 점검

- 창 붙이기, 표시 순서, 게임 수명주기, 데이터 저장을 분리했다.
- “게임 종료 전에 질문”은 게임 제어 없이 가능한 사후 IRIS 확인으로 명확히 했다.
- 원본 보호 대기함/인증/기존 미커밋 작업은 보존하고 표시 설정만 별도 저장한다.
- 새로운 게임 조회/DB 저장/오버레이 작업으로 범위를 확대하지 않았다.
