# IRIS 축소바·알림·캐릭터 관리 설계 후보

상태: 한설이 2026-10-12 묶음/설치글꼴·소리·둥근창 방향과 실행계획 직접진행을 승인했다. 로컬 구현·합성검증·단일교차검토/중요수정·정상재시작까지 진행했다. 운영 push/배포 승인은 아니며 실제게임/모서리/소리 사용자확인은 별도다. 아래는 승인설계 기준, 최신결과/제한은 HANDOFF를 따른다.

## 목적과 실행 순서

게임을 가리지 않는 작은 애드온 바를 만들고, 생텀의 출현 안내와 본인 캐릭터 관리를 같은 앱에서 제공한다. 바탕화면 클릭 버그·로컬 글꼴은 먼저 처리했다. 다음은 **축소바 → 알림 → 캐릭터 관리** 순서로 각각 좁은 시험 후 연결 검증한다. 새 DB/권한/게임 행동/패키지/버전/배포는 이번 범위가 아니다.

설치 글꼴 자동 목록을 앞에 추가하고, 네이티브 재시작은 글꼴/축소/소리 변경을 묶어 최소화한다. 실행 방법은 현재 대화에서 순차 직접 작업을 추천하며 추가 에이전트는 기본 사용하지 않는다.

## 0. 설치 글꼴 자동 목록

- Windows 네이티브의 InstalledFontCollection으로 이름 목록만 읽고 실행 중 캐시한다. 글꼴 파일을 업로드/다운로드하거나 DB/Vercel에 보내지 않는다. 이름은 정렬/중복 제거하고 목록 응답은 최대2048개·이름80자·제어문자 없는 문자열로 제한한다.
- 설정에 테마를 따르는 검색 가능한 드롭다운과 목록 새로고침을 제공한다. 처음 필요할 때1회 조회, 새로고침만 캐시를 갱신한다. 외부 WebView/구epoch/브라우저 파일 경로·인수 입력은 거절한다.
- 이전 기본/글꼴 이름/6~22pt 설정을 보존한다. 목록 읽기 실패나 구 native에서도 기존 설정을 지우지 않고 안내/직접 입력을 유지한다. 추가 글꼴 권한이나 설치 작업을 수행하지 않는다.

## 1. 축소바

- 제목의 최소화와 닫기 사이 □는 접기/펼치기. 최소화·종료와 별개의 표시 상태다. 일반 화면은 지금의 상시 버튼형을 유지한다.
- 접힌 화면은 제목·선택 캐릭터와 얇은 기능 버튼 두 줄. 버튼 선택 시 그 기능만 아래로 잠시 펼치며 바깥 클릭/Escape로 닫는다. 시낙시스/계정/설정 진입도 잃지 않는다.
- 게임 최대화 또는 모니터를 채운 전체화면 진입 때 자동으로 접고 화면 모서리에 배치한다. 일반 창 복귀는 기존 폭·도킹을 복원하지만, 사용자가 원래 접어둔 경우는 접힘을 유지한다. 수동 이동은 존중한다. 조회 실패를 전체화면으로 오인하지 않는다.
- 네이티브 높이 동기화와 WebView 표시 상태를 연결해야 한다. 도킹의 기존 게임 높이 강제 지정이 접힌 창을 다시 늘리지 않아야 한다. 추천/알림/편집/종료 확인 패널이 뜨면 읽고 조작할 수 있는 임시 높이를 확보하고 닫으면 복귀한다.
- 본문을 숨길 뿐 캐릭터/계정 범위·입력 초안·저장 큐를 해제하지 않는다. 기존 최소화/복원·같은 층·작업표시줄·바탕화면 예외를 보존한다. 게임 창이나 입력 초점은 조작하지 않는다.
- 네이티브 창 모서리도 둥글게 잘라 CSS 바깥의 사각형 배경이 남지 않게 한다. 크기/DPI 변경에 맞춰 갱신하고 모서리 밖은 뒤 창이 보인다. 왼쪽/오른쪽 resize grip은 가운데 부분에서 계속 작동한다. 오래된 Windows도 지원 가능한 window region을 사용하며 게임 창은 수정하지 않는다.

## 2. 크로노스 ‘알림’

- 하위에 알림을 추가, 필드보스/소환의 결계/어비스 구멍/심층 구멍 4개 카드에 기존 SVG와 콘텐츠별 켜기/끄기. 처음에는 모두 켜짐, 변경은 로컬 환경별 저장. 계정 데이터와 게임 상태를 설정에 저장하지 않는다.
- 각 콘텐츠에 소리 ON/OFF도 제공한다. 기본 알림/소리는 켜짐으로 제안한다. 알림 OFF면 소리는 실행하지 않고, 알림 ON·소리 OFF는 화면 안내만 제공한다. 소리 선택은 알림을 다시 켜도 기억한다. 짧은 자체 벨 음색(1초 미만), 외부 음원/다운로드/소리 URL·파일경로/OS 볼륨 변경 없음.
- 같은 경고의 재렌더/중복 이벤트에 다시 울리지 않고 네이티브도 짧은 재생 간격을 제한한다. 게임·다른 창을 강제 활성화하지 않는다. 재생 실패는 화면 알림을 없애거나 제보/캐릭터 저장을 실패시키지 않는다. 합성 시험에서는 실제 소리를 재생하지 않는다.
- 생텀 홈의 현재 기준: 필드보스12/15/18/20/22시, 2분 전 임박·출현 후30분 활성. 결계 매시00분부터2분 전 안내,02분부터04분 전까지 활성. 어비스는 승인된 제보 기준2분 전 임박·출현 후15분 활성. 한국 시간 기준을 명시하고 웹 표시와 어긋나지 않게 공통 계산을 분리/시험한다.
- 심층은 매시00/30분 **제보 초기화**이지 확정 출현이 아니다. 갱신 시각 및 현재 기간의 새 양수 개수 제보를 구분한다. 어비스의36시간15분 기본 주기 계산은 ‘예상’이며 승인 제보 없는 실제 출현 모달로 단정하지 않는다.
- 단계별 경고는 같은 출현/제보에1회. 매초 재팝업, 재로그인/캐릭터 전환 시 과거 경고 재생, 늦은 응답에 의한 중복을 방지한다. 다른 추천·저장·편집 모달과 겹치지 않게 한 번에 하나만 표시한다. native 포커스는 뺏지 않는다. 뒤늦게 복귀한 과거 경고를 줄줄이 보여주지 않는다.
- 로컬 CLI `capabilities`(2026-10-12 실측)에 구멍 출현 시간/위치/개수 조회는 없다. `get_current_environment`는 내 위치/날씨/시간, `get_activity`는 내 진행/상호작용 상태라 출현으로 역산하지 않는다. 따라서 생텀 제보를 이용한다.
- 기존 `deep_holes`/`abyss_reports` 조회·Realtime 권한 범위를 재사용한다. 매초 DB 조회는 하지 않고 초기 조회와 이벤트/사용자 재조회만 연결한다. 구독/응답은 계정 변경·로그아웃 시 정리, 실패는 ‘조회 실패’로 표시한다.
- 기존 `/api/reports` POST 재사용: 심층 사냥터(창백한 산/센마이 평원)와 개수0~3; 어비스 남은 분 제보는 기존 pending 승인 절차. `channel` 필드가 심층 UI에서는 개수라는 기존 의미를 그대로 따른다. 새 스키마/운영 시험 제보를 만들지 않는다.

## 3. 캐릭터 선택·관리

- 사진의 두 열 카드 선택창을 단일 진입점으로 삼고 추천의 ‘다른 캐릭터/직접 선택’도 그 창을 연다. 입력 중이거나 잠긴 모달 뒤에서 다른 선택창을 열지 않는다.
- 실제 등록 캐릭터만 카드로 표시, 빈 슬롯을 채우지 않는다. 마지막에 +캐릭터 추가 카드 하나만 둔다. 기존 조회 허용100개를 근거 없이6개로 제한하지 않는다.
- 카드 오른쪽 작은 연필로 닉네임·주클래스 수정, 대표 캐릭터는 명확한 표시와 설정 제공. 클래스 목록은 기존 활성 카탈로그를 이용한다. 대표는 한 계정에서 하나만 유지한다. 새 캐릭터도 닉네임/주클래스를 입력해 저장한다. 삭제·대량 정렬은 이번 범위가 아니다.
- 생텀 `/api/member-mutations`의 기존 본인 소유 검증/수정·등록 경로와 `characters.is_main`을 참조한다. IRIS는 UUID를 계속 식별 기준으로 쓰고 닉네임을 신원/로그인 변경으로 해석하지 않는다. 계정 닉네임이나 역사적 파티/활동 기록을 임의로 전역 치환하지 않는다.
- 저장 큐와 캐릭터 메타 변경의 진행 작업을 직렬화한다. 미저장/불명확 결과·잘못된 클래스 초안은 먼저 해결 또는 명시적 보관을 안내하며 조용히 폐기하지 않는다. 메타 저장 중 중복 제출/추천 전환을 막고 성공 후 디렉터리·선택 캐릭터·추천 후보를 새로 읽는다. 실패/응답 유실은 무조건 성공이나 자동 재전송으로 처리하지 않는다.
- 서버가 대표 변경/등록을 여러 번 호출하는 기존 경로이므로 부분 실패와 다른 창의 수정을 확인해야 한다. 실제 경로에서 필요한 안전 보완 범위를 구현 전에 좁힌다. DB 마이그레이션이 필요해지면 별도 승인을 받는다.

## 검증과 승인 경계

- 축소: 수동/자동 전환·일반 창 복귀·폭 보존·임시 패널·최소화·같은 층 회귀의 native 합성 시험, 실제게임은 정상 재시작 뒤 한설 확인.
- 알림: KST 자정/출현 전후/제보 승인·기한/중복/구독 끊김/켜기끄기 복원/로그아웃·늦은 응답. 실제 운영 제보를 시험 목적으로 쓰지 않는다.
- 캐릭터: 0/1/6/다수 카드·12자 닉네임·추가/수정/대표·소유권·이름 중복·부분 실패·저장 큐/추천/늦은 응답·단일 선택창. 합성 API로 검증한다.
- 글꼴6~22pt/360~720 폭/밝고 어두운 테마에서 클리핑·조작을 확인. 묶음 끝에 타입/관련 회귀/전체 Node/diff를 확인한다.
- 이 문서 승인 후 구현 계획을 작성하고 현재 대화에서 순차 실행한다. 실제 push/배포·새 버전·DB 구조 변경은 추가 승인 없이는 하지 않는다.
