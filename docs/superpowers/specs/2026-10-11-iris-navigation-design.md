# IRIS 애드온 바 탐색 정리 — 설계 검토안

날짜: 2026-10-11 KST / 작업자: 영겁

상태: 2026-10-11 한설이 기능 선택 설계와 직접 구현 계획을 승인했다. 로컬 구현·합성 검증 완료. 실제 사용자 앱 확인·새 버전·배포는 별도이며 미래 HUD 구현 승인이 아니다.

## 목적과 현재 기준

한설은 기능이 늘어날 때 애드온 바가 복잡해져 무엇을 조작하는지 혼동하지 않도록, 세련된 관리 화면을 먼저 정리하고 HUD 오버레이로 확장하기를 요청했다.

기준 커밋은 `fb607e0`, 제품 버전은 IRIS Beta 0.2.2다. 상점구매·임무게시판·시낙시스, 길드버스 해산/탈퇴 확인창, 앱 업데이트 핫픽스는 완료된 기존 작업이다. 이를 다시 구현하지 않는다. 해당 버전의 검증 범위와 실제 사용자 시험의 한계는 `docs/HANDOFF.md`를 따른다.

이번 설계는 **탐색 화면만** 다룬다. 게임 조회 명령 추가, HUD 창 생성, 자동화는 별도 후속 설계다. 커넥터 비교 문서의 49개 검토 항목을 현재 구현 목록이나 일괄 구현 승인으로 취급하지 않는다.

## 권장 방향과 대안

- 권장: 같은 IRIS 안에서 애드온 바는 관리·조작, 향후 HUD는 읽기·관찰을 맡는다. 기존 계정·보호 대기함·조회 흐름을 재사용한다.
- 모든 기능을 항상 보이는 버튼으로 추가: 한 번에 찾기는 쉽지만 앞으로 화면 높이와 탐색 혼잡이 계속 늘어난다.
- HUD를 별도 앱으로 제공: 독립 실행은 가능하지만 로그인·조회·저장 상태와 업데이트 경로를 중복 관리하게 된다.

## 이번 화면 변경안

1. 제목·Beta 버전·업데이트 버튼, 캐릭터 선택과 계정/홈/설정 위치를 유지한다.
2. 크로노스(가방)와 시낙시스(레이드)는 현재 상위 메뉴·SVG·명칭을 유지한다.
3. 크로노스의 7개 상시 버튼을 **현재 기능 이름 + ‘기능 선택’ 버튼** 한 줄로 정리한다. 선택한 기능은 패널을 닫아도 항상 읽을 수 있다.
4. ‘기능 선택’을 누르면 세 묶음이 한 패널 안에 모두 나타난다. 묶음을 다시 눌러 들어가는 추가 탭은 만들지 않는다.

| 묶음 | 기존 기능 | 설명 |
| --- | --- | --- |
| 생텀 기록 | 숙제 / 물물교환 / 상점구매 / 임무게시판 | 생텀에서 관리하는 기록 |
| 캐릭터 관리 | 클래스 / 스탯 | 저장 레벨과 본인 게임 스탯 비교·확인 |
| 게임 정보 | 재화 | 공식 커넥터로 읽은 현재 게임 정보 |

5. 별도 검색창·즐겨찾기 메뉴·새 홈 화면은 이번에 추가하지 않는다. 7개 기존 기능은 빠짐없이 같은 선택 패널에서 접근한다.
6. 기능 선택 패널은 테마 변수와 기존 둥근 카드/절제된 강조를 사용한다. 상위 메뉴와 같은 금색 채움 버튼을 반복하지 않는다.
7. ‘생텀 기록’과 ‘게임 정보’ 설명은 데이터 출처를 구분하기 위한 것이다. 스탯은 두 출처를 비교하는 기존 동작을 유지한다. 게임 일일·주간 미션은 생텀 숙제나 임무게시판과 동일한 기능이 아니다.

## 동작과 데이터 보존

- 기존 `DesktopTab` ID, 마지막 크로노스 기능 기억, 시낙시스 왕복, 설정 진입/복귀를 유지한다.
- 기능 전환 시 기존 패널을 불필요하게 다시 만들지 않는다. 클래스 초안·보호 대기함·미저장 기록과 저장 안내를 그대로 보존한다.
- ‘기능 선택’ 패널을 여는 것만으로 조회·저장·커넥터 명령을 실행하지 않는다. 실제 기능 변경에만 기존 `onTabChange`와 활성 패널 흐름을 적용한다.
- 잠금 중 선택을 막고, 잠금/설정 진입/상위 메뉴 변경/캐릭터 변경 시 열린 선택 패널을 닫는다.
- 계정·테마·캐릭터·기능 선택 패널이 서로 겹치지 않게 한다. 바깥 클릭·Escape·선택으로 닫는다.
- 기능 선택은 일반 버튼 목록으로 구현한다. 열 때 현재 선택으로 초점을 이동하고, Tab으로 탐색한다. Escape/취소 시 호출 버튼으로 복귀하고 선택 시 현재 기능 위치로 복귀한다. 숨긴 패널은 초점과 클릭을 받지 않는다.
- 짧은 화면에서는 선택 패널 내부만 스크롤한다. 12자 닉네임과 기능 이름은 생략하지 않고 읽을 수 있게 줄바꿈한다.
- DB/API/권한·보호 기록 형식·native bridge·게임 조작·새 라이브러리 변경은 없다.

## 구현 대상과 검증 기준

- `components/iris/DesktopCenter.tsx`: 탐색 묶음·선택 패널·기존 전환/초점 동작.
- `app/iris/desktop/desktop.css`: 범위 한정 선택 패널 스타일. 전역 6테마와 rem 기준 사용.
- `tests/iris-navigation.browser.mjs` 및 관련 fixture: 7개 기능 접근, 상위 메뉴 왕복, 미저장 초안 유지, 잠금·Escape·외부 클릭·초점 복귀 회귀.
- 기존 스탯/재화/즐겨찾기/시낙시스 시험 중 탐색 전환과 연결된 검증만 우선 실행한다. 메뉴를 여는 것으로 추가 호출되지 않는지 확인한다.
- 320/390/768/1280px, PC 글자 3단계, 밝은/어두운 테마에서 잘림·겹침·가로 넘침·조작 불가가 없어야 한다. 6테마의 선택/초점 대비도 확인한다.
- 묶음 완료 시 타입·관련 통합 테스트·빌드와 변경 diff를 확인한다. 운영 파티 생성/해산/탈퇴 시험은 하지 않는다.

## 이후 HUD 확장 순서 — 이번 구현 범위 밖

1. 공식 CLI 응답 계약을 확인하고 게임 미션·가공 상태/남은 시간·에린 시각/환경·가방 무게의 읽기 전용 데이터 계층을 별도로 설계한다. 응답이 없는 값은 0이나 완료로 만들지 않는다.
2. 같은 IRIS 관리 프로세스 아래 선택해서 켜는 소형 HUD를 연결한다. 현재 애드온 바의 클릭 통과/투명도 제한은 유지하며, HUD는 별도 안전한 입력·숨김·복구 규칙을 설계한다.
3. 스탯/재화와 새 HUD는 단일 조회 조정 흐름을 공유한다. 숨긴 위젯·게임 종료에서 조회를 멈추고 오래된 값·관측 시각·연결 오류를 구분한다. 게임 데이터로 생텀을 자동 수정하지 않는다.
4. 게임 미션 → 가공 → 시계/환경 → 무게 순으로 하나씩 계약·표시·복구를 검증한다. 구형 `overlay.ps1` 시제품을 동시에 실행하거나 완성된 최신 앱 기능으로 간주하지 않는다.
5. 인벤토리·레시피 계산은 그 다음 후보, 수령/제작/채집·원격 조작·음악은 별도 승인과 안전 설계가 필요한 후속이다. 외부 도구를 필수 설치로 만들거나 코드·레시피·그림을 무단 복제하지 않는다.

## 승인 경계

기능 선택 방식과 첫 단계 범위는 승인됐다. 이를 바탕으로 구현 계획을 작성하고 실행 방식을 확인한 뒤 제품 코드를 변경한다. 다음 HUD 설계의 승인으로 확대 해석하지 않으며 버전 상승·push·공지 게시·운영 DB 변경은 별도다.
