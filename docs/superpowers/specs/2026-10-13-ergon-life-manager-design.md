# ERGON 스마트 생활 매니저 — 착수 설계

상태: **2026-10-13 한설 설계 승인, 실행 계획 검토 단계**. ‘구현해줘’로 설계 진행을 승인했다. 이 문서는 구현 범위·안전 동작을 구체화하며, 아직 구현 완료 또는 실제 게임 실행 승인 기록이 아니다.

## 목적과 범위

에르곤에서 재료·가공 현황을 읽고, 만들 품목과 수량을 계획하고, 명시적으로 승인한 생활 작업을 실행하고, 관측된 결과를 확인한다. 별도 외부 생활 앱 설치를 요구하지 않는다. 기존 크로노스 저장·시낙시스·창 연동·업데이트를 보존한다.

이번 ‘남은 기능’은 **에르곤의 조회·재고·레시피·목표 계산·작업 계획·채집/가공/제작·시설 수령·제한된 순차 실행·작업 기록**으로 해석한다. 음악/모바일 원격/외부 공유/게임 채팅/독립 HUD 창은 이 묶음에 추가하지 않는다. 운영 DB·RLS·신규 서버·유료 서비스 변경 없음. 기존 2026-10-11 재고/생활 설계의 원칙을 구체화한다.

## 현재 확인한 공식 계약

사무실에 설치된 공식 MabinogiMobile_CLI.exe의 `--help`, `capabilities`를 읽었다. 아래 조회만 실제 실행했다. **수령·채집·가공 등록·제작·stop_action은 실행하지 않았다.** 원문은 Git 제외 scratch에만 있으며 전체 개인 재고를 문서·공지에 넣지 않는다.

| 구분 | 실제 확인한 응답 / 공식 capabilities |
| --- | --- |
| 생활 상태 | get_activity 실제 최상위 IsAutoPlaying/IsAutoTraveling/IsDead/IsReviving/IsInCombat/IsDialoguePlaying/IsWaitingForSelection, Dungeon/Battlefield/Tutorial/Scenario/Performance/Interaction/Mode. 설명의 autoPlay/combatState 묶음이 실제 JSON 구조와 다르므로 실제 평면 필드를 따른다 |
| 무게 | get_inventory: CurrentInventoryWeight/CurrentInventoryWeightAsDecimal/MaxInventoryWeight/MaxInventoryWeightAsDecimal |
| 가공 진행 | get_altering_works: completedCount, works의 DisplayName/FacilityName/State/IsCompleted/RemainingSeconds |
| 채집 후보 | get_gatherable_items 실제178행, DisplayName/ToolOk |
| 가공 후보 | get_alterable_items: DisplayName/Alterable/ProducedPerWork/Reason/MissingIngredients |
| 제작 후보 | get_craftable_items: craftingUnlocked, DisplayName/Craftable/ProducedPerCraft/Reason/MissingIngredients. 이번 읽기545행/약117KB |
| 재료 | get_items의 Ingredient 필터 실제485행/약80KB: Location/DisplayName/Category/CategoryDisplayName/Count/IsLocked. 위치는 inventory/account_storage/character_storage |

현재 스탯/재화 reader는 64KB/8초 제한이다. 실제 생활 목록은 이를 넘는다. **기존 reader의 제한을 무조건 풀지 않고 별도 생활 reader**로 분리한다. 생활 읽기는 명령별 최대1MiB/8초/깊이16/목록2048행/문자열160자 제한을 시작값으로 사용하고 초과는 부분 성공으로 숨기지 않는다. 실제 목록과 합성 경계 시험으로 조정한다. 무게 Decimal 우선·누락은 null 유지.

### 중요한 제한

- 레시피 응답은 전체 재료표가 아니라 현재 **부족 재료**를 제공한다. 이미 보유한 재료의 필요량을 누락 목록에서 역산하지 않는다. 전체 BOM 없는 다회 소모량/선행 체인은 ‘미확인’이다.
- 제작 가능한 목록에 있다고 임의 시설 최대 횟수를 만들어 표시하지 않는다. 공식 execute_crafting은 craftCount가 제작 횟수이며 시설별 maxCount는 거절 응답에 나타날 수 있다. 첫 실제 실행은1회로 제한한다.
- execute_gathering의 문서화된 입력은 displayName이며1회 최대100개를 수집한다. 목표20개를 보냈다고20개에 멈춘다는 계약은 없다. 임의 quantity 인자를 추가하지 않는다. 작은 목표의 정확한 자동 종료는 미지원으로 표시한다.
- 낚시 전용 품목은 started 후 무기한 자동 낚시이며 자동 설정도 남는다. 같은 명령이지만 일반 채집처럼 완료100개로 취급하지 않는다. 초기 자동 큐에서는 낚시를 제외한다.
- stop_action은 현재 게임의 여러 행동을 멈출 수 있으며 IRIS 작업 전용 stop ID가 없다. 다른 앱 작업까지 멈추는 자동 중지를 만들지 않는다.
- CLI 조회는 실제 게임 닉네임/고유 캐릭터 ID의 증명이 아니다. 생텀 선택 캐릭터를 게임의 확정 신원으로 표시하지 않는다.

## 화면 — 네 메뉴의 실제 역할

### 작업 계획

- 검색해 선택한 공식 조회 품목, 채집/가공/제작 경로, 목표 산출량, 작업당 산출량, 계산된 필요 횟수, 현재 조회 가능/차단 이유 표시.
- 계산은 ceil(목표/확인된 산출량). 산출량0·미확인은 계산 불가. 같은 이름의 불명확한 경로는 실행 불가.
- 부족 재료는 현재1회 기준임을 표시한다. 전체 레시피 자료가 없으면 전체 체인/다회 총재료 계산은 차단한다. 초기1회 계획은 저장할 수 있다.
- 계획 편집과 실행 승인을 분리한다. 계획을 저장했다고 게임을 조작하지 않는다. 로컬 환경/생텀 계정별 최대50항목, 재시작 시 실행 상태 복원/자동 실행 없음.

### 재료 확보

- 재고 검색·위치별 구분·잠김 표시, 가방 무게·조회 시각·오래된 값/일부 미지원 표시.
- 계정/캐릭터 창고를 가방 가용 재료로 자동 합산하지 않는다. 공식 Craftable/Alterable 판정과 창고 이동 비용/잠금 이유를 구분한다.
- 가공 시설별 진행/완료 수량과 남은 시간. 총시간 없는 진행률은 만들지 않는다. 수령 가능 상태와 현재 품목을 보여주지만 조회로 수령하지 않는다.

### 자동 실행

- 준비된 계획을 확인한 뒤 **명시적으로 시작한 제한 실행**이다. 기본 자동 시작/무한 반복/재시작 재개는 없다.
- 완성 순서: 시설 하나 수령 → 가공1회 등록 → 제작1회 → 일반 채집1회 → 검증된 단일 행동만 묶는 제한 큐. 한 단계씩 합성/native 검증하며 실제 시험은 승인 대상/소모 한도를 별도로 받는다.
- 실행 전 현재 게임 상태/대상/수량/이동 포함/예상 날개·재료/누락 정보/현재 캐릭터 확인을 보여준다. 생텀 DB 저장과 다른 게임 명령임을 알린다.
- 채집/가공 등록/제작은 **각 명령 호출당 정령의 날개5개**라는 공식 계약을 표시한다. 수령 명령에는 고정5개 소모 계약이 명시되지 않았으므로 ‘무료’라고 단정하지 않는다.
- 기본 비용 한도5개/단일 실행, 초기 큐 최대5개 명령·합계25개 이내. 사용자가 승인한 한도를 늘리거나 잔여를 임의 재사용하지 않는다. 완료 후 재실행은 새 확인이 필요하다.
- 시설 수령은 선택 품목 하나만이 아니라 **그 시설의 완료 작업 전체**를 수령한다. 같은 시설 그룹과 수령 대상 전부를 확인창에 보여준다.
- 전투/죽음/부활/대화/선택 대기/던전/전장/튜토리얼/시나리오/연주/다른 자동 플레이·이동/하우징 편집/미니게임은 차단. 필수 필드가 없거나 읽기에 실패해도 실행하지 않는다.
- ‘대기 작업 중지’는 다음 명령을 보내지 않는 기능. 현재 게임 행동 중지는 별도 확인을 거쳐 영향 범위를 알리며, 공식 소유권을 증명할 수 없으면 게임 Stop 버튼 사용을 안내한다. CLI 프로세스 종료를 게임 작업 중지라고 표시하지 않는다.
- 큐 시간 한도는 **다음 작업 시작 차단**이며 진행 중 명령의 강제 종료 보장이 아니다. 오래 걸리면 경고와 수동 게임 중지 안내. 이 제한을 사용자가 확인하기 전 큐 시작 불가.

### 작업 기록

- IRIS가 요청한 명령·선택 대상·승인 한도·시작/응답/후속 관측·중단/실패/결과 불명 기록. 전체 계정 소비나 타 앱 작업 이력이라고 주장하지 않는다.
- 비용 예상과 CLI가 알려준 실제 비용/산출을 분리한다. accepted만으로 성공 처리하지 않는다. 가공 started는 등록 완료이지 생산 완료가 아니다. 낚시 started도 채집 완료가 아니다.
- 성공 판단에 필요한 후속 조회 실패/대상 변경은 결과 불명. 불명확 작업은 재시도·다음 의존 작업·새 작업을 막고 재조회/본인 확인만 제공한다.
- native 별도 보호 파일에 환경/계정별 보관,30일 또는 최근300건. 인증/전체 재고/보호 저장 큐 원문을 넣지 않는다. 실행 기록 보관 실패 시 새 행동을 시작하지 않는다. 명시적 삭제/내보내기는 후속 범위다.

## 구조와 보안

- UI: DesktopErgon 아래 조회/계획/실행/기록 모듈. 단일 useErgonSession이 active/context 변경·늦은 응답·조회 조정을 담당한다. 기존 SANCTUM 보호 저장 큐와 타입/상태/파일 모두 분리한다.
- 읽기: native 고정 command allowlist. 브라우저가 실행 파일 경로·명령 문자열·임의 인자를 보내지 않는다. 목록은 같은 세션의 latest snapshot으로 판정한다.
- 행동: native가 공식 목록/사전 점검을 다시 읽고 확인한 enum action + snapshot에 있는 displayName + 검증된 횟수로 JSON을 재구성한다. shell 실행 없음. unknown action/추가 필드/개행/초과 길이/미확인 대상 거부.
- 브라우저 확인창만 믿고 소비 명령을 수행하지 않는다. native가 승인한 intent/nonce·계정/게임 context·요청ID·승인 비용을 결합한다. 동일 요청/동시 실행/재생 공격을 native 단일 실행 잠금으로 차단한다.
- lifecycle/현재 origin/epoch 검증 유지. 캐릭터 추천/계정 전환/게임 종료/최소화·업데이트 시 새 행동은 정지하고 진행 중 결과를 불명으로 기록한다. 기존 앱 종료 저장 기능을 생활 재개 기능으로 바꾸지 않는다.
- 읽기 기본은 수동 새로고침. 활성 가공 목록만10초 단일 flight, 숨김/최소화/연결 불가에서 중지. 실행 모니터는 별도 조정자에서 중복 없이 이어지며 새 명령을 자동 만들지 않는다.
- 긴 실행용 runner는8초 reader와 분리한다. CLI timeout/종료는 게임 행동 완료 증거가 아니며 자동 재시도하지 않는다. 공식1시간 사용자 재확인·blocked 팝업·권한 거부를 우회하지 않는다.

## 검증·출시·제외

- 조회/계산:0/null/소수/대목록/전체 BOM 누락/동명/잠김/위치 중복/변경된 snapshot/오래된 응답/계정 전환/조회 중 숨김.
- 행동: 연속 클릭1회만 전송, 승인 한도 초과0호출, unsafe/unknown state0호출, 전송 직전 상태 변경 차단, 요청 재생 거부, started와completed 구분, 비용 실패/부분 생산/accepted+error/후속 조회 실패/CLI 종료/중지 미확인/앱 재시작0자동재개.
- 실제 UI 좁은 창·6~22pt·6테마·Escape/바깥 클릭/키보드, 타입/전체 Node/build/native 패키지/보호 기록 회귀.
- 실제 게임 시험은 한설이 고른 시설/품목·날개/재료 한도를 확인한 뒤 진행한다. 구현용 합성 시험과 실제 게임 완료를 구분한다. 신규게임명령이 있는 공개 패키지·버전·push·배포·공지 역시 별도 마감 승인 또는 기존 사용량 임계값 체크포인트 범위로 구분한다.
- 전체 레시피 사전·정확한 소목표 자동 채집 종료·무기한 낚시 자동 큐·소유권 불명 자동 Stop·숨은 클릭·외부 자료 무단 복사·자동 DB 이력은 구현 완료로 가장하지 않는다.

## 설계 자체 점검

- 주 사용자 의도(생활 준비→확인된 행동→결과 확인)를 네 메뉴에 대응시켰다. 브랜드/그리스어 소개를 반복하지 않는다.
- 실제 조회117KB/80KB와 평면 activity 필드를 반영했다. 임의 CLI 필드/전체 재료표/작업ID/가공 전체 시간/공식 최대 제작 횟수를 발명하지 않았다.
- 가장 큰 위험은 명령이 발생한 뒤 결과 불명·다른 앱의 Stop·자동 낚시 무한 실행이다. 초기 단일 행동/새 확인/불명 차단/낚시 제외로 완화한다.
- 설계 승인 후 파일별 실행 계획을 작성·검토받고, 조회/계획부터 구현한다. 이 문서만으로 게임 명령을 전송하지 않는다.
- 사용자 추가 중단 조건: 5시간 또는 주간 사용량 중 어느 하나든 잔여3% 이하이면 새 구현을 멈추고 검증 상태·미완료 작업을 인계 후 정상 체크포인트 push한다. 운영 미검증/실제 생활 미연결 기능을 완성 버전으로 배포하지 않는다.
