# IRIS 저장 안정성·전환 저장·재화 마지막 조회 설계

기준: 2026-10-22, 영겁. 원격 기능 브랜치 `codex/home-gnosis-iris-integration-20261019`, HEAD `a95c0768a490d18ff0f8ab4b1e0c62cd5c05bb33`. 사용자 승인된 대화 설계를 상세화했다. 제품 구현·합성 검증은 아직 수행하지 않았다. 별도 관리 worktree이며 집 개인12항목은 원래 checkout에 보존한다.

## 목적과 대안

사용자가 체크한 내용을 신뢰할 수 있게 보관하고, 전환 시 구계정 인증으로 저장한 뒤 이동한다. 재화는 연결 없이 마지막 조회를 볼 수 있지만 현재 가용 잔액으로 표시하지 않는다. ERGON B-2는 보류한다.

권장: 기존 항목별 CAS/멱등성·직렬 전송은 유지하고 대기 마감과 전환 조정을 개선한다. 서버 일괄 저장은 스키마/API 영향이 크므로 제외한다. 현재 trailing debounce만 유지하는 대안은 계속 수정할 때 기존 항목까지 지연시키므로 채택하지 않는다.

## 확인된 소스 계약

- queue의 edit는 같은 범위 모든 pending을 매번 now+15000으로 재예약한다. leaveCharacter도 15초를 다시 부여한다. 이것은 정적 추적 사실이며 사용자가 체감한 지연의 합성 재현은 다음 단계다.
- controller는 durable inflight 보관→최신 상태 검사→save→결과 보관을 직렬 수행한다. selectCharacter는 전송 완료를 기다리는 흐름이 아니며 switchAccount/login은 keep 전환이다.
- unknown은 자동 재전송하지 않고 명시적 복구로 검사한다. 계정 epoch/selection, 요청별 settle 및 CAS는 보존해야 한다.
- DesktopCurrencies는 화면 메모리만 사용한다. CurrencySnapshot에는 조회 시각/이름/수량만 있고 귀속 증거가 없다. 선택 캐릭터 ID만 붙여 실제 게임 캐릭터로 간주하지 않는다.

## 1. 자동 저장

최초 유효 수정으로 열린 해당 범위 pending 묶음의 가장 이른 deadline을 유지한다. 이후 수정/취소는 그 마감을 뒤로 밀지 않는다. 순차 전송 중 새 요청은 이미 전송한 요청의 ID/내용을 바꾸지 않고 새 revision으로 보관한다. 같은 항목의 선행 미확인 결과가 있으면 후속 소비가 아닌 서버 쓰기도 기존 보호대로 차단한다. 빠른 변경을 네트워크 요청마다 15초 기다리는 방식으로 만들지 않는다.

첫 네트워크 호출은 묶음 기한 후이며, 대상5개가 모두 baseline이면 details 검사5회+항목별 save5회를 기대한다. 최신 상태가 이미 desired이면 쓰기는 생략할 수 있으므로 정확 호출 수는 각 fixture 전제와 함께 기록한다. 새로운 batch API나 병렬 쓰기를 추가하지 않는다.

느린 요청이 있는 동안 순차 대기는 유지한다. 전송 완료를 꾸며내거나 timeout만으로 미전송으로 되돌리지 않는다. 응답 유실은 unknown으로 보관하며 명시적인 결과 대조 후 처리한다. 기간 경계는 기존 periodKey로 검사하고 새 기간으로 요청을 옮기지 않는다.

저장 표시는 로컬 보관 중/보관 실패, 서버 대기, 전송 중, ACK 확인 완료, 결과 확인 필요를 분리한다. pending이 없다는 사실만으로 완료를 표시하지 않는다. 성공 표시는 해당 범위 잔여 항목 및 새 revision을 확인한 뒤 표시한다. 항목별 미리보기 숫자는 저장 완료 증거가 아니다.

## 2. 전환

캐릭터·계정·로그인 변경은 단일 전환 gate 안에서 새 편집/중복 전환을 차단한다. 기존 실행 중 요청을 기다리고 전환 대상과 구계정/캐릭터/epoch를 고정한다. pending 기한을 즉시 앞당겨 구계정 세션으로 전송·확인한 뒤 새 캐릭터 조회 또는 쿠키 변경을 수행한다. account 공용 항목은 실제 큐 소유권 규칙을 유지한다.

실패/인증 만료/unknown/conflict/expired가 남으면 자동 전환하지 않는다. 짧은 ‘저장 중’ 안내 후 실패 시 재시도·이 PC에 보관 후 전환·돌아가기를 제공한다. 보관 후 전환은 로컬 원자 저장 성공을 먼저 확인하고 네트워크 결과를 성공으로 변경하지 않는다. 다른 계정 항목은 삭제하지 않는다. invalid 클래스 초안은 고치거나 되돌리는 기존 보호를 유지한다.

logout/종료는 기존 save/keep/discard 선택을 별도로 유지한다. 응답 유실 상태에서 keep 종료는 네트워크 없이 보호 보관할 수 있어야 한다. 게임 생활 명령 busy gate와 종료 미저장 보호를 우회하지 않는다.

## 3. 재화 캐시

기존 DPAPI·원자 replace/backup 패턴을 재사용하되 큐/ERGON 원장과 별도 파일·형식·잠금을 사용한다. 환경/인증 계정으로 namespace를 나누고 캐릭터 귀속은 verified 또는 unverified로 명시한다. 공식 응답에 귀속 증거가 없는 현재 단계는 unverified 관측으로만 보관한다. 다른 계정/환경·확정 캐릭터 값으로 자동 승격하거나 복사하지 않는다. 사용자 선택과 공식 귀속 검증을 혼동하지 않는다.

성공 응답의 검증된 숫자만 저장한다. 일부 null/누락/조회 실패가 정상 숫자를 지우지 않도록 품목별 마지막 정상 시각을 유지하며 다른 시각의 값은 같은 최신 snapshot으로 가장하지 않는다. 빈 응답은 기존 값을 삭제하지 않는다. 저장 실패 시 화면 조회 성공과 영속 보관 실패를 구분한다. 손상 캐시는 원본을 덮지 않고 보관 불가로 안내한다.

재시작은 캐시 읽기로 시작한다. ‘마지막 확인 기록’, 한국 날짜·시각, 연결 끊김/귀속 미확인을 표시하고 수동 새로고침을 제공한다. 연결 복구 후 성공 조회만 갱신하며 자동 무한 재시도/고빈도 폴링은 추가하지 않는다. 오프라인 캐시를 ERGON 비용 승인·시작 전 점검의 live balance로 전달하지 않는다. 새 DB/API/Realtime/Storage 사용0.
