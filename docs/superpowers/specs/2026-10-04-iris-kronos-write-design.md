# IRIS 크로노스 체크 저장 설계

작성: 2026-10-04 · 영겁
상태: 2026-10-04 한설의 `진행하자`로 설계 승인, 후속 `작업진행해줘 왠만하면 쭉 해줘`로 inline 실행 승인. 로컬 구현·합성 자동 검증 완료(161/161·타입·린트·빌드). 실제 운영 쓰기 검증·독립 리뷰·배포 완료를 뜻하지 않는다.

## 목적과 단계

한설이 실제 게임 위 체크보드의 읽기 연결과 항목 표시를 확인했다. 다음 목적은 웹을 다시 열어 조작하지 않고, 확인한 본인 캐릭터의 숙제를 오버레이에서 체크하고 생텀에 저장하는 것이다. 실제 게임 콘텐츠 완료 자동 판정이나 게임 보상 수령이 아니다.

전체 목표는 ① 크로노스 체크 저장 ② 시낙시스 내 파티·신청 상태 조회 ③ 단일 IRIS 센터의 카테고리 정리 순서로 나눈다. 이 설계는 **①만** 구현 대상으로 삼는다. 시낙시스와 센터 개편은 별도 설계·계획·검증을 거친다. 그노시스는 카테고리 방향만 유지하며 새 기능을 가정하지 않는다.

## 선택한 경로와 대안

- 권장: 기존 승인 브라우저가 Windows의 최소 변경 요청을 받아, 생텀 서버 인증 경로로 저장한 뒤 결과를 돌려준다. 로그인 정보와 서버 키를 Windows에 전달하지 않는다.
- 웹 페이지 열기만 제공하면 현재의 번거로움을 해결하지 못한다.
- Windows에서 DB에 직접 연결하는 방식은 인증·키 보관 경계를 늘리므로 채택하지 않는다.

센터는 하나를 유지하고 이후 내부 카테고리로 기능을 고른다. 카테고리별 센터 창을 동시에 추가하지 않는다. 독립 위젯은 사용자가 필요한 것만 표시한다.

## 기존 코드 기준

- `lib/irisRelay.ts`: 승인된 브라우저의 직렬 15초 조회와 localhost 중계, 계정·선택·generation 경계.
- `iris/connection-state.mjs`, `iris/connection-http.mjs`: native/browser 역할별 인증과 선택 상태.
- `iris/overlay-checkboard.cs`: 현재 읽기 전용 항목 위젯.
- `lib/irisKronos.ts`: 웹과 같은 숙제 판정, 상세 행·합계 생성.
- `app/api/member-mutations/route.ts`: 본인 캐릭터 인증, `_checklistAction` 단일 항목 변경, 기존 체크 기준 부분 병합 및 비교 조건부 쓰기. 그대로 모든 형태를 호출할 수 있다고 가정하지 않는다. 반복 항목과 기간 경계를 검증하고 서버 전용 공통 로직으로 재사용한다.

## 사용자 동작

1. 기존 읽기 동의와 별도로 웹에서 **숙제 수정 허용**을 명시한다. 허용 전에는 읽기 전용이다.
2. 현재 게임 캐릭터를 기존 방식으로 직접 확인한다. 위젯 상단에 선택 캐릭터와 읽기/수정 상태를 항상 표시한다.
3. 일반 숙제는 체크/해제, 반복 숙제는 −/+로 변경한다. 범주별 완료 합계는 로컬 변경을 반영하되 미저장임을 명시한다.
4. 첫 출시 범위는 **명시적 저장 버튼**이다. 자동 저장은 이 설계에서 활성화하지 않는다. 여러 조작을 모아 저장할 수 있어 매 클릭마다 DB를 호출하지 않는다.
5. 미저장 → 저장 중 → 저장 완료/실패/충돌 상태를 구분한다. 서버 결과와 재조회가 확인되기 전 저장 완료로 표시하지 않는다.

남은 숙제 필터·아코디언·클래스 목록은 유지한다. 클래스 레벨 수정, 전체 완료 버튼, 배경 자동 완료는 제외한다.

## 변경 요청과 저장 경계

- 로컬 메모리 큐에 `{requestId, generation, selectionVersion, accountId, characterId, category, taskId, baseCompleted, desiredCompleted, periodKey}`를 둔다. 이름만으로 대상을 식별하지 않는다.
- 같은 항목은 최초 기준값을 보존하고 최종 원하는 값으로 합친다. 숫자 증가 명령을 재전송하지 않고 원하는 절대값을 전달한다.
- 큐는 최대 200항목, 요청 본문은 기존 64KiB 제한을 따른다. 초과 시 저장을 막고 안내하며 자르지 않는다.
- native는 본인의 capability로만 큐를 만들고, 승인된 browser capability로만 큐를 읽고 결과를 반환한다. 기존 정확한 Origin·generation·선택 버전 검증을 유지한다.
- 브라우저는 쓰기 허용과 현재 계정·선택을 재확인한 다음 same-origin 새 `POST /api/iris/kronos` 경로로 전달한다. 쿠키·로그인 코드·서비스 키는 loopback으로 보내지 않는다.
- 서버는 매 요청마다 세션, 승인대기 여부, 소유권, 활성 항목, 범주, 현재 한국 기간, 숫자 범위를 검증한다. 다른 프로필·레벨·상점·메모 필드는 입력받지 않는다.
- 최신 저장값이 기준값과 다르고 원하는 값도 아니라면 409 충돌로 반환한다. 최신값이 이미 원하는 값이면 성공 상태를 재확인한다. 변경하지 않은 항목·레거시 기록은 보존한다.
- DB 쓰기는 현재 체크 필드 기준 비교 조건을 사용해 경쟁 변경을 탐지한다. 경쟁 발생 시 자동 덮어쓰지 않는다. 기존 helper의 적용 가능성을 먼저 테스트한다.
- 항목별 직렬 저장 결과를 반환한다. 여러 항목의 원자적 일괄 성공을 약속하지 않는다. 일부 성공 시 성공 항목만 큐에서 제거하고 실패 항목은 남긴다.

## 실패·전환·종료

- 타임아웃은 결과 불명으로 표시하고 먼저 최신값을 조회한다. 결과가 불명인 상태에서 같은 요청을 자동 재전송하지 않는다.
- 저장 중 재클릭을 차단한다. 사용자가 실패 항목을 확인하고 재시도할 수 있다. 무한 재시도·중복 저장 루프를 만들지 않는다.
- 캐릭터 변경·새 연결·계정 변경은 미저장 변경의 폐기 확인 후 진행한다. 진행 중 요청 결과는 원래 대상에만 귀속되고 새 캐릭터 화면에 적용하지 않는다.
- 기존 연결 만료 시 수정 기능을 잠그고 미저장 상태를 명시한다. 큐는 메모리만 사용하며 재연결 후 자동 재생하지 않는다.
- 위젯 닫기/전체 숨김은 큐를 유지한다. 앱 종료는 미저장 경고를 추가한다. 강제 종료·OS 종료 후 큐 복구는 보장하지 않으며 안내한다.
- 승인 브라우저 탭을 닫으면 저장할 수 없다. 새로운 동반 인증 체계는 추가하지 않는다.
- 기존 BETA-065의 기간 정보 없는 과거 반복 기록을 임의로 초기화하거나 보정하지 않는다. 의미를 확정할 수 없으면 해당 항목 저장을 막고 기존 기록을 보존한다.

## 검증과 완료 기준

합성 저장소·fake fetch로 먼저 실패 테스트를 만든다. 무인증/타 계정/타 캐릭터/만료/잘못된 범주·기간·수치 거부, 부분 병합, 웹과 동시 변경 409, 반복 조작 병합, 일부 성공, 응답 유실 후 재조회, 중복 클릭, 캐릭터 전환 및 늦은 응답을 포함한다.

Windows 위젯은 읽기/수정 허용, 체크·반복 버튼, 저장 상태, 필터 합계, 테마·불투명도·숨김 복원 회귀를 합성 데이터로 검증한다. 기존 Node 전체 테스트·TypeScript·웹 빌드·diff 검사를 수행한다.

자동 검증에 실제 운영 DB 쓰기와 게임 조작은 포함하지 않는다. 한설이 별도 승인한 실제 항목에서 오버레이 저장 → 웹 재조회 → 새로고침 유지 → 다른 항목 보존을 직접 확인해야 실동작 완료다. 독립 에이전트 리뷰는 별도 요청 없이는 실행하지 않는다.

## 데이터 영향과 제외

운영 스키마/RLS/권한 변경 없이 기존 체크 필드만 사용한다. 이것이 기술적으로 불가능하면 구현을 멈추고 별도 DB 변경안을 승인받는다. commit/push/배포·공지·게임 조작·수령/채집/가공 자동화·시낙시스 신청/취소는 이번 범위가 아니다.

## 문서 검토

작성자 검토: 범위 분리, 직접 DB 인증 금지, 명시 저장·충돌·부분 성공·타임아웃, 기간 경계 및 실제 쓰기 검증 승인 구분을 확인했다. 사용자 승인 후 구현 계획을 작성하고, 계획 검토와 실행 방식 승인 후 제품 구현한다.
