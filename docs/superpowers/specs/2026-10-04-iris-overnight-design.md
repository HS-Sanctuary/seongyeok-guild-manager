# IRIS 밤샘 확장 설계

한설의 2026-10-04 요청: 중간 확인 없이 영겁이 판단하여 커넥터 기능과 SANCTUM 고유 UI/UX를 최대한 진행하고 2026-10-05 03:00까지 정리한다. 이 요청에 따라 설계/계획 중간 승인 대기는 생략한다. 실제 게임·운영 DB 실행 권한으로 확대하지 않는다.

## 방향

권장: 단일 IRIS 센터 내부에 게임/크로노스/시낙시스/그노시스 범주를 두고 필요한 독립 위젯만 표시한다. 여러 하위 센터 창은 복잡성을 늘리므로 제외한다. 기존 창과 명칭/복구/저장 경로는 보존한다. 새 미지원 범주는 작동하는 것처럼 표시하지 않는다.

## 자동 작업 첫 단위

게임 실행과 분리된 메모리 작업 큐를 자체 구현한다. 허용 종류 gather/process/collect/craft. 지원 명령 목록은 외부에서 주입된 확인 계약만 사용하며 임의 명령을 만들지 않는다. 초기 비활성, 사용자 명시 시작 및 현재 캐릭터 확인, 15초 이내 snapshot, inventory ratio < 설정 상한, 게임 연결/차단 상태 검증을 모두 통과해야 한 작업 claim이 가능하다. 수량 1~100, 최대100 작업, 최대3600초, 과적 상한 50~95%. 결과 accepted는 완료가 아니며 running을 유지한다. 완료/blocked/failed/timeout/canceled를 구분한다. 전송 후 응답 불명은 unknown으로 정지하고 자동 재전송하지 않는다. 중지 후 이미 전달된 작업을 취소했다고 주장하지 않는다. 큐는 재실행 복구를 보장하지 않는다.

실제 CLI adapter/HTTP 노출/게임 실행은 이번 첫 단위에 포함하지 않는다. 큐 테스트 통과를 실제 채집·수령 기능 완료로 표현하지 않는다. 기존 reader 허용 목록은 변경하지 않는다.

## CLI 요청 계약 단위

2026-10-04 metadata capabilities를 재조회했다(실제 동작 없음). gather는 `displayName`만 받으며 한 호출 최대100, 원하는20처럼 임의 목표 수량을 전달하는 계약은 없다. process는 한 호출1작업, craftCount는 출력 수가 아닌 제작 횟수다. gather/process/craft는 호출당 정령의 날개5 비용이 명시돼 있다. collect는 완료 작품 DisplayName으로 한 시설 전체를 수령한다. 순수 `planAction`은 최신(15초) 카탈로그에서 정확한 반환명/가능여부/도구/비용 한도를 검사해 이 계약만 생성하고, 미지원 수량은 거절한다. `classifyActionResult`는 accepted만으로 완료를 만들지 않고 제작completed/가공started/채집completed/수령collected를 구분한다. 실제 명령 호출/HTTP 배선은 제외한다.

센터에서 게임 위젯/생텀 숙제 진입을 구분하고, 여유 있는 간격과 대비 높은 주/보조 글자를 사용한다. 각 표시 버튼은 기존 독립 창을 열며 ×는 숨김 유지. 6테마/불투명도/종료 확인/단축키는 유지한다. 시낙시스는 실제 확인된 스키마와 인증 경로가 확보된 뒤 읽기 전용부터 추가한다. 그노시스는 이번에 데이터를 임의 수집하지 않는다.

## 개별 불투명도 추가 단위

기존 전체40~100% 기본값과 6테마를 유지하며 센터/상태/가공/미션/연결/체크보드의 불투명도를 각각40~100%로 설정한다. 별도 version1 `widget-display-settings.json`은 알려진 창 키와 정수 불투명도만 저장한다. 잘못된 설정은 무시하고 안전한 전체 기본값을 사용한다. 설정의 `전체` 적용은 개별 예외를 전부 초기화한다. 화면 글자와 배경이 함께 투명해지는 기존 Windows 특성을 명시한다. 배율·프리셋/음악회/미디어는 후속이며 이 단위 완료로 전부 구현했다고 표현하지 않는다.
