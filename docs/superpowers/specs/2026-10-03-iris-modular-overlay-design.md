# IRIS 독립 모듈 오버레이 설계

- 작성: 2026-10-03 KST 영겁
- 사용자 방향 승인: 독립 소형 창, 스테이터스 아코디언, 가공/숙제/주변 연주/음악 기능. 중간 승인 대기 대신 자율 실행·후보고를 명시 요청함.
- 이번 구현: 관리창과 스테이터스/가공/게임 미션 세 창. 본인 캐릭터/생텀 크로노스 인증 연결은 별도 기존 설계를 이어 구현한다. 숙제 저장·주변 연주·외부 음악은 후속 별도 구현 단위다.

## 구성

큰 단일창 내부 구역 분리보다 실제 독립 WinForms 창을 선택한다. 한 관리창만 Ctrl+Alt+I/O, 트레이, 타이머, SnapshotPoller와 서버 수명주기를 소유한다. 모듈창은 단축키를 등록하지 않고 관리창의 복구 가능 여부를 참조한다. 관리창 실패/핸들 재생성 시 모든 창의 클릭 통과를 해제한다. 모듈 숨기기는 IRIS 전체 종료가 아니다.

각 모듈은 제목 드래그, 제목 옆 접기/펼치기와 숨기기를 제공한다. 트레이에서 개별 다시 표시하고 전체 숨김/복구도 가능하다. 전체 복구는 통과를 해제하되 사용자가 개별 숨긴 창을 강제로 다시 켜지 않는다. 관리창은 항상 복구된다. 창별 xy/collapsed만 기존 allowlist 저장을 재사용하며 토큰/게임값/닉네임은 파일에 남기지 않는다. 모듈 ID는 stats/processing/missions 고정값이다.

기존 display.Values[0..5]는 스테이터스 6행, [6]은 가공 1행, [7]은 게임 미션 1행으로 배치한다. 생텀 크로노스 데이터로 오해되지 않도록 미션 창은 게임 CLI 출처로 표시한다. 가공은 모든 제작 완료가 아니라 현재 공식 가공기 조회 범위다.

한 서버 조회 결과를 모든 창에 배분한다. 전체 숨김은 요청 취소/기존 값 삭제, 복구 후 새 응답 전 빈 값 유지. 개별 모듈 숨김 때 관리창 조회는 그대로 한 번만 수행한다. 창 크기는 내용 행수로 계산하고 접힌 높이는 44px, 모듈 기본 폭 292px. 기본 위치는 관리창 아래로 배열하고 작업 영역 안으로 보정한다. 글꼴 크기는 기존 native 알파 기준 유지, 실제 다중 DPI 검증은 별도다.

## 검증과 안전 경계

Windows 테스트에서 실제 모듈 클래스의 행수/값 배분/접힘 높이/재펼침/숨김 의도/복구 권한과 불필요한 단축키 등록을 검사한다. 기존 timer/render 함수 회귀를 유지한다. 한설 게임 화면의 초점·드래그·트레이는 직접 확인이 필요하며 자동 완료로 보고하지 않는다.

기존 미커밋 알파 변경을 이어받으므로 현재 작업 폴더에서 보존하며 실행한다. 새 worktree로 미커밋 의존 파일을 누락시키지 않는다. commit/push/운영 배포/운영 DB 변경/유료 구매는 하지 않는다. 음악 서비스 인증은 계정 ID가 아닌 공식 동의 흐름으로 설계하고, 게임 API 제공 범위 밖 데이터나 MoFo 내부 구현을 추정하지 않는다.
