# IRIS 본인 캐릭터 선택·크로노스 읽기 연결 설계

- 작성: 2026-10-03 KST, 영겁
- 상태: 10/3 한설이 모듈형 방향을 승인하고 중간 설계·계획 승인 대기 대신 자율 판단·후보고 실행을 명시 요청했다. 로컬 구현은 영겁의 inline 실행으로 진행한다. 운영 DB/배포/구매 승인은 포함하지 않는다.
- 범위: 로컬 개발 후보. 운영 DB 변경·공식 push·배포·공지·버전 변경은 포함하지 않는다.

## 1. 사용자 의도와 성공 기준

한설은 게임 위 IRIS에서 생텀 계정의 캐릭터를 직접 선택하고 마지막 선택을 기억하길 원한다. 클래스·능력치로 캐릭터를 추측하지 않는다. IRIS의 생텀 연결 버튼이 연결용 브라우저를 열고, 이미 로그인했다면 재입력 없이 연결 확인으로 넘어간다. 자동 열림은 게임 화면을 가리거나 키보드 초점을 가져오지 않는 것이 목표다. 로그인/연결 승인은 사용자가 브라우저에서 직접 한다.

게임의 현재 `get_my_info` 응답 필드와 capabilities 28개 명령의 공개 계약을 10/3 다시 확인했다. 닉네임·캐릭터 UUID 조회는 확인되지 않았다. 실제 게임 값은 출력/파일 저장하지 않았다. 생텀 `characters.id`는 기존 DB 행 식별자이며 게임 캐릭터 신원 증명이 아니다.

성공: 승인된 내 캐릭터 목록이 오버레이에 나타남 → 캐릭터 선택/확인 → 그 캐릭터의 생텀 숙제 요약 읽기 표시. 다른 캐릭터로 전환하면 이전 요약이 즉시 사라지고 새 선택의 결과만 표시한다. 연결 실패·만료 때는 오래된 기록을 정상 상태로 표시하지 않는다.

## 2. 접근 방식과 선택

1. **기존 브라우저 세션 중계(선택)**: 로그인 쿠키는 생텀 브라우저에만 유지한다. 브라우저가 본인 목록과 요약을 인증된 서버 API에서 읽어 loopback IRIS에 전달한다. DB 구조 변경이 없고 지금 로그인 체계를 재사용한다. 연결 탭이 살아 있어야 하며 백그라운드 탭 지연/중지 시 오버레이는 대기 또는 끊김으로 바뀐다.
2. 독립 Windows 기기 인증: 브라우저 없이 지속 연결이 가능하지만 기기 토큰 발급·폐기·범위/만료와 서버 저장 구조 설계가 새로 필요하다. 후속 승인 과제로 남긴다.

오버레이에 생텀 로그인 코드·쿠키·서버 키를 복사하는 방식은 사용하지 않는다. 게임 UUID가 제공되기 전에는 DB에 가짜 게임 식별자를 추가하지 않는다.

## 3. 사용자 흐름·화면

- 실행 시 기존 게임 읽기 HUD와 두 단축키 동작을 보존한다. 브라우저를 무조건 반복 실행하지 않는다.
- 사용자가 `생텀 연결`을 누르면 1회 연결 시도와 안내를 표시한다: “생텀에 연결하기 위해 브라우저가 열립니다. 연결 후에는 탭을 열어두세요. 최소화해도 됩니다.”
- 기본 브라우저를 비활성 열림으로 요청하는 방법을 별도 검증한다. IRIS가 게임/다른 앱의 포커스를 강제로 되찾거나 브라우저 창을 숨기지 않는다. 기존 브라우저가 요청을 무시할 수 있으므로 뒤에서 열림을 보장한다고 표시하지 않는다. 지원이 확인되지 않으면 자동 열림을 비활성화하고 사용자가 누르는 `생텀 화면 열기`로 대체한다. 사용자가 `생텀 화면 보기`를 누르는 경우의 일반 브라우저 열림은 허용한다.
- 브라우저에서 기존 생텀 로그인과 본인 데이터의 로컬 전달 동의를 받는다. 기존 세션이 있으면 로그인 입력은 생략하되 전달 동의는 생략하지 않는다.
- 승인된 내 캐릭터 목록에서 오버레이가 전체 닉네임을 보여준다. 선택 시 “현재 게임 캐릭터가 맞나요?” 확인 후 크로노스 요약을 읽는다. 게임이 자동 확인한 것처럼 표시하지 않는다.
- 선택한 생텀 캐릭터 이름을 항상 표시하고 `캐릭터 변경`을 제공한다. 재연결/재실행은 마지막 선택을 제안할 뿐 자동 확정하지 않는다.
- 상태: 미연결 / 브라우저 로그인·승인 대기 / 캐릭터 확인 대기 / 연결됨 / 요약 갱신 대기 / 연결 끊김·만료. 재연결은 사용자 버튼으로 한다.
- 게임 CLI의 미션 요약과 생텀 크로노스 요약은 구분된 레이블로 표시한다. 한쪽 실패가 다른 쪽의 정상 조회를 지우지는 않는다.

## 4. 구성·데이터 계약

- 기존 `app/iris/page.tsx`: 브라우저 중계/승인 상태. 읽기 요청은 한 번에 하나, 완료 뒤 다음 호출을 예약한다. 백그라운드 탭의 타이머 실행을 보장하지 않는다.
- 기존 `/api/iris/characters`: 승인된 서버 세션과 소유자 필터를 유지하고 기존 `characters.id`를 최소 목록 응답에 포함한다. 기존 owner 없는 대표 캐릭터의 제한된 호환 규칙은 재사용한다. 계정 ID는 선택 기억을 다른 계정에 재사용하지 않는 구분값이며 인증 수단이 아니다.
- 새 `/api/iris/kronos` GET: 요청 캐릭터 ID를 서버에서 로그인 계정 소유로 검증한다. 기존 daily/weekly/raid JSON과 활성 숙제/콘텐츠 카탈로그를 읽고 `lib/matchingUtils.ts`의 기존 체크·반복 해석을 재사용해 표시용 일간/주간/어비스/레이드 완료·총수만 반환한다. 원본 JSON/불필요한 스탯/다른 캐릭터/메모는 반환하지 않는다. 캐릭터 ID 타입은 DB 기준/실제 조회 계약을 확인해 검증하며 UUID로 단정하지 않는다.
- 기간 판정은 현재 생텀 체크 표시와 같은 규칙을 공유한다. 타임스탬프 없는 구형 체크를 이번 API에서 임의 초기화/새 기간으로 재도장하지 않는다. 일/주간 경계 차이가 발견되면 데이터를 바꾸지 말고 별도 결함으로 보고한다.
- `iris/server.mjs`와 별도 로컬 연결 상태 모듈: 캐릭터 목록, 현재 선택, 갱신 요약, nonce/버전을 메모리에만 유지한다. 브라우저와 native 요청의 역할별 권한을 나눈다.
- `overlay.ps1`와 support 모듈: 비동기 본인 목록/선택/요약 조회, 캐릭터 선택 UI, 상태 표시. 기존 HUD 폴링·트레이·클릭 통과 복구를 유지한다.
- 서버는 루프백 127.0.0.1만 사용한다. native 연결 권한은 IRIS가 직접 시작한 서버와 메모리 토큰으로 연결한다. 기존 서버의 소유를 확인할 수 없다면 자동 탈취/종료하지 않고 사용자 재시작 안내를 한다. 게임 읽기만 가능한 기존 서버는 그대로 보존한다.
- 브라우저의 로컬 전달은 승인 시 발급한 별도 30분 토큰과 정확한 Origin 허용 목록으로 제한한다. native용 토큰을 브라우저에 넘기지 않는다. 연결 변경/해제/만료는 토큰과 메모리 데이터를 비운다. 응답 크기·문자열·목록 개수·JSON 스키마를 제한하고 원본 요청 로그를 남기지 않는다.
- 연결 URL의 임시 브라우저 토큰은 fragment로만 전달하고 읽은 즉시 주소에서 제거한다. 세션 로그인으로 이동하는 동안 서버 쿼리/로그나 return URL에 토큰을 넣지 않는다. 로그인 이동으로 승인 정보가 사라졌다면 재연결을 안내한다. localStorage/sessionStorage에 토큰을 저장하지 않는다.
- 로컬 초기 허용 대상은 `http://localhost:3000` / `http://127.0.0.1:3000`. 운영 origin 추가와 배포는 이번 구현 범위에서 제외한다. 따라서 실제 운영 사이트에 새 연결 UI가 제공됐다고 보고하지 않는다.

## 5. 선택 기억·오류·경쟁 요청

- PC에 저장하는 새 설정은 버전과 마지막 계정 구분값/생텀 캐릭터 ID뿐이다. 기존 창 위치·접힘 설정은 보존한다. 닉네임은 새 로그인 목록에서 다시 얻는다. 로그인 코드·쿠키·연결 토큰·게임 수치·숙제 기록은 디스크 저장하지 않는다.
- 같은 계정의 최신 목록에서 ID가 여전히 존재할 때만 마지막 선택을 제안한다. 다른 계정·삭제된 캐릭터면 기억값을 적용하지 않는다. 설정 오류는 미선택 기본 상태로 안전하게 복구한다.
- 계정 변경/로그아웃/소유권 실패는 목록·선택·요약을 비우고 새 승인을 요구한다. 유효 세션은 매 요약 요청 서버에서 다시 검사한다.
- 캐릭터 선택 버전과 연결 세대 번호를 요청·응답에 묶는다. 늦게 돌아온 다른 캐릭터/이전 연결 응답은 폐기한다. 목록 갱신에서 소유 캐릭터가 사라지면 선택을 해제한다.
- 마지막 유효 생텀 응답 이후 60초 경과 시 요약을 비우고 갱신 대기/끊김을 표시한다. 브라우저 탭 닫힘은 unload 이벤트에 의존하지 않고 freshness 제한으로 처리한다. 표시 만료 판정은 native 타이머로 수행한다.
- 중복 클릭은 요청 중 잠그며 연결 탭을 계속 추가하지 않는다. 숨김/종료는 조회를 중단·정리한다. 클릭 통과 중 캐릭터 선택은 기존 통과 해제 단축키/트레이로 복구한 뒤 사용한다.

## 6. 검증·제외 범위

합성 데이터 자동 테스트: 본인/타인/승인대기/만료 세션, 레거시 대표 캐릭터, 빈 목록·삭제·계정 전환, 설정 allowlist, 구형 체크/반복 해석, 캐릭터 전환 늦은 응답 폐기, 토큰·Origin·Host·메서드·본문 크기·만료·해제, 느린 요청 중복 방지, 60초 stale 비우기. 테스트는 실제 모듈/API를 실행하고 외부 HTTP/DB 경계만 대역으로 둔다. 전체 `node --test`, 별도 타입 검사와 빌드를 수행한다.

한설 수동 확인: 기존 브라우저 실행/미실행 두 경우의 게임 포커스 유지, 로그인→승인→오버레이 목록, 캐릭터 선택/변경·재실행 기억 확인, 다른 계정·탭 닫힘·로그아웃. 자동화로 실제 게임/로그인 입력을 대신하거나 검증 완료를 추정하지 않는다. 뒤에서 열기 미지원이면 버튼 대안이 기본값이다.

제외: 게임 닉네임 자동 인식/UUID 생성, 능력치 기반 신원 추정, 게임 자동 조작, 생텀 체크 수정·능력치 저장·DB 구조/RLS 변경, 장기 기기 인증, 운영 배포/공개 공지. 원본 개인정보는 테스트 fixture·Git·문서에 넣지 않는다.

## 7. 구현 전 검토 결과와 다음 단계

사용자 의도/현 CLI 한계/내 캐릭터 소유권/로컬 저장/브라우저 의존성/초점 유지 목표/운영 제외를 분리했다. placeholder 없이 이번 결과를 읽기 전용 요약으로 제한했다. 기존 game HUD와 생텀 기록의 출처가 혼동되지 않게 했다. 토큰·실제 DB 값 없이 읽기 조사만 수행했다.

10/3 추가 지시로 모듈형 창 기반을 먼저 구현한다. `2026-10-03-iris-modular-overlay-design.md`가 창 분리의 기준이고 이 문서는 그 다음 인증 연결의 기준이다. 사용자가 자율 판단·후보고를 요청했으므로 반복 승인 질문 없이 설계/계획/검증 기록을 남긴다. 현재 Git commit/push 승인이 없으므로 문서는 미커밋으로 보존한다.
