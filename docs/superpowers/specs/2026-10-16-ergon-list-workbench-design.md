# ERGON 목록형 생활 작업대 설계

작성: 영겁 / 2026-10-16 KST / 기준 `07b3f4f`

상태: 한설이 인계 메시지에서 목록형 방향을 승인하고 설계 구체화를 요청했다. 이 문서는 그 방향의 상세 설계안이며 **서면 검토 전·제품 구현 전**이다. 검토 후 실행계획을 작성한다. 사용자 요구를 다시 처음부터 묻지 않는다.

## 목적과 범위

드롭다운과 접힌 대기열을 찾아다니지 않고, 항상 보이는 작업 목록에서 품목·추가 수량·선택·교체·제거를 처리한다. 즐겨찾기와 필요한 재료, 현재 진행 상황을 같은 작업대에 배치한다. 작은 설명을 줄이되 실제 비용·현재 차단 이유는 숨기지 않는다.

첫 묶음은 UI/로컬 상태 재구성이다. 기존 `DesktopErgonQueue`의 편집·예약 계산, `useErgonSession`의 보관 계획, `DesktopErgonExecution`의 행동 보호·관측을 재사용한다. 별도 대기열·진척 엔진을 만들지 않는다. 기본 노출만으로 자동 순차 실행 기능이 생기지 않는다.

전체 자동 생산, Chronos 카드 가져오기, 시설 자동 재충전·정원 계약, 주간 모달 자동 승인, PC 완료 알림은 후속 범위다. 모바일 푸시/외부 PC연동도 포함하지 않는다. 현재 native 수정의 실제 앱 수령 검증은 UI 재설계와 별개의 선행 검증이다.

## 선택한 접근

- 목록 중심 단일 작업대: 승인된 방향. 여러 목표 편집과 현재 선택 작업을 함께 유지한다.
- 기존 화면에 편집 버튼만 추가: 변경은 작지만 접힌 목록·드롭다운 왕복이 남아 제외한다.
- 단계별 마법사: 초회 사용은 단순하지만 여러 품목 비교/수정이 어려워 기본 화면으로 사용하지 않는다.

## 화면 구성

공통 상단은 캐릭터·날개·가방·가공 완료의 짧은 현황과 새로고침이다. 시설 수령 카드는 기존 아이콘/짧은 이름/2열·좁으면1열을 유지한다. 원격 비용은 관련 작업을 선택했을 때 보여주고 상단에 미확인 숫자를 만들어 채우지 않는다.

넓은 작업화면의 기본 구성:

| 품목 찾기 | 내 작업 목록 | 선택 작업 |
| --- | --- | --- |
| 채집/가공/제작·검색·즐겨찾기 | 품목·추가 수량·선택·교체·제거 | 필요/가방/창고/부족·진척·다음 행동 |

작업 목록은 기본 노출하고 별도 ‘전체 대기열’을 편집 진입점으로 요구하지 않는다. 통합 부족분·참고 출처·원장 상세는 접어서 볼 수 있다. 기존 재료 확보/작업 기록 진입 기능은 보존하되 선택은 드롭다운이 아닌 목록을 공통으로 사용한다. 수령을 눌러도 선택된 원래 생산 목표를 삭제하지 않는다.

좁은 화면은 현황→작업 목록→선택 상세 순서다. 품목 찾기는 같은 화면에서 펼치는 영역으로 제공하고 열고 닫아도 검색·선택 목표를 유지한다. 확장 시 같은 데이터·같은 편집기를 사용한다. 선택 행으로 상세 영역을 명확히 연결하며 자동 포커스 이동/스크롤은 사용자의 선택·편집 완료에만 수행한다. 주기 조회로 화면 위치나 입력 초점을 바꾸지 않는다.

320/390/768/1280px, 글자18/20/22px에서 검증한다. 삼분할은 넓은 작업창의 실제 가용 폭을 만족할 때만 활성화하고 태블릿은2영역 또는 세로 구성으로 전환한다. 긴 품목명과 큰 수치는 줄바꿈하며 가로 넘침/잘림을 만들지 않는다.

## 작업 행과 편집 계약

기본 행: `품목명 · 분류 / 추가 수량 [-][입력][+] / 교체 / 제거`. 선택 행은 금색 표시와 선택 텍스트로 구분한다. 표 안 버튼에 다른 버튼을 중첩하지 않고 독립 선택 조작과 입력을 제공한다.

- 수량은 기존1~1,000,000 정수/최대50계획/32KiB 계약을 유지한다. 입력 중 빈 값은 draft로만 두고, blur 또는 Enter에서 유효한 값만 저장한다. Escape는 편집 전 값으로 복귀한다. 잘못된 입력은 짧은 오류와 원래 값을 유지하며0으로 쓰지 않는다.
- 기존 `session.plans`만 단일 원본으로 사용한다. 별도 복제 배열이나 같은 작업의 편집 UI를 중복 렌더하지 않는다. 한 편집의 저장은 한 번이며 실패 시 세션 값 유지·보관 실패 안내를 표시한다. 손상된 저장 원본을 자동 초기화하지 않는다.
- 새 품목 담기는 명시된 추가 수량을 사용한다. 이미 같은 분류/이름의 계획이 있으면 기존 행을 선택·주목시키고 수량 편집을 열며 자동 합산/교체하지 않는다.
- 품목 교체는 검색/현재 분류 선택으로 대상을 고르고 적용한다. 현재 추가 수량은 유지하되 기존 보관 계획을 교체하며 새 plan ID를 부여한다. 옛 품목의 목표 진척/승인/임시 선행 계획을 새 품목에 이전하지 않는다.
- 다른 행과 같은 분류/이름으로 교체하려 하면 기존 행으로 이동 안내만 제공하고 중복 행·암묵적 병합을 만들지 않는다. 검색이 비었거나 미조회이면 최신 고정 목록을 읽어 선택하고 임의 문자열을 native 명령으로 보내지 않는다.
- 제거는 게임 행동 취소가 아니다. 한 번의 명시된 제거로 계획만 지우고, 선택 행 제거 후 남은 인접 행을 선택한다. 마지막 행 제거 시 빈 목록 안내/품목 담기만 제공한다. 실행된 작업을 제거로 성공·취소 처리하지 않는다.
- 준비·최종확인·실행·결과 미확정 관측 중에는 해당 소비 흐름과 충돌하는 품목 교체/수량 수정/제거/다른 작업 시작을 막는다. 이미 보낸 요청의 관측은 메뉴 이동·숨김에서도 기존 수명대로 계속한다. unknown 보호는 보기 편해졌다는 이유로 완화하지 않는다.

## 목표와 진척

첫 묶음의 저장 수량은 기존 **추가 생산 수량**이다. ‘총 보유 목표’로 이름만 바꾸거나 전체 재고를 임의 차감하지 않는다. 향후 총 보유 목표 모드는 재고/등록 중/확인된 완료의 예약 계약을 따로 설계한 뒤 지원한다.

확인된 제작 진척은 기존 account/character/plan ID/품목/수량/산출량 identity와 own terminal 결과 계약을 따른다. 같은 목표를 단순 선택·접기·넓은 창 전환해도 유지한다. 수량 변경·품목 교체는 새 추가 목표로 표시하고 이전 성과를 재사용하지 않는다. 재시작 후 세션 진척을 복구한 것처럼 표시하지 않는다.

선행 작업은 기존 임시계획 흐름을 사용한다. 행에는 원래 목표, 상세에는 현재 선행 단계가 함께 보인다. 가공 등록은 생산 완료가 아니고, 완료품 수령 후 신선한 실제 가방 조회로만 재료를 다시 계산한다. 등록 중 산출량과 예상 산출량을 현재 보유량에 합하지 않는다. 현재 수동 ‘다음 작업’ 안내를 무인 연속 소비로 바꾸지 않는다.

## 즐겨찾기

새 로컬 저장소 `iris_ergon_favorites:v1:<environment>:<accountId>`를 사용한다. 분류+정확한 품목명 쌍만 보관하고 전체 게임 목록·재고·개인 원장을 저장하지 않는다. 최대200개/32KiB, schema1, 중복·제어문자·범위 밖 값 거부, 손상 원본 자동 덮어쓰기 금지, 저장 불가 시 현재 세션에서만 유지한다.

분류 안의 ‘전체/즐겨찾기’ 필터와 별 버튼을 제공한다. 별 버튼은 품목 선택/담기와 분리하며 `aria-pressed`와 품목별 접근 가능한 이름을 가진다. 계정/환경 전환 시 이전 즐겨찾기를 노출하거나 새 계정에 쓰지 않는다. 캐릭터가 바뀌면 같은 계정 즐겨찾기는 유지하지만 현재 공식 목록에 없는 품목은 미확인으로 표시·실행 불가다. 목록상 사라졌다고 저장된 별을 자동 삭제하지 않는다.

## 재료·원격 사용·비용

선택 상세에는 재료별 필요/가방/계정 창고/캐릭터 창고/가방 기준 부족을 나눠 표시한다. 조건부 원격 충족은 별도 상태이며 무료 가용재고로 합치지 않는다. 같은 창고 재고의 중복 예약 방지 규칙을 유지한다. 모호한 품목·잠김·신선도 부족·불완전 참고표를 충분으로 승격하지 않는다.

원격 사용 관련 한 줄: `전송기·부스러기·게임 확인 필요`. 펼치면 마이홈 재료 전송기 설치, 품목/수량별 연금술 부스러기 비용, 일주일 주기의 확인창을 안내한다. 사진의 비용4를 공통 비용으로 쓰지 않는다. 공식 근거가 없는 설치 여부/비용/확인창 숨김 상태는 미확인이다.

시작 옆에는 확인된 요청 단위 날개 비용/보유량과 총비용 확인 범위를 구분한다. 모르는 상한은 ‘미확인’, 원격 비용은 ‘게임에서 확인’이다. 사용자가 화면을 편집하거나 즐겨찾기했다고 비용·주간창에 동의한 것으로 처리하지 않는다. 모달 자동 클릭/일주일 숨김/자동 재시도는 추가하지 않는다.

## 상태와 시인성

금색은 선택/주요 실행, 청록은 담기·수령 등 보조 행동, 중립은 편집·닫기, 빨강은 중지/삭제, 주황은 실제 주의·차단에 사용한다. 색만으로 구분하지 않고 이름/아이콘/상태 텍스트를 유지한다. 테마 변수와 기존 ERGON 역할 토큰을 확장하며 임의 모듈 배율·작은 고정 px 글자를 추가하지 않는다.

기본 설명은 한두 줄, 매 시설마다 반복하는 안내는 공통 접기로 합친다. 차단은 현재 이유 한 줄과 다음 해결 행동 하나를 먼저 보여주고 원장/출처 상세는 펼친다. 오래된 미확정 기록과 현재 실행 중 상태는 분리하되 보호 확인 책임과 기록은 보존한다. ‘기록 확인’만 반복하고 현재 차단 이유를 숨기는 문구는 쓰지 않는다.

품목 교체 패널은 바깥 클릭/Escape/닫기로 취소하고 포커스를 원래 버튼으로 돌린다. 모달이면 배경 스크롤/포커스 이탈을 막는다. Enter가 준비·실행·수령의 의도치 않은 제출로 전파되지 않게 한다.

## 조회와 컴포넌트 경계

- `DesktopErgon`: 기존 선택/임시계획/실행·수령 lifecycle 조정만 유지한다. 중복 드롭다운 제거, 새 목록 선택을 같은 rootPlan 경로에 연결한다.
- `DesktopErgonQueue`: 행 편집/선택을 기본 노출할 수 있게 분리하고 통합 부족분은 선택적인 접힌 상세로 재사용한다. 참고표 조회32개 한도와 직렬화/문맥 취소를 유지한다.
- 새 목록 행/품목 선택/즐겨찾기 모듈은 단일 책임으로 분리한다. 즐겨찾기와 순수 편집 검증은 native 소비 API를 갖지 않는다.
- `DesktopErgonWorkbench`: 현황/재료 표시를 유지·압축한다. 소비는 기존 `DesktopErgonExecution`의 준비/동의/중지 경로와 `DesktopErgon`의 원클릭 수령 조정 경로만 사용하고, 새 목록/즐겨찾기 모듈에 native 소비 경로를 추가하지 않는다.
- `useErgonSession`, `irisErgonPlan`, `irisErgonSupply`, `irisErgonCraftGoal`의 저장/예약/진척 계약을 재사용한다. 필요할 경우 편집 검증만 순수 함수로 추출한다. 기존 계획 schema1은 유지한다.
- 기존 idle15초 직렬 조회/숨김·준비·실행 pause/복귀·종료 즉시 갱신과 실행관측2초/신선도15초를 유지한다. 목록 기본 노출로 전체 참고표 재조회 루프나 행별N+1을 만들지 않는다. 선택 변경은 현재 분류·재료 조회만 합쳐 수행하고 즐겨찾기 조작은 게임 조회를 발생시키지 않는다.

## 검증과 적용

1. 순수 검증: draft/범위/교체 중복/다른 identity 진척 미사용/즐겨찾기 손상·계정 분리·저장 실패를 RED→GREEN으로 시험.
2. 실제 React 합성: 기본 목록 편집/선택·교체·제거/메뉴 왕복/원래목표 유지/창고 조건부·중복예약/조회 중복 방지/실행 중 편집 차단/늦은 응답을 확인. 기존 collection·queue·guided·수량·craft-goal 회귀 유지.
3. 타입·관련lint·Node 전체·격리 웹 build. native 제품변경이 없으면 기존 계약 smoke를 위험도에 맞게 확인하고 새 게임 성공으로 표현하지 않는다.
4. 네 폭/글자3단계/긴 이름·큰 값·0·미확인·느린 조회·키보드/포커스/테마/가로 넘침을 눈으로 확인한다. 사용자에게 에르곤→작업대 경로와 확인할 변화2~3개만 안내한다.
5. 실제 게임 행동은 매번 직전 질문→품목/비용/횟수 승인→1회 실행→결과 질문. 이번 설계 또는 UI 테스트를 행동 승인으로 사용하지 않는다. 현재 앱의 정상 종료·재시작도 사용자와 순서대로 확인하고 강제 종료하지 않는다.

5시간 사용량15% 잔여 시 새 구현을 중단하고 검증/안전 인계한다. 운영main·다운로드ZIP·DB·과거unknown 원본은 변경하지 않는다. push는 별도 명시 요청 또는 해당 시점에 유효한 인계 승인 범위를 확인한다. 구현 전 사용자 서면 설계 검토와 실행계획 승인이 필요하다.

## 자체 점검

- 승인된 목록형 방향과 아직 미승인인 상세설계·실행계획을 분리했다.
- 기존 편집/예약/진척을 중복 구현하지 않고, 품목 교체와 새 목표의 경계를 정의했다.
- 가방/창고/가공 등록·완료/예상치를 구분하고 알려지지 않은 비용을 만들지 않았다.
