# IRIS 컴팩트 오버레이·본인 스탯 동기화 설계

- 작성: 2026-10-06, 영겁 / 집 호스트.
- 상태: 2026-10-06 한설이 작성 설계서를 승인했다. 1단계 구현 계획 검토 대기이며 제품 구현 전이다.
- 기반: `2026-10-05-iris-sanctum-desktop-design.md`. 기존 로그인·보호 대기함·숙제 저장을 보존한다.
- 최신 수동 근거: 한설이 화연 로그인·캐릭터 목록·체크한 숙제의 실제 웹 크로노스 반영을 확인했다. 전체 계정 전환/복구/자동저장 시나리오 완료를 뜻하지 않는다.

## 1. 목적과 경계

실사용 센터까지 게임 위에서 작은 창으로 조작한다. 큰 관리 프로그램을 기본으로 두지 않는다. 확인된 게임 스탯의 변경분을 같은 계정의 해당 캐릭터에 저장해 웹 크로노스에서도 사용한다.

기존 미커밋 변경·세션 프로필·미저장 숙제를 보존한다. 운영 DB 구조/RLS/권한 변경, 실제 운영 데이터 검증 쓰기, 게임 명령/조작, 비밀값 추출, OS 설치/자동 시작, commit/push/배포는 포함하지 않는다. 사용자가 본인 체크/스탯 저장을 쓰는 제품 경로와 개발자가 운영 데이터를 임의로 변경하는 작업을 구분한다.

## 2. 접근 선택

권장: 현재 WebView2 로그인·저장 엔진에 네이티브 오버레이 창 정책과 작은 화면을 붙인다. 게임 읽기는 앱 소유의 읽기 전용 경로로 통합한다. UI가 달라져도 인증·저장 주체는 하나다.

큰 창을 단순 항상 위로 만드는 방식은 화면 점유와 불편한 클릭 수를 해결하지 못한다. 구형 오버레이와 신규 앱을 동시에 실행하는 방식은 두 인증/저장 주체와 단축키 경쟁을 만들므로 채택하지 않는다. 구형 코드는 검증 전 삭제하지 않는다.

## 3. 화면·조작

- 하나의 둥근 센터: 좁은 헤더에 IRIS·현재 캐릭터·연결 상태·접기/닫기. 캐릭터 선택은 헤더 바로 아래 한 단계로 제공한다.
- 주 진입점은 숙제·스탯·시낙시스·설정. 한 번에 하나의 내용을 펼치며 별도 거대 계정 관리 창을 기본으로 열지 않는다.
- 숙제 기본은 1열 짧은 행. 체크형은 행/체크박스 클릭으로 변경하고 반복형만 −/현재값/＋를 둔다. 일일·주간·어비스·레이드는 간결한 전환/접기로 제공한다. 완료·남은 항목 필터, 키보드 조작을 유지한다.
- 저장 상태는 캐릭터 이름·변경 수·남은 시간 한 줄, 지금 저장·버리기 제공. 여러 캐릭터는 요약 후 펼쳐 확인한다. 충돌/불명확/실패는 숨기지 않고 항목명과 복구 동작을 표시한다. 내부 숫자 ID를 닉네임 대신 노출하지 않는다.
- 로그인/계정 전환/로그아웃/테마/투명도는 센터 안의 작은 패널. 바깥 클릭·Escape·초점 복귀를 제공한다. 대기 저장이 계정 전환으로 섞이지 않도록 기존 잠금을 유지한다.
- 6테마·rem 글자 설정·12자 전체 닉네임·스크롤/접힘/포커스 보존. 네이티브 폭은 320~480px 후보로 시작하며 높이는 작업 영역 안에서 제한한다. 화면 크기는 수동 검증 후 조정할 수 있다.
- 시낙시스 탭은 기존 연결 계약을 확인해 상태를 표시하는 범위다. 현재 미지원 기능을 정상 데이터/활성 버튼으로 꾸미지 않는다. 파티 신청·운영/자동 게임 작업은 이 단계의 신규 범위가 아니다.

## 4. 네이티브 오버레이

- 창 테두리/큰 제목 막대를 축소하고 드래그·크기 조절·항상 위 표시·표시/숨김·클릭 통과를 제공한다. 로그인 입력/편집 때만 정상 입력 초점을 받도록 한다.
- Ctrl+Alt+I 표시/숨김, Ctrl+Alt+O 클릭 통과를 기존 의미로 유지한다. 두 단축키 확보 실패 시 클릭 통과는 꺼짐/사용 불가로 두며 트레이에서 반드시 조작 상태로 복구할 수 있다. 핸들 재생성·종료 시 등록을 해제한다.
- WebView2 자식 창까지 클릭이 실제 게임으로 통과하는지 네이티브 합성 입력 대상으로 먼저 확인한다. 부모 창 스타일만 바꾼 상태를 통과 완료라고 보고하지 않는다.
- 투명도·둥근 외곽과 WebView2 렌더링 조합을 기술 검증한다. 초기 목표는 읽기 쉬운 패널과 창 투명도이며 픽셀별 투명/둥근 외곽 지원을 확인 없이 보장하지 않는다.
- 작업 영역 밖 위치·DPI·다중 모니터 복구, 트레이 복원, 보호된 종료 처리를 유지한다. 독점 전체 화면 위 표시를 보장하지 않으며 게임 창/테두리 없는 창 위 실검증을 별도로 남긴다.
- 프로세스·보호 대기함·단축키 소유자는 하나. 기존 실행기의 공유 잠금을 유지하고 신규 실행기를 기본으로 전환하는 것은 사용자 수동 확인 뒤다.

## 5. 게임 읽기·캐릭터 연결

현재 `iris/reader.mjs`는 전투력·생활력·매력·마도저항의 읽기 필드를 정규화한다. 현재 공개 snapshot에는 검증된 게임 닉네임/캐릭터 식별자가 없으며 길드공헌도도 없다. 전체 계정 캐릭터 조회 지원 역시 확인되지 않았다.

먼저 공식 읽기 응답/지원 계약을 조사한다. 자동 식별은 안정적인 캐릭터 식별자 또는 실제 닉네임이 확인되는 경우에만 사용한다. 문자열 필드 이름을 추측하거나 같은 클래스/레벨을 근거로 자동 매칭하지 않는다.

기본 쓰기 조건은 로그인 계정의 본인 소유 캐릭터와 검증된 게임 식별의 일치다. 자동 식별을 제공하지 않으면 스탯 저장은 비활성으로 남긴다. 수동 연결을 대안으로 사용하려면 별도 설계 승인이 필요하며 기존 숙제 선택만으로 연결을 승인한 것으로 간주하지 않는다.

게임 연결 끊김/재연결·게임 식별 변경·로그아웃·앱 재실행에는 연결 epoch를 갱신한다. 읽기 시작 당시 식별/epoch와 응답 후 식별을 비교해 중간 캐릭터 변경의 응답을 버린다. 늦은 응답을 새 선택 캐릭터에 적용하지 않는다. 웹 숙제 선택이 게임 캐릭터 선택을 뜻하지 않으며 두 상태를 화면에서 구분한다.

길드공헌도는 공식 응답에서 정확한 의미/단위를 확인한 뒤 활성화한다. 미지원이면 기존 DB 값을 유지하고 미지원으로 표시한다. 데코점수·재화 등 다른 숫자로 대체하지 않는다. 다른 캐릭터 일괄 조회를 지원하지 않으면 플레이하며 정상 읽은 본인 캐릭터만 각각 갱신한다.

## 6. 저장 흐름·요청량

- 숙제 편집은 즉시 화면 반영, 마지막 사용자 조작/캐릭터 떠남 후15초, 지금 저장 유지. 캐릭터 A의 대기는 B 조작으로 계속 미뤄지지 않는다.
- 스탯은 게임 연결 식별이 확인된 새 응답만 받는다. 누락/오류/빈 값은 변경으로 기록하지 않으며 기존 값에0/null을 쓰지 않는다. 명시적인 유효한0과 읽기 실패를 구분한다. 수치 감소도 정상 값이면 변경 대상으로 보며 무조건 최고값으로 바꾸지 않는다.
- 정상 읽기의 변경 스탯만 캐릭터별 대기에 합친다. 지속적인 읽기 자체가 숙제15초 타이머를 초기화하지 않는다. 스탯만 바뀐 경우 최초 변경 후15초에 저장하고 그동안 최신 검증값으로 합친다. 원래 값 복귀 시 불필요한 쓰기를 제거한다.
- 지금 저장은 해당 캐릭터의 숙제와 검증된 스탯을 처리한다. 숙제 저장과 스탯 저장은 별도 결과를 가지며 한쪽 실패를 전체 성공으로 표시하지 않는다. 무변경이면 스탯 쓰기0건.
- 게임 읽기는 초기 연결/명시 갱신과 표시 중 최대30초마다1회로 제한한다. 단일 in-flight, 숨김 때 주기 읽기 중단, 복귀 때 제한적 갱신. 미연결 캐릭터/전체 계정 무한 조회를 하지 않는다. 실제 CLI/요청 지연·이그레스는 검증값으로 보고한다.
- 대기 스탯은 계정·캐릭터·원래 DB 기준값·최신 희망값·게임 관측 시각/연결 식별에 귀속한다. 원래 캐릭터의 유효한 관측은 다른 숙제 캐릭터를 선택해도 해당 원래 캐릭터로만 저장한다. 계정이 바뀌면 이전 대기는 보류하며 새 인증으로 보내지 않는다.
- 재실행/응답 유실은 최신 DB 값으로 확인한 뒤 명시 복구한다. 오래된 스탯을 자동 재생하지 않고 게임 재확인 없이 다시 쓰지 않는다. 보류 항목·복구 실패를 보인다.
- 스탯 대기는 기존 숙제 schema1의 허용 항목에 끼워 넣지 않는다. 버전 있는 보호 저장 계약으로 확장하고 schema1 호환 읽기/이관·원자 교체·손상 파일 보존 테스트를 선행한다. 대기함을 빈 파일로 초기화하지 않는다.

## 7. 인증·서버 갱신

서버는 기존 HttpOnly 계정 세션으로 소유권을 다시 검사한다. 클라이언트의 게임 식별 주장은 서버 인증이 아니며 타인 캐릭터 쓰기를 허용하지 않는다. 기존 운영진용 일괄 동기화 API를 일반 사용자의 우회 쓰기 경로로 쓰지 않는다.

기존 확인된 `characters` 컬럼에만 본인 스탯의 변경 필드를 갱신한다. 전투력/생활력/매력/마도저항/길드공헌도 외 숙제·직업·클래스 레벨·다른 필드와 다른 캐릭터는 수정하지 않는다. 요청 필드 허용 목록·크기·숫자 범위·관측 시간·소유권·현재값 조건부 갱신을 검증한다. 값 범위/컬럼 매핑은 구현 계획 전 기존 스키마와 공식 계약을 확인해 고정한다.

웹 동시 수정은 원래 읽은 DB 기준값과 비교해 충돌로 돌려주며 강제 덮어쓰지 않는다. GET 확인→조건부 갱신 중 경합도 차단한다. 멱등/불명확 응답은 최신값 확인으로 처리하고 blind POST retry는 금지한다. 성공 확인 전 최신 업데이트 표시를 올리지 않는다.

스탯은 숙제 초기화 대상이 아니다. 숙제의 KST06시/월요일06시 기간 검사는 그대로 유지한다. 스탯의 웹 최신 업데이트·로그/통계 연동 방식은 기존 화면/서버 규약을 조사해 필요한 기존 동작만 보존하며 운영 전체 동기화/랭킹 배치를 임의로 실행하지 않는다. DB 구조 확장이 필요하면 이 설계만으로 진행하지 않고 대상/복구 방법을 설명해 별도 승인받는다.

## 8. 구현 순서와 완료 조건

1. 현재 로그인/숙제 저장 엔진의 컴팩트 화면과 저장 요약. 합성 응답만으로6테마·320/390/768/1280px·글자3단계·동일 DOM/포커스/스크롤/접힘 검증.
2. 네이티브 항상 위·드래그·단축키·실제 클릭 통과·복구·단일 실행 검증. 사용자 게임 위 확인 전 일반 창이 오버레이 완료가 됐다고 보고하지 않는다.
3. 읽기 계약·캐릭터 식별·필드 지원 여부 확인. 미지원은 비활성 유지. 식별 없는 데이터/연결 epoch 경합/오래된 응답이 저장되지 않는 테스트.
4. 보호 대기/본인 스탯 조건부 저장의 합성 테스트: 변경0쓰기, 누락 보존,0/감소, 타인 거절, 계정 전환, 웹 충돌, 게임 캐릭터 전환, 종료/재실행/응답 유실, 숙제와 부분 성공, 과대/잘못된 값 차단.
5. 한설이 실제 로그인·게임 위 조작·15초 저장·웹 반영·단축키/복구를 한 단계씩 확인. 개발자 임의 운영 데이터 쓰기/게임 조작 없이 검증한다.

이 설계서는 구현 완료 보고가 아니다. 사용자 승인 뒤 현재 폴더에서 1단계 컴팩트 HUD/네이티브 후보를 구현·자동 검증 중이며 실제 게임/DPI 승인은 남았다. 스탯 계약 조사는 docs/IRIS_STATS_CONTRACT.md에 기록했고 검증된 게임 신원이 없어 자동 스탯 쓰기는 비활성이다. Git 커밋·푸시는 별도 요청 전 실행하지 않는다.
