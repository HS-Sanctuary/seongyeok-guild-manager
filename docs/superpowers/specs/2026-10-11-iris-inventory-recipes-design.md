# IRIS 재고·레시피 계산 — 보관용 설계안

상태: 2026-10-11 검토안. 참조 ID: R07–R13, L05, L07. 읽기 HUD 안정화 다음 후보이며 게임 실행 승인 아님.

## 목표와 단위

보유 재료와 부족분을 이해하도록 재고 조회 → 단일 레시피 계산 → 선행 재료 체인 미리보기 → 메모/백업 순으로 나눈다. 처음부터 전체 게임 레시피 사전이나 자동 제작을 약속하지 않는다. 각 단위는 독립 시험 가능한 화면과 계산기를 갖는다.

## 조회·계산

- 재고는 공식 조회가 실제 제공하는 가방/계정창고/캐릭터창고 위치를 분리한다. 잠긴 수량·사용 가능한 수량·범위 미지원·관측 시각을 보존한다. 같은 항목의 서로 다른 위치를 임의로 자동 합산해 즉시 제작 가능으로 표시하지 않는다.
- R08 기존 재화 표시를 유지한다. 고정/정렬은 로컬 표시 설정이며 새 재화 DB 이력이나 자동 스탯 저장은 없다.
- 레시피는 경로/결과물/재료/산출량/잠금·해금/확인 출처·버전·불완전 여부를 구분한다. 동명은 표시 이름이 아니라 확인된 실행/조회 키로 구분한다.
- 계산은 목표 산출량과 확인된 산출량으로 필요한 제작 횟수를 올림 계산한다. 재고 최대량/부족분/시설 상한/재료 이송 가능성은 각각 표시하고 미확인 조건을 가능 판정으로 숨기지 않는다.
- R12 관찰·기여 자료의 충돌과 출처를 유지한다. 여러 출처가 일치해도 전체 레시피 완전성을 주장하지 않는다.
- R13 체인은 읽기 미리보기만 한다. 초기 제안은 깊이 8/노드 200 상한, 순환 탐지, 같은 재료 합산, 미해결 경로 표시다. 중간 산출을 중복 재고로 세지 않는다. 실제 큐에 자동 등록하지 않는다.

## 자료·설정·백업

공식 CLI와 IRIS 자체 관찰을 우선하며 타 앱의 레시피 JSON/이미지/EXE를 복사하지 않는다. 외부 기여 자료는 권리/출처/갱신일 확인 전 제외한다. 로컬 캐시는 계정별 분리·만료하며 로그에 전체 재고나 개인 경로를 무분별하게 남기지 않는다.

L05 메모/프리셋은 같은 계정 범위의 목적별 표시/목표 설정이다. L07 내보내기는 인증·닉네임·개인 경로·보호 큐 원문을 제외한 버전 명시 JSON이다. 가져오기는 크기/버전/항목 allowlist를 검사하고 미리보기·기존 값 보관·명시 확인 후 반영한다. 내보낸 보호 기록을 다른 계정에 복원하는 기능은 제공하지 않는다.

## 검증·영향·되돌리기

순수 계산기에서 0/소수·부족·산출량 누락·중복 위치·잠금·동명·순환·상한·반올림을 먼저 테스트한다. 명시된 위치/권리/필드 계약 없이는 ‘가능’ 배지를 내지 않는다. UI는 출처·stale·부분 자료를 읽을 수 있어야 한다.

native는 고정 재고/레시피 읽기 후보, UI는 재고/계산 모듈, cache는 별도 로컬 파일을 검토한다. DB·게임 행동·현재 보호 큐 형식은 변경하지 않는다. 캐시를 폐기하거나 모듈을 끄면 기존 기능으로 복귀 가능해야 한다.
