# ERGON 원클릭 수령·과거 작업 자동 정리 설계

작성: 영겁 / 2026-10-15 KST / 상태: 한설 서면 설계·구현 계획 승인, 로컬 구현·합성 검증 후 정상 재시작/실게임 확인 대기

## 1. 사용자 의도와 완료 기준

한설은 사용자가 기록을 찾아 잠금을 해제하거나 준비·확인을 반복하지 않고, 시설의 수령 버튼 한 번으로 게임 속 해당 시설로 이동해 완료품을 받기를 원한다. 에르곤은 기본적으로 자동 점검·진행·결과 갱신을 담당하고 실제 예외만 사용자에게 알려야 한다.

이번 범위는 **수령 한 번의 원클릭 처리와 과거 실행 잠금의 자동 판정**이다. 이후 부족 재료 확보→가공→수령→제작의 자동 연결을 발전시키기 위한 기준이지만, 이번에 무제한 채집·제작/시설 순회·재등록/자동 반복을 허용하거나 구현하지 않는다.

완료 기준:

- 최초 원클릭 수령 허용 뒤에는 매 수령마다 기록 확인·준비·최종 확인을 요구하지 않는다.
- 시설 버튼 한 번은 해당 시설의 완료품 전체를 수령하는 새 요청 한 번이다. 다른 시설이나 과거 명령을 자동 실행하지 않는다.
- 현재 실행과 관계없다고 판단할 근거가 갖춰진 과거 unknown만 실행 차단에서 자동 분리한다. 원래 결과는 여전히 unknown이다.
- 진행 중·상태 불명·연결 끊김·과적·문맥 변경이면 명령을 보내지 않고 한 줄로 이유를 보여준다.
- 이동·수령 중 창이 숨겨져도 요청 ID별 관측과 잠금이 유지되며, 종료 뒤 현황이 자동 갱신된다.

## 2. 확인된 현재 구조

- `complete_altering_work`는 이동만 하는 명령이 아니라 **시설 이동+그 시설의 완료품 전체 수령+보상 처리**다. 설치본 근거는 `docs/IRIS_COLLECTION_COMMAND_TRACE_20261015.md`에 남겼다.
- native `DesktopLifeJournal.HasUnresolved`와 `Begin`은 development/production의 unknown/inflight를 전역 차단한다. UI 버튼만 바꿔서는 풀리지 않는다.
- 집에서 읽기 전용으로 확인한 차단 건은 development의 2026-10-13 통나무 gathering unknown 1건이다. 원본·계정·캐릭터 식별자·복호화 원문을 Git에 넣지 않는다.
- 현재 native는 모든 confirm에 매번 동의창을 띄운다. 이를 프런트엔드에서 무시하거나 confirm 함수를 무조건 true로 바꾸면 안 된다.
- 현재 CLI 상태 정보만으로 과거 산출량·날개 소모·성공 여부를 복원할 수는 없다. 지금 idle이라는 이유로 과거 작업을 completed로 바꾸지 않는다.

## 3. 대안과 선택

| 대안 | 판단 |
| --- | --- |
| unknown을 삭제하거나 오래됐다는 이유로 무시 | 제외. 과거 증거와 진행 중 보호를 잃는다. |
| 매번 사용자에게 원장 확인·종료 확인 요구 | 제외. 이번 사용자 의도와 맞지 않는다. |
| 원본 결과와 현재 실행 차단을 분리하고 native가 조건부 자동 판정 | 권장. 원본 보존·중복 방지와 원클릭 UX를 함께 달성한다. |

이번 변경은 native 정책·암호화 저장·bridge·UI 계약에 걸친 구조 변경이다. 한설이 서면 설계와 구현 계획을 모두 승인하고 직접 구현·검증을 선택했다. 실제 보호 해제·게임 행동은 사용자의 첫 native 허용과 시설 클릭 전에는 실행하지 않는다.

## 4. 원클릭 수령 허용

### 최초 1회만 native에서 범위 안내

허용되지 않은 PC/생텀 계정/환경에서는 첫 수령 클릭 때 native가 한 번만 다음 범위를 안내한다. 사용자가 허용하면 같은 요청의 자동 점검을 이어간다. 취소하면 아무 게임 명령도 보내지 않는다.

- 이후 시설 수령 버튼 클릭은 게임에 현재 접속한 캐릭터의 해당 시설 이동·완료품 전체 수령 요청이다.
- 수령 비용이 아직 실측되지 않았다는 사실을 안내한다. 타앱 설명만 보고 0개로 확정하지 않는다.
- SANCTUM에서 선택한 캐릭터는 앱 문맥이다. 공식 조회로 게임 캐릭터의 동일성을 보장할 수 없는 경우 두 신원이 일치한다고 표시하지 않는다.
- 채집·가공 등록·제작·재등록·자동 반복은 이 권한에 포함되지 않는다.
- 외부 자동화 앱과 동시에 명령을 보내지 않도록 안내한다. 타앱은 IRIS의 실행 잠금을 공유하지 않을 수 있다.

허용은 사용자별 DPAPI 보호 설정으로 저장하고 설정에서 해제할 수 있다. 계정/환경/정책 버전이 다르거나 저장이 손상되면 재사용하지 않는다. 웹 콘텐츠가 전달한 boolean만으로 허용 상태를 켤 수 없으며 최초 허용·철회는 native가 통제한다. 단순 앱 재시작마다 같은 동의를 반복하지 않는다.

기존 채집·제작의 native 최종 확인은 이번에 변경하지 않는다. 구형 앱은 새 정책 capability가 없으면 업데이트 필요를 안내하고 조용히 원클릭을 가장하지 않는다.

## 5. 과거 unknown의 자동 차단 분리

### 결과 보존과 차단 분리는 서로 다른 사실

원본 `ergon-actions-v1.dpapi`의 과거 unknown을 성공/거절/삭제로 고치지 않는다. 별도 DPAPI 정리 이력에 원본 요청 ID·환경·원본 레코드 해시·판정 시각·정책 버전·판정 근거를 추가한다. 의미는 **“과거 성과는 미확인, 현재 진행 작업은 아님”**이며 수량·날개·제작 목표 성과에는 반영하지 않는다.

정리 이력이 없거나 손상됐거나 원본 해시가 다르면 기존 차단을 유지한다. 구형 native는 이 정리 이력을 몰라도 원본 unknown을 읽고 보수적으로 차단하므로, 롤백이 기존 안전장치를 약화하지 않는다. 첫 정리 이력 저장 전 원본 암호화 파일을 private 위치에 복사 보관한다. 실제 백업·원장·설정은 Git/채팅에 포함하지 않는다.

### 자동 분리에 필요한 조건 — 모두 만족

1. 현재 native 실행 task/confirm/stop 요청이 없고, 프로세스 간 실행 lease를 독점 획득한다. 살아 있는 다른 IRIS 실행이 있으면 분리하지 않는다.
2. 대상은 이전 실행 문맥의 unknown이다. legacy 기록도 startedAt이 현재 native 세션 시작 전이고 현재 추적 중인 요청 ID와 달라야 한다. inflight나 현재 세션에서 생성된 unknown은 자동 분리하지 않는다. 기존 startup의 interrupted 복구는 별도 사실이며 성공을 뜻하지 않는다.
3. 최소 경과 시간은 12분이다. 현재 CLI 응답 대기 상한 10분과 준비 유효기간 2분보다 짧게 잡지 않는다. **경과 시간만으로는 절대 해제하지 않는다.**
4. 공식 CLI의 미완료 실행 프로세스/현재 실행 요청이 없음을 확인한다. IRIS 자체 읽기 작업은 먼저 완료시킨다. 프로세스 역할을 구분할 수 없으면 자동 분리하지 않는다. 프로세스 종료·게임 메모리 접근·게임 파일 수정은 하지 않는다.
5. 연결된 같은 게임 프로세스/앱 문맥에서 새 activity를 두 번 읽는다. 간격은 최소 1초이며 각 응답은 15초 미만의 신선한 값이어야 한다. 둘 다 기존 native SafeActivity의 idle 조건(이동·전투·채집·연주·대화 등 안전 플래그 포함)을 만족해야 한다.
6. 계정/환경/선택 문맥·native 문서 epoch·대상 원본 해시가 점검 전후 동일해야 한다. 조회 실패·게임 재시작·캐릭터/문맥 변경이면 중단한다.
7. 실행 lease를 유지한 채 원본과 정리 이력을 다시 확인하고 정리 이력을 원자적으로 저장한다. 같은 원본에 중복 정리 이력을 만들지 않는다.

두 번의 idle 조회만으로 모든 외부 도구의 미래 명령을 증명할 수는 없다. 따라서 위 조건은 실행 소유권·남은 CLI·시간·신선한 게임 상태를 함께 보는 운용 기준이다. 근거가 모자라는 경우에는 짧은 예외 안내를 남기며 성공으로 추정하지 않는다.

development/production에서 차단에 참여하는 원장 모두 같은 규칙을 적용한다. 다른 계정의 기록 내용은 UI에 노출하지 않는다. 현재 실행 잠금과 새 요청의 안전 점검은 과거 기록 분리 뒤에도 항상 유지한다.

## 6. 한 번의 클릭 처리

1. UI는 시설/완료품 anchor/현재 문맥과 클릭 요청 ID를 고정하고 해당 버튼에 `확인 중`을 표시한다. 연타·다른 작업 추가를 잠시 막는다.
2. native는 좁게 정의된 새 원클릭 collection 요청을 받는다. 최초 허용이 필요하면 위 안내 한 번만 수행한다.
3. 먼저 읽기 작업의 종료를 최대 10초 기다리고 실행 lease를 획득한다. 10초 안에 종료하지 않으면 소비 명령 없이 중단한다. 클릭 요청의 유효기간은 2분이며 최초 허용창에서 오래 머물러도 연장하지 않는다. 사용자 이탈/문맥 변경/요청 만료 시 실행 전 취소한다. 소비 명령을 보내서 상태를 시험하지 않는다.
4. 차단 원인이 과거 기록뿐이면 5절의 자동 판정을 한다. 현재 작업 진행/연결 불명은 종료시키거나 우회하지 않는다.
5. 새로운 가공 현황·가방·재화·activity를 점검한다. 해당 시설의 완료품을 고유하게 가리키는 anchor가 있고, 준비·커밋 전후 시설/품목/문맥이 동일할 때만 실행한다.
6. native가 새 요청을 먼저 원장에 기록하고, `complete_altering_work`를 한 번 보낸다. 클릭 요청 ID를 중복 수신해도 두 번째 실행하지 않는다.
7. 화면은 `이동·수령 중`을 표시한다. 이는 요청 진행 표시이며 실제 이동 관측과 혼동하지 않는다. 숨김 중에도 같은 요청 ID의 결과를 관측한다.
8. 응답과 가공 완료 목록 감소를 함께 확인한다. 완료가 검증되면 `수령 완료`와 현황을 자동 갱신한다. 중단·연결 손실·회수0·판정 불가면 새 unknown을 남기고 자동 재시도하지 않는다.

과거 자동 정리는 원클릭 요청의 준비 과정에서만 수행한다. 화면 열기·상태 폴링·앱 시작만으로 수령을 시작하지 않는다. 앱 재시작 뒤 대기 중이던 클릭을 자동 재개하지 않는다.

## 7. 화면과 예외

- 정상: `수령 →` 한 번 → `확인 중` → `이동·수령 중` → `수령 완료`. 허용된 사용자는 추가 모달이 없다.
- 자동 정리된 과거 건은 접힌 기록에 `과거 결과 미확인 · 실행 종료 확인`으로 표시한다. 일반 수령 화면을 오래된 경고로 채우지 않는다.
- 진행 중: `다른 생활 작업이 진행 중이에요.` 연결 불명: `게임 연결을 확인해 주세요.` 과적: `가방 공간이 부족해요.` 안전 판정 불가: `이전 작업 종료를 확인하지 못했어요.`
- 일시적인 읽기 작업 충돌은 짧게 기다려 처리하되 소비 명령을 재전송하지 않는다. 회복된 조회 오류 문구는 지우고, 실제 남은 원인만 보여준다.
- 실제 판정 불가일 때만 접힌 상세/기록 접근을 제공한다. 사용자가 원장 파일이나 식별자를 다룰 필요는 없다.

## 8. 변경 범위·검증·복구

예상 변경 영역은 native 정책/실행기·저장소·bridge·동의 설정, TS store/응답 검증, ERGON 클릭/상태 표시와 관련 fixture다. 임의 셸/CLI 명령·경로를 bridge에 노출하지 않는다. 운영 DB·웹 권한·배포·공개 ZIP·무제한 자동화는 범위 밖이다.

구현 전에 새 정책의 실패 재현 시험을 먼저 작성한다. 필수 검증은 오래된 unknown/현재 inflight/살아 있는 sibling·orphan CLI/상태 신선도·문맥 변경/정리 이력 손상·원본 변경/동시 요청/복구 중 crash/구형 원장 보존/허용 범위·철회/최초 동의 취소/연타·재시작/이동 뒤 결과 불명/숨김 관측/조회 오류 회복이다. 실제 파일의 구조를 닮은 합성 자료를 사용하고 실제 개인 원장으로 회귀 시험하지 않는다.

전체 관련 자동시험·타입·lint·격리 웹 빌드·private native compile 뒤 사용자가 native를 정상 재시작한다. 실게임 시험은 시설 하나와 해당 시설의 완료품 전체라는 범위를 사용자에게 보여주고 확인하며, 시험 전후 완료 건수·가방·날개를 비교한다. 합성 검증과 실제 게임 성공을 구분한다.

문제가 생기면 새 원클릭 허용을 끄고 기존 보수적인 실행 경로로 돌아간다. 원본 원장과 private 백업을 보존한다. 정리 이력·허용 설정을 임의 삭제해 되돌리지 않고 비활성화 정책으로 차단을 복구한다. 공식 push는 별도 요청이 있을 때만 한다.

## 9. 이번 문서의 승인 경계

- 승인받은 방향: 자동 점검·원클릭 수령, 원본을 보존하는 과거 실행 차단 자동 정리, 예외만 사용자에게 알림.
- 이번 턴 승인: 이 서면 설계의 최초 1회 native 허용, 자동 정리의 복합 조건/12분 하한, 수령 이외 동작은 기존 권한 유지. 한설은 이번 작업의 사용량15% 자동 중단 약속도 철회했다.
- 로컬 구현/합성 검증은 진행했다. 아직 실행하지 않은 것: 실제 원장 정리/잠금 해제, 수령 권한 설정, 게임 이동·수령, push/운영 배포. 실제 후보 재시작·사용자 검증은 별도다.
