# ERGON 2차 B-2 연결 후보 검증 — 2026-10-23

## 선별 전송 승인 및 마감 재검증

한설이 비활성 조건의 B-2 후보를 인정하고 제품10·시험9 및 최소 한국어 인계의 기능 브랜치 선별 commit·일반 push를 승인했다. 새 제품 기능·main 병합·운영 배포·실게임·잠금 해제는 승인하지 않았다. 아래 구현 완료 당시의 commit/push 금지·미전송 기록은 당시 경과로 보존하며 이번 승인 범위만 대체한다. 전송 성공·최종 SHA는 실제 일반 push 후 원격 HEAD 대조 결과로 판단한다.

전송 직전 19개 소스 SHA256이 구현 검증 기준과 모두 일치했다. 개인16항목과 이전 worktree 별도 ACK의 상태/해시는 이번 전송 작업 시작·종료를 비교한다. 이는 아래에 명시한 더 이전 구현 전체 기간의 해시 증명 한계를 소급 해소한 것은 아니다. 로컬 전용 로그/해시 기준표/합성 자료는 전송하지 않는다. 최신 원격은 기능 b3e243c/main b0b63c7이며 ff-only pull 최신을 확인했다.

정상 호스트는 DesktopBridge(store, development)를 사용하며 합성 시험 전용 enableErgonForLocalTesting=true를 전달하지 않는다. progress API와 prepare/confirm/collect는 비활성 gate에서 거절된다. capability=false가 단독 보안 장치인 것은 아니며, 실제 차단은 native bridge와 고정 호스트 생성 경로에서 적용한다. 기존 stop 경로는 현재 동작을 멈추는 보호 기능이며 새 채집/가공/제작/수령을 시작하는 API가 아니다.

전송 직전 재검증: `node --test tests/*.test.mjs`는 641개 중638 PASS/기존3 SKIP/FAIL0, 기존 저장34·A22·B-1 20·H22·R5 유지다. native8·TypeScript·scoped ESLint·실제 native 소스 목록 컴파일도 종료 코드0이다. 로그는 로컬에만 보존한다.

추가 로컬 잠금 점검은 기본 development/production bridge의 progress 8종·prepare/confirm/collect 3종, 총22요청을 모두 거절하고 native callback 0회를 확인했다. 실제 CLI·네트워크·사용자 저장 접근은 없다. 이 점검 스크립트의 최초 Add-Type 익명 타입 이름 충돌은 불필요한 익명 DTO를 제거해 해결했으며 제품/전송 시험 코드는 변경하지 않았다. 원본 오류 로그는 로컬에 보존한다.

선별 커밋 전 보존 대조: 사무실 원본16항목 및 이전 worktree ACK 1항목의 파일 상태·SHA256·각 HEAD가 이번 전송 작업 시작 기준과 동일하다. staged 대상은 제품10·시험9·문서6의 25파일이며 비밀값 패턴·개인 경로·로그·원장·공개 ZIP/metadata 포함 후보0이다. 검증 소스19파일은 변경하지 않았다. 일반 push 후에도 원본 보존과 로컬/원격 SHA를 다시 확인한다.

## 실제 연결한 내용

1. `DesktopLifeProgressConnection`이 기존 `ProgressCoordinator`와 실제 `DesktopLifeExecutor`를 연결한다. 저장 목표 없는 소비 Prepare와 바인딩 없는 구 Confirm은 거절한다. 전체 동결 intent 지문, 계정·캐릭터·epoch·문맥·revision·nonce를 재검증한다.
2. 잠금 순서는 actor mutation → game lease → 공통 writer → 짧은 Store 파일 잠금이다. 모든 직접 Commit도 기존 공통 writer 제외 규칙을 따른다. 승인 대기 중 writer와 Store 파일 잠금은 보유하지 않는다.
3. 승인 대기 역시 Busy로 노출하여 기존 종료·업데이트 보호가 적용되게 했다. WinForms owner 파괴 시 승인은 거절로 끝나며, 소유한 비동기 경로는 UI 동기화 문맥에 의존하지 않고 정리한다.
4. Claim한 실행 lease는 실제 Run의 terminal 관측/저장 시도까지 유지한다. 최종 admission writer 해제 후에만 Run이 시작되는 barrier로 빠른 terminal 저장 경합을 막는다. 불명확한 실행은 자동 재전송하지 않는다.
5. 기존 journal의 실제 행만 terminal 근거로 사용한다. 완료 명령과 생산 수량을 구분하며 예상량은 확인 수량에 가산하지 않는다. unknown·inflight·행 누락·소유/품목/횟수 불일치·진행 저장 실패이면 추가 소비/확인을 차단하고 과거 이력을 보존한다.
6. journal.Begin의 기존 30일/300건 정리 후에도 참조 행을 다시 대조하고, 누락되었으면 Dispatch 전에 차단한다. journal 형식·정리 정책을 바꾼 것은 아니다. 이때 생성된 inflight는 임의 성공/삭제하지 않는다.
7. 수령은 목표 바인딩과 별도 기능으로 유지하되, 구 Confirm 수령과 CollectOneClickAsync 모두 진행-원장 불일치 검사를 통과해야 한다. 진행 기록에 참조된 unresolved를 수령의 기존 분리 절차로 우회하지 못한다. 참조되지 않은 기존 수령 정책은 보존한다.
8. bridge는 고정 allowlist·strict payload·origin·epoch 보호를 유지한다. 경로·종료 증거·임의 snapshot 입력 API는 없다. TypeScript는 strict scoped load만 연결하며 쓰기 UI나 자동 실행 루프는 추가하지 않았다.

## 구현 완료 당시 보존 및 종료 상태 (선별 전송 승인 전 경과)
