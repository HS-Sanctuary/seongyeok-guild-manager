## VS Code에서 받기

집 경로에서 먼저 확인한다. 파일 목록이 있으면 여기서 멈추고 영겁에게 변경 보존을 맡긴다. 오류가 나면 다음 줄을 실행하지 않는다.

```powershell
Set-Location 'C:\Users\Moon\seongyeok-guild-manager'
git status --short
```

깨끗한 상태 또는 영겁이 보존을 마친 뒤 한 줄씩 실행한다.

```powershell
git fetch origin
git switch codex/iris-checkboard-classes
git pull --ff-only origin codex/iris-checkboard-classes
git log -2 --oneline
```

정확한 최종 SHA는 순월의 마지막 전달 및 수신함 후속 마감과 비교한다. main만 pull하면 이번 후보가 없다. reset/clean/강제덮어쓰기/임의 stash 금지.

## REA와 후보 앱 열기

- REA는 `docs/REA_SETUP.md`의 현재 설치/Node 확인→Codex 범위 미리보기→MCP+공식 스킬 설치→doctor→Codex 정상 재시작 순서다. 사무실 캐시·개인 설정은 Git으로 전달되지 않는다. 정상 연결을 확인한 뒤 재설치를 반복하지 않는다.
- 코드 후보는 운영에 배포하지 않았다. 기존 공개 IRIS.exe는 운영 UI이므로 새 큐가 보이지 않는 것이 정상이다. 영겁이 로컬 서버를 확인하고 `npm run dev` 후 `http://localhost:3000/iris/desktop` 응답을 먼저 점검한다.
- native 후보는 사용자의 기존 IRIS 정상 종료를 확인하고 아래 Development 모드로 연다. 켜진 앱을 임의 forcekill하지 않는다. 정상 종료가 막히면 미저장 변경을 보존하는 안내를 먼저 한다.

```powershell
powershell.exe -NoProfile -STA -File iris/desktop.ps1 -Development
```

게임/보호원장/참고재료파일은 집 PC의 로컬 자료다. 사무실 private패키지·PID·캐시·DPAPI 상태가 Git으로 전달된다고 가정하지 않는다.

## 확인할 화면

1. ERGON → 작업 계획 → 품목을 담고 **전체 대기열**을 펼친다. 두 목표가 같은 재료를 쓰면 가방 재고가 두 번 공제되지 않아야 한다. 수량 수정·선택·제거,320/390/720/넓은창·큰글자, 계정/캐릭터 전환을 확인한다.
2. 추가 목표20도 준비되며 실제 요청은 최대5회다. 시험을 바로20개 모두 실행하지 말고 먼저 승인된 적은 수량/1요청으로 공식 완료횟수·실제 결과물·날개5 차감을 대조한다. 비용/결과 불명은 성공 처리하지 않는다.
3. 확인된 완료량만 제작 진척·남은 목표·재료에 반영되어야 한다. 예:20중5 완료→큐/재료는15, 보관 원본20. 다른 품목 선택 후 복귀해도 진척/예산 유지. 완료목표는 재준비 금지, 명시적 새 추가 목표는0에서 시작하고 그 자체로 소비하지 않는다.
4. 메뉴 이동·다음 작업 중지·5분 만료/묶음 예산은 새 준비만 막고 이미 요청한 결과 관측은 버리지 않아야 한다. 자동 다음 소비명령은 없어야 한다. 재시작은 자동 복원/재개하지 않으므로 실제 보유량을 먼저 확인한다.
5. 시설 등록/완료/남은시간은 조회된 작업 기준이다. 시설 전체 정원·본인 큐 소유권·전체 수령 대상·비용은 아직 미확인이다. 사진의7칸이나15칸을 API 계약으로 단정하거나 절반완료 안내만으로 자동수령/재등록하지 않는다.
