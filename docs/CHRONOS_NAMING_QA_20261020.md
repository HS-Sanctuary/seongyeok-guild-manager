- 2026-10-20 KST / 영겁.
- 기능 브랜치: `codex/home-gnosis-iris-integration-20261019`.

## 발견 원인과 변경 범위

Git 이력상 `be1f81c`(2026-09-16)의 메뉴 정의에서 CHRONOS가 KRONOS로 바뀌었지만 본문과 IRIS에는 CHRONOS가 남아 혼용됐다. 현재 공식 표기는 **CHRONOS / 크로노스**다.

| 파일 | 사용자에게 보이는 수정 |
| --- | --- |
| `types/layout.ts` | SANCTUM PC·모바일 공용 메뉴 KRONOS → CHRONOS |

IRIS `DesktopMainTabs.tsx`는 이미 CHRONOS이므로 제품 코드를 바꾸지 않았다. 플로팅의 크로노스 표시와 내부 `kronos` 명령도 유지한다. 현재 구조 설명은 `app/SANCTUM_MASTER_GUID.md`에 반영했다. 과거 릴리스·릴레이·파일명에 남은 KRONOS는 역사 또는 내부 식별자로서 소급 치환하지 않는다.

보존: `/character`, URL/API, Supabase 테이블·컬럼·RLS, localStorage/로컬 앱 키, 계정·캐릭터 기록, 함수·파일·타입·프로토콜. 네 제품 파일의 변경을 TypeScript AST로 비교해 예상 표시 문자열과 주석 외 실행 코드 차이가 없음을 확인했다.

작업 전 미커밋11항목을 해시로 비교해 모두 보존했으며 기존 삭제 상태도 유지했다. `BETA_FEEDBACK.md`에는 이번 항목만 추가하고 기존 본문은 동일 해시임을 확인했다. 다른 인계 자료·개인 파일을 덮어쓰지 않았다.

## ERGON 설계 반영

- [뉴월 인계서](ERGON_NEWOL_HANDOFF.md)와 [목표 생산 통합 설계](superpowers/specs/2026-10-20-ergon-goal-production-integration-design.md)에 공식 이름·부족분 연결·중단/재개·ETA·무료 운영 제약을 반영했다.
- `부족분 만들기`는 미구현 설계다. 직접 추가100개와 필요100·보유30→부족70을 구분한다.
- 승인 후 즉시 가능한 작업부터 시작하며 사용자 실행시간 입력은 요구하지 않는다. 관측된 가공 대기열 시간과 불명확한 전체 목표 시간을 구분한다.
- 재개 시 게임을 다시 조회하고 남은 목표만 계산한다. 결과/비용 불명은 추가 소비를 막는다. 낚시 별도 검증, 원격 이번 구현 없음.
- 상세 진척·원장은 로컬 우선이다. Supabase Free/Vercel Hobby의 한도와20~40명 가정별 요청·쓰기·폴링·전송량은 설계서에 명시했다. 현재 사용량이나 Hobby 이용 조건이 확인되지 않으면 원격을 보류하고 로컬/수동 대안을 유지한다.

## 남은 과제와 필요한 결정

1. 목표 생산 전체 실행기: 부족 재료 채집부터 반복 가공·수령·재등록·목표 확인은 아직 미완성. 이번에는 구현하지 않는다.
2. 품목별 BOM·해금·시설 용량·비용·실제 결과의 근거가 필요하다. 불명확한 소비를 자동 성공 처리하지 않는다.
3. 한설 결정: 다음 구현에서 우선 지원할 품목/목표, 승인 가능한 비용·초과 산출 범위. 실게임 소비 시험은 별도 승인이다.
4. 원격은 추후 요청 필요성과 무료 이용 적합성·기존 사용량 확인 후 판단한다. 유료 전제 기능으로 진행하지 않는다.
5. 이번 마감 승인 범위만 기능 브랜치에 전송한다. 기존 미커밋 변경은 제외하며 공유 파일의 이번 부분만 분리한다. 운영·공개 버전은 유지하고 정상 전송 확인 뒤 추가 개발 없이 종료한다.
