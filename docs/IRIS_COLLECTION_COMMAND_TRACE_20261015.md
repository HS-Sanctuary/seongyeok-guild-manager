## 결론과 범위

한설은 시설 버튼이 앱 내부 미리보기가 아니라 게임 캐릭터를 해당 시설로 보내길 요청했다. 생활 커넥터 1.3.1과 MobiWorks 설치 소스(서버 표기1.0.11)를 직접 읽어 수령 경로를 대조했다. 두 앱의 소스가 제공되어 추가 분석 엔진·바이너리 디컴파일은 필요하지 않았다. 소스의 주석·설명은 제작자의 관측이며 이번 IRIS 실게임 측정 결과가 아니다.

`complete_altering_work`는 완료된 품목의 `displayName`으로 시설을 정하고, **이동→그 시설의 완료품 전체 수령→보상 처리**를 한 요청으로 수행하는 계약이다. 이번에 확인한 경로에는 이동만 하는 별도 호출이 없다. 따라서 IRIS는 `수령 →` 클릭 뒤 기존 native 최종 확인창을 열고, 사용자가 승인해야 이 명령을 한 번 보낸다. 확인을 취소하면 이동하지 않는다. 자동 재시도·다른 시설 연속 수령·재등록은 추가하지 않는다.

## IRIS 연결과 검증 경계

- `requestErgonCollection`: 유효한 완료품·현재 선택 범위·busy/unknown 검사→기존 native 준비→응답 시설/계정/캐릭터/품목 일치 검사→기존 최종 동의 요청 한 번. 늦은 준비 응답은 nonce 취소, 자동 재개 없음.
- `DesktopErgon`: 사용자 클릭 이벤트만 시작점. 준비 중 연타를 ref로 막고 단일 Execution의 busy와 합친다. 작은 창은 자동 실행 탭의 확인 영역으로 초점·스크롤 이동. 중간 수령 준비 버튼은 숨긴다.
- 최종 확인 뒤 늦게 온 running receipt는 화면이 숨겨져도 ID를 보존한다. 단일 Execution이 같은 ID의 종료 결과까지 관측하므로 UI 안내를 버리는 것과 실행 잠금/관측을 버리는 것을 구분한다. 해당 경합은 합성 실제 React 시험에서 RED→GREEN 확인했다.
- native의 기존 최종 동의·동의 전후 시설 고정·상태 재조회·원장 보호는 그대로다. 실수로 닫힌/오래된/다른 캐릭터 화면에서 실행하지 않는다. 과거 unknown을 해제하지 않는다.
- 단위·실제 React·가짜 CLI·native fixture는 게임과 분리한 합성 검증이다. **이번 실제 게임 이동·수령0건**, 완료품 변화·날개·무게 변화 실측은 사용자 최종 동의 후 별도 확인해야 한다.
