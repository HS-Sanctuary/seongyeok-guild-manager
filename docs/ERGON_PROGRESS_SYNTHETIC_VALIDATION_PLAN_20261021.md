대상: [저장 설계](superpowers/specs/2026-10-21-ergon-progress-result-confirmation-design.md).

**이 문서는 시험 계획이다. 아래 항목의 새 코드 작성/실행/통과는 아직 없다.** 기존 1차 Node614 PASS/3skip·native4그룹·화면14파일 등의 결과를 2차 저장/복구 통과 증거로 재사용하지 않는다.

기본 저장 방향·장기 보존 보완·[3단계 구현 계획](superpowers/plans/2026-10-21-ergon-progress-three-stage-implementation.md)은 한설 검토 승인됐다. 아래61개 원래 ID/범위는 유지하며 마지막10절에서 단계별1차 소유권을 배정한다. [최신 마감 인계](ERGON_CLOSEOUT_20261021.md)는 기존 수정·문서 전송만 승인하며 신규 구현 시작과 구분한다.

## 1. 안전한 시험 환경

- native는 새 고유 임시 디렉터리의 합성 DPAPI 파일/가짜 원장 snapshot만 사용한다. 실제 사용자 AppData·실제 보호 파일·마이그레이션 경로를 생성자에 전달하지 않는다.
- game/CLI 전송기는 호출을 세는 가짜 함수다. 로컬 데이터 API 시험의 기대 호출 수는 0이며, 실행 경계 시험도 실제 실행 대신 고정 결과만 돌려준다. 실 CLI 바이너리/프로세스를 실행하지 않는다.
- 브라우저는 실제 React 컴포넌트·도메인·DTO parser를 사용하고 외부 IO만 교체한다. 실제 계정/인증/DB/게임 연결·원문 응답을 넣지 않는다.
- fault injection은 테스트용 파일 IO seam에서 수행한다. 실제 게임/IRIS 프로세스를 종료하는 대신 테스트 자식 프로세스/가짜 저장기만 중단한다.
- 프로덕션 코드는 시험 전용 성공 판정·수량 주입 우회 API를 추가하지 않는다. 합성 계정/캐릭터/요청/보상 숫자는 검증 자료이며 공식 CLI 계약으로 문서화하지 않는다.
- 실제 원장 생성·Unprotect·unknown 복구·원장 분리는 시험에 포함하지 않는다. 새 진행 파일의 합성 암호화·복호화만 검증한다.

## 2. 공통 통과 오라클

1. 저장 후 새 인스턴스로 읽은 revision/event/request/출처/합계가 기대값과 같아야 한다.
2. 동일 요청에 대한 최신 유효 확인값만 합산되어야 한다. 이전 정정 이벤트와 tombstone은 남아야 한다.
3. 실패·미확인·정합성 충돌에서는 목표 완료/새 게임 confirm·자동 재실행이 없어야 한다.
4. 실패 직전 마지막 정상 데이터는 새 인스턴스에서도 보존되어야 한다. 잘못된 빈 저장소로 대체되면 실패다.
5. 사용자에게 저장 성공으로 보이는 순간과 원자적 커밋 ACK가 일치해야 한다. 호출 수만 확인하고 UI/파일 결과를 생략하지 않는다.
6. 테스트 원장·기존 대기함에 대해 읽기 전후 바이트 해시/상태가 기대대로 유지되어야 한다. native 안전 잠금을 진행 저장이 해제하면 실패다.

## 8. 후속 구현 때의 실행 순서·게이트

1. 순수 도메인/strict parser 테스트를 먼저 RED로 확인한 뒤 최소 구현한다.
2. 새 native 저장소·fault injection·2프로세스/CAS·재시작 fixture를 검증한다. 실제 사용자 파일이 아닌지 테스트 루트 방어부터 확인한다.
3. 바인딩·원장 대조를 기존 native 실행기의 가짜 IO와 통합한다. 실행 안전 관련 기존 nonce/lease/journal/bridge 회귀를 재실행한다.
4. 실제 React + 합성 bridge로 확인/정정/저장 실패/캐릭터 전환/종료 경고·대기열 예약을 검증한다.
5. 전체 Node, scoped lint, 별도 TypeScript 검사, 실제 설정을 읽지 않는 격리 빌드, 공개 잠금·현재 저장 줄 회귀를 실행한다. 고정 포트 브라우저 시험은 직렬 실행한다.
6. 기존 실패는 HEAD/동일 조건과 비교해 신규 회귀와 구분한다. 잠금 때문에 실패하는 오래된 시험을 통과시키려고 공개 ERGON을 열지 않는다.
7. 실제 게임·기존 보호 파일 변경·commit/push·배포 없이 변경·합성 결과·미완료를 보고한다. 실게임 성공으로 표현하지 않는다.

명령/파일의 최종 구현 목록은 설계 승인 뒤 구현 계획에서 확정한다. 이 실행 순서는 시험 범위 제안이며 이번에 실행을 승인하거나 테스트 코드를 만든 것이 아니다.
