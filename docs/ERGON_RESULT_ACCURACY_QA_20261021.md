## 후속: 보상 증거를 조사하는 안전한 방법 — 미실행

1. 한설에게 **기존 소유 응답의 오프라인 열람** 범위부터 별도 승인받는다. 추가 CLI 호출이나 실제 제작 승인을 포함시키지 않는다.
2. 승인된 응답의 원본·해시·보호 상태를 먼저 확인한다. 변경하지 않는 로컬 사본만 조사하고, 기존 last-response/보호 원장을 덮어쓰거나 해제하지 않는다.
3. `rewards`, `criticalRewards`는 capabilities에서 존재만 확인한 후보로 취급한다. 배열 행의 필드 이름/품목 식별자/수량 의미/기본과 대성공의 중복 관계를 실제 자료 및 공식 설명과 대조한다. 수령의 `Name`/`Amount` 형식을 제작에 임의 대입하지 않는다.
4. 계정/캐릭터/토큰/개인 경로·원문 로그를 채팅이나 공개 Git에 출력하지 않는다. 필요한 경우 키·자료형과 익명화된 합성 반례만 문서/테스트에 남긴다. 허용된 응답이 없으면 조사 불가로 남긴다.
5. 품목·등급·요청 대응과 합산 의미가 확인되지 않으면 파서를 만들지 않는다. 빈 배열·누락·미지원 형식·충돌·범위 초과를 실제0이나 예상량으로 바꾸지 않는다.

## 후속: 별도 결과 검증 어댑터 제안 — 미구현

- 책임: 명령 종료와 독립적으로 **이번 요청의 목표 품목에 귀속된 확인 수량 또는 미확인**을 반환. 예상량/명령 횟수로 대체 금지.
- 후보 수정 경계: native 제작 응답 검증 → 검증된 증거 전용 bridge 타입/버전과 strict parser → goal 진척 반영. 기존 원문 원장과 안전 잠금은 별도로 보존.

- 장비 수량을 증명할 수 없으면 명시적 사용자 결과 확인을 별도 출처·시점·요청으로 연결하는 UX를 후속 설계. 이 확인으로 native unknown 원장을 해제하지 않음.
