## 램 도구

설정은 대상 `MabinogiMobile.exe`, 임계값 2000MB, 검사 간격 45초, threshold 모드, 오버레이 표시, Windows 시작 시 실행이다. 설정의 실제 계산 기준과 정리 API는 EXE 소스가 없어 미확인이다.

관측 시 게임 Working Set 약 996MiB, Private Bytes 약 4209MiB, 램 도구 두 프로세스 Working Set 합계 약 6MiB였다. 이전 관측의 게임 Working Set 약 664MiB와 비교해 값이 변했으나 정리 직전/직후 측정이 아니므로 효과나 인과관계를 주장하지 않는다. 누수 수정 효과도 증명하지 않았다.

Windows의 Working Set 정리는 할당 해제와 다른 개념이다. 이 EXE가 해당 방식을 사용하는지도 확인하지 못했다. 참고: https://learn.microsoft.com/windows/win32/memory/working-set 및 https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-emptyworkingset

IRIS 동시 시작은 가능하다. 구현 시 기존 Windows 자동 실행/수동 실행을 확인하고 중복 시작을 막아야 한다. 사용자가 먼저 실행한 프로세스를 IRIS 종료 시 임의로 종료하지 않는다. 파일 경로는 PC 로컬 설정에 저장하고 배포본에 타 제작자 EXE를 포함하는 것과 구분한다. 원본 config 변경이나 재배포는 이번 검토에 포함하지 않았다.

## 확인된 제한과 IRIS 반영 방향

1. 설명서가 최신 기능을 모두 담지 못한다. `README_Manual.txt`는 2열 탭 설명과 구 명칭 일부를 유지하며 반복 가공·재등록·앱 업데이트 설명이 부족하다. 첨부 가이드와 실제 모듈을 함께 기준으로 삼는다.
2. 프로세스 간 작업 충돌 방어가 없다. 설치 모듈 검색에서 IRIS의 `Local\SANCTUM.IRIS.Queue...`와 공유되는 Mutex/파일 잠금을 확인하지 못했다. 커넥터의 UI 내부 잠금은 IRIS 실행을 막지 않는다. IRIS 자동화 구현 시 외부 도구 작업과 동시 실행을 제한하는 설계가 필요하다.
3. 메모·즐겨찾기·설정 저장의 catch가 비어 있어 실패가 사용자에게 드러나지 않을 수 있다. Program Files 저장 권한에 따른 실제 실패 여부는 미검증이다. IRIS 자체 설정은 사용자 AppData에 저장하고 실패를 표시한다.
4. 연결 시 상태 폴링은 목표 1.5초 주기로 본인·재화·가공·환경·주변을 순차 조회한다. 연결 실패 시 최소 5초 대기가 있다. IRIS와 함께 쓸 때 중복 조회가 늘 수 있다. IRIS 로컬 캐시/단일 조회 경로를 유지하고 게임 상태를 DB에 매 주기 기록하지 않는다.
5. 공식 저장소 URL 제한, 파일 크기·SHA256 검증, 실행 중 작업이 있으면 업데이트 차단하는 코드가 있다. 실제 배포 자산·설치 성공은 확인하지 않았다.
6. 반복 가공에는 사용자 확인·최대 1시간·재료/날개 부족·사용자 중단 대응 및 수령/등록 후 재조회가 있다. 실제 장시간/경계/실패 테스트는 남는다.
7. 명칭 변경으로 공식 CLI 조회 경로 자체가 바뀐 근거는 없다. 신원/초상화/모든 캐릭터 스탯을 새로 지원한다고 가정하지 않는다. 기존 `IRIS_STATS_CONTRACT.md`의 안전한 캐릭터 매칭 제한은 유지한다.
