# ASTRA 계정 활동 집계 DB 제안 — 2026-10-28

상태: **승인 대기·미적용**. 기능 플래그 `SANCTUM_ACCOUNT_ACTIVITY_ENABLED`가 정확히 `true`일 때만 새 기록·조회 경로를 사용한다. 기본값은 비활성이다. 이 문서는 운영 스키마 확인본을 대신하지 않는다.

## 목적과 영향

웹과 IRIS에서 인증된 사용자의 실제 입력·접속 활동을 계정당 마지막 시각 한 값으로 합친다. 새 `public.sanctum_account_activity`는 계정 UUID 기본키와 DB가 정한 `last_active_at` 두 컬럼만 가진다. 캐릭터 활동·기존 세션의 `last_seen_at`을 수정하거나 과거 기록으로 현재 활동을 추정하지 않는다. 세션 삭제·로그아웃 뒤에도 집계는 남으며 계정 삭제 때만 외래키로 함께 삭제된다.

기록 API는 POST `/api/account/activity`, 본문은 `{ expectedAccountId }` 한 필드이며 최대 256바이트다. 같은 출처의 Origin이 필수다. 현재 HttpOnly 세션 쿠키의 해시와 기대 계정만 서버 전용 RPC에 보낸다. 기대 계정은 계정 전환 중 잘못된 기록을 막는 비교값이며 인증 수단이 아니다. 클라이언트가 기록 계정·시각·닉네임을 지정할 수 없다.

DB 함수는 잠금 없는 세션 소유자 탐색 뒤 승인된 계정 행 → 같은 token hash·소유자의 세션 재조회 순서로 공유 잠금을 잡는다. 최초 탐색값만으로 인증하지 않는다. 기존 계정 삭제의 FK cascade/코드 변경과 잠금 순서를 맞춘다. 계정별 트랜잭션 advisory lock 뒤 DB 시각으로 만료를 다시 검사한다. 계정 하나의 행에 대한 조건부 UPSERT가 모든 기기의 20분 제한을 적용하고 시각이 감소하지 않게 한다. 세션 만료 연장·주기적 heartbeat·접속 이력 추가 테이블은 없다. 표시 범위와 개인정보 설정은 별도 조회 계층에서 기존 정책을 적용한다.

## 적용 전 확인과 승인 범위

준비 SQL은 `supabase/proposals/20261028_account_activity.sql`이며 자동 마이그레이션 경로 밖에 있다. 한설의 별도 DB 승인이 있기 전 실행하지 않는다. 기존 테이블은 변경하지 않지만 새 테이블·함수·권한을 만드는 구조 변경이다.

승인 뒤에는 실제 DB 버전·기존 `accounts`/`sanctum_sessions` 형식, 함수/테이블 이름 충돌 없음, `service_role`의 BYPASSRLS·조회·행 잠금 권한을 먼저 확인한다. 이 SQL은 새 테이블의 PUBLIC/anon/authenticated 접근을 모두 막고 service_role에 SELECT/INSERT/UPDATE만, 새 함수에는 EXECUTE만 허용한다. 다른 계정·세션 정책은 바꾸지 않는다. 현재 운영 스키마 및 권한과 대조한 뒤 필요한 재실행 가능한 마이그레이션 등록과 필수 구조 문서 갱신은 별도 적용 작업으로 수행한다.

## 검증 범위와 남은 위험

로컬 시험은 실제 TypeScript API/도우미를 실행하고 DB I/O만 합성 대체했다. 기본 비활성 시 DB 호출 0, 세션 누락, 계정 불일치, 엄격한 본문·출처 제한, 오류 비밀값 차단, 20분 합성 동시 요청 계약을 확인한다. SQL 잠금·권한 구조는 정적 확인이다. **실제 PostgreSQL 실행·동시성·운영 조회·배포 검증은 미실행**이다.

적용 승인 뒤에는 실제 DB에서 만료·철회·승인대기 세션의 쓰기 0, 다른 계정 쿠키와 기대 계정의 충돌 및 쓰기 0, 웹/IRIS 병렬 요청의 한 행·20분 제한, 잠금 대기 중 만료 재검사, 동시 계정 삭제/코드 변경·최초 탐색 후 세션 삭제/소유 변경을 검증해야 한다. 테이블 직접/default service_role 권한도 먼저 회수한 뒤 SELECT/INSERT/UPDATE만 부여한다. 역할 멤버십을 통한 상속 권한까지 REVOKE가 없애지는 않으므로 실제 멤버십·has_table_privilege·함수 EXECUTE를 따로 검사한다. 잠금 해시 충돌은 무관한 계정의 처리를 잠시 직렬화할 수 있지만 소유권을 바꾸지 않는다. 실제 서비스 권한·동시성 검증과 배포 확인 전 플래그를 활성화하지 않는다.

## 복구

문제 발생 시 모든 서버에서 플래그를 먼저 끄고 해당 호출이 멈췄는지 확인한다. 필요하면 그 다음 새 RPC의 service_role EXECUTE를 회수한다. 생성된 집계 행은 보존하며 기존 값 덮어쓰기·추정 시각 채우기·테이블 삭제를 복구 수단으로 사용하지 않는다. 기존 로그인·세션·캐릭터 테이블에 복구할 변경은 없다.
