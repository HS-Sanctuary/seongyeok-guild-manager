# IRIS 로컬 읽기 시제품

게임이 켜져 있고 `MM AI 에이전트`가 활성화된 PC에서 `node iris/server.mjs`를 실행한 뒤 `http://127.0.0.1:4317`을 연다. 기본 게임 CLI 경로가 다르면 `MABINOGI_CLI_PATH` 환경 변수를 지정한다.

Codex의 제한된 실행 환경에서는 게임 CLI가 실제 게임 실행 여부와 관계없이 `game_off`를 반환할 수 있다. 이 PC에서는 일반 로컬 실행에서 정상 연결되었으므로, 연결 대기가 보이면 게임 설정을 바꾸기 전에 실행 환경의 접근 권한을 확인한다.

- `get_my_info`, `get_altering_works`, `get_daily_missions`, `get_weekly_missions`, `get_currencies`만 호출한다. 게임을 조작하는 CLI 명령은 허용 목록에 없다.
- 서버는 `127.0.0.1`에만 바인딩한다. 계정 식별자·캐릭터 이름·원본 응답은 브라우저에 보내지 않으며 저장도 하지 않는다.
- 생텀 DB 동기화는 구현되지 않았다. 실제 데이터의 필드·의미를 확인한 뒤 별도 승인과 검증이 필요하다.
- 생텀 `/iris`는 로그인 세션에 속한 캐릭터 목록을 크로노스와 같은 선택 UI로 보여준다. 선택 확인은 화면 상태에만 남고 새로고침하면 사라진다. 게임 닉네임 자동 판별, 영구 계정 페어링, DB 저장·동기화는 아직 없다.
- 로컬 화면의 `생텀에서 미리보기 승인`을 누르면 30분짜리 일회성 브라우저 연결 토큰이 만들어지고 개발용 `http://localhost:3000/iris`로 돌아간다. 토큰은 URL fragment로만 전달하고 주소창에서 즉시 제거한다. `/iris`에서 계정 소유 캐릭터를 직접 확인한 후 브라우저가 `127.0.0.1:4317`의 읽기 전용 브리지에서 요약값을 가져온다. 연결 해제 시 로컬 토큰을 폐기한다. **서버 DB 업로드·자동 동기화·게임 닉네임 검증은 하지 않는다.** 현재 브리지의 허용 Origin은 로컬 개발용 `localhost:3000`/`127.0.0.1:3000`뿐이다.
- 게임이 꺼져 있거나 에이전트 연결이 끊기면 연결 대기 상태가 표시된다.
- 이 미리보기는 개인 PC에서만 실행한다. 인터넷에 공개하거나 게임 CLI를 Vercel 서버에서 실행하지 않는다.

검증: `node --test iris/reader.test.mjs`

## Windows 오버레이 알파

Windows PowerShell에서 저장소 루트로 이동한 뒤 `powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File iris/overlay.ps1`을 실행한다. 별도 PowerShell 7 설치는 필요 없다. `ExecutionPolicy Bypass`는 이 프로세스에만 적용되며 시스템 설정을 변경하지 않는다. 별도 설치 패키지는 아직 없으며, 창을 닫으면 오버레이가 시작한 로컬 서버도 함께 종료된다. 이미 실행 중이던 로컬 서버는 종료하지 않는다.

오버레이는 게임 위에 놓는 작은 항상 위 창이다. 제목 부분을 끌어 이동하고 `−`로 접거나 `×`로 닫을 수 있다. 직업·레벨, 전투력·생활력·매력·마도저항·데코점수, 가공기 및 일일·주간 숙제 요약을 5초 간격으로 읽는다. 게임 연결 대기 중에는 값을 임의로 채우지 않는다. 게임 전체 화면의 표시 방식에 따라 항상 위 창이 보이지 않을 수 있으므로 창 모드/테두리 없는 창 모드에서 우선 확인한다.

이 알파는 읽기 전용 표시 도구다. 캐릭터 이름 자동 대조, 게임 조작, 생텀 DB 업로드, 자동 제작·채집은 포함하지 않는다.
