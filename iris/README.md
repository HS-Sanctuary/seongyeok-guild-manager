# IRIS 로컬 읽기 시제품

## 램 정리 함께 시작 — 2026-10-07

`desktop.ps1`과 기존 `overlay.ps1`은 PC별로 연결한 램누수정리v2를 함께 시작한다. 기존 실행이 있으면 재사용하고, 없으면 실행 파일 폴더를 작업 경로로 지정하여 시작한다. 램 도구의 정리 주기/임계치·Windows 시작 설정은 변경하지 않는다. IRIS 종료 시 램 도구는 계속 실행된다.

최초 연결은 저장소 루트에서 아래 명령으로 설정한다. 이 사무실 PC는 연결·켜짐 설정을 완료했다. 다른 PC는 설치된 실행 파일의 실제 경로를 지정해야 한다. 연결되지 않은 PC는 기본 꺼짐이다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File iris/configure-ram-companion.ps1 -ExecutablePath "C:\Users\sungw\Downloads\램누수정리v2\램누수정리v2.exe"
```

Windows 알림 영역의 IRIS 아이콘을 우클릭하면 시작 결과와 `램 정리 함께 시작 · 다음 실행부터` 체크 메뉴가 보인다. 끄면 다음 IRIS 시작부터 적용되고 실행 중인 램 도구는 유지한다. 경로를 바꾸려면 위 연결 명령을 새 경로로 실행한다. 설정은 사용자 `%LOCALAPPDATA%\Sanctum\IRIS\ram-companion.json`에만 저장하며 Git/서버에 올리지 않는다. 파일 누락·설정 손상·시작 실패는 트레이에 표시하며 IRIS 실행은 유지한다.

검증: Windows PowerShell 5의 9개 회귀 시나리오(기존 부모/자식 재사용·단일 시작 요청·실패·파일 이동·꺼짐·손상 설정), 실제 실행 중인 두 프로세스 유지 및 트레이 메뉴 생성. 새 프로세스가 없는 상황의 실제 EXE 시작/IRIS 전체 재시작은 수동 확인 대상으로 남는다. 제작자 EXE는 저장소에 포함하지 않는다.

## 컴팩트 오버레이 후보 — 2026-10-06

정상 종료 후 같은 `desktop.ps1 -Development`로 재실행하면 둥근 작은 센터가 열린다. 캐릭터 버튼으로 선택하고 숙제 항목을 바로 체크한다. 일일/주간/어비스/레이드 제목으로 접고 펼친다. 센터의 − 버튼으로 전체를 접어도 저장/복구 요약은 남는다. 최종 조작 후15초 자동저장과 지금 저장은 유지한다.

상단 얇은 띠를 끌어 이동하고 하단 띠로 폭을 조정한다. 내용에 따라 높이가 줄고 늘며 화면 작업 영역 안으로 제한된다. Ctrl+Alt+I 표시/숨김, Ctrl+Alt+O 클릭 통과. 설정에서50~100% 불투명도와 통과 상태를 바꾼다. 단축키 충돌 시 통과는 비활성이고 트레이 센터 열기로 입력을 복구한다. 테마 버튼은 현재 화면에 적용되며 재실행 기억은 후속이다.

큰 구형 창의 로그인·숙제 반영 사용자 확인과 새 네이티브 후보 자동 검증을 구분한다. 게임 전체화면/실제 게임 클릭 통과·DPI·다중 모니터는 사용자 검증 대기다. 새 후보는 기존 스테이터스/가공/미션 위젯을 함께 실행하지 않는다. 스탯 자동 저장과 시낙시스 조회도 아직 활성화되지 않았다. 자세한 지원 근거는 docs/IRIS_STATS_CONTRACT.md를 따른다.

## 2026-10-06 생텀 데스크톱 후보

기존 IRIS를 정상 종료한 뒤, 로컬 서버가 켜진 상태에서 `powershell -NoProfile -STA -File iris/desktop.ps1 -Development`로 새 후보를 연다. 기본 실행기 교체·배포는 하지 않았다. 새 전용 창에서 생텀 계정으로 직접 로그인한다. 로그인 코드는 채팅에 보내지 않는다.

캐릭터별 마지막 조작과 캐릭터를 떠난 시점부터 15초 후 자동저장하며 ‘지금 저장’도 제공한다. 불명확 저장은 자동 반복하지 않고 확인 후 재시도한다. 미저장 항목은 Windows 사용자/환경별 암호화 파일로 보관한다. 클래스 표시는 생텀에 저장된 레벨이다.

일반 종료는 저장/보관/버리기/돌아가기를 선택한다. 오프라인은 ‘보관하고 종료’를 사용한다. 보관 실패 안내 또는 트레이 ‘복구 종료’는 최근 변경 손실 위험을 확인한 경우에만 사용한다. 읽을 수 없는 보호 파일은 덮어쓰지 않는다.

실제 로그인 유지·저장 시간·재실행 복구·게임 위 사용성은 수동 검증 전이다. 신규 후보는 기존 게임 읽기 위젯과 단축키를 자동 통합하지 않는다. 두 실행기는 공유 잠금으로 동시 큐 실행을 막는다.

## 2026-10-04 크로노스 체크·명시 저장 — 최신 로컬 후보

현재 체크보드는 읽기 전용에 더해 **별도 동의 후 숙제 수정**을 지원한다. 아래 과거 절의 미구현 설명은 해당 당시의 상태다. 실행 중인 IRIS는 정상 종료하고 위 실행 명령으로 재실행한다. `생텀 연결 · 크로노스`에서 새 읽기 연결→생텀 화면 열기→읽기 동의→오버레이 본인 캐릭터 확인을 한 뒤, 같은 생텀 탭의 **동의하고 숙제 수정 허용**을 누른다.

센터 **숙제**에서 단일 항목은 완료 체크/취소, 반복 항목은 −/+로 바꾼다. 아직 DB에 쓰지 않은 값은 **미저장 N개**이며 **변경 저장**을 눌러야 저장된다. 승인 탭을 열어 둬야 한다. 저장 대기/결과 확인/실패/충돌/저장 확인을 구분한다. 여러 항목은 순서대로 저장하므로 일부만 성공할 수 있다. 불명 결과는 중복 저장하지 않고 다시 읽으며, 실패는 확인 후 명시 재시도, 충돌은 변경을 버리고 최신 상태부터 확인한다.

위젯 ×/숨김은 변경을 보존한다. 캐릭터 전환·새 연결·변경 폐기·IRIS 종료에서는 폐기를 먼저 확인한다. 큐는 메모리 전용(최대200, UTF8 크기 초과 거절)으로 강제종료 복구는 보장하지 않는다. 이미 서버에 도착한 저장은 폐기/종료로 취소되지 않는다. 클래스 레벨 수정, 게임 보상 수령·자동 채집/제작, 게임→DB 자동 동기화는 없다. 구형 통합 완료 키를 쪼개 다른 숙제를 바꾸게 되는 경우 안전하게 거절한다.

자동 검증은 합성 데이터만 사용했다. 전체161/161·별도 타입·이번 저장 범위 린트·웹 빌드 통과. 실제 DB 저장 시험은 대상 항목 별도 승인 후 진행하며 아직 사용자 검증 대기다. 신규 DB/RLS/권한 변경·배포 없음.

## 2026-10-04 독립 숙제 체크보드 — 로컬 후보

센터 상단 `숙제`에서 **크로노스 체크보드**를 열 수 있다. 기존 `생텀 연결 · 크로노스`에서 승인하고 현재 캐릭터를 확인하면, 일일/주간/어비스/레이드를 각각 펼쳐 항목명과 완료/총횟수를 읽는다. `남은 숙제만`은 표시 필터이며 기록을 변경하지 않고 범주 합계도 그대로 유지한다. 완료 목록과 빈 목록을 구분한다.

`클래스 · 생텀 저장값`은 활성 클래스와 해당 캐릭터의 기존 저장 레벨을 보여 준다. 미등록/비정상 값은 `미등록`이며 캐릭터 레벨이나 Lv.1로 채우지 않는다. 게임의 전체 클래스 목록을 자동 수집하는 기능이 아니다. 체크보드는 **읽기 전용**이며 항목 체크 저장·자동 채집·가공·수령은 아직 없다.

긴 항목명은 줄바꿈하고 큰 목록은 창 내부에서 스크롤한다. 6테마/전체 불투명도/접기/개별 숨기기/단축키 복구를 기존 창과 공유한다. `×`로 숨긴 뒤 센터 `숙제` 또는 트레이에서 다시 연다. `checkboard-window.json`에도 위치/접힘만 저장하며 숙제·클래스 데이터는 저장하지 않는다. 탭 연결 중단/캐릭터 전환/잘못된 상세/만료에서는 이전 데이터를 비운다.

적용: 실행 중 IRIS를 `IRIS 종료`에서 확인 후 종료 → 아래 실행 명령으로 재시작 → `http://localhost:3000/iris` 새 읽기 연결 승인 → 오버레이 캐릭터 확인 → 센터 `숙제`. 자동 Windows/Node 테스트는139/139(실제 공유 갱신 배선 포함), 별도 타입 검사와 웹 빌드 통과. 실제 사용자 연결 상태에서 새 체크보드의 항목/클래스 대조와 DPI 확인은 대기다. 검증 과정에서 실제 게임 명령/운영 DB 쓰기는 실행하지 않았다.

10/3 로컬 후보는 Windows에서 직접 소유한 서버·브라우저 승인·본인 캐릭터 확인·크로노스 읽기 요약까지 연결한다. 기존 게임 읽기와 별개이며 자동 채집·제작·수령이나 숙제 체크 저장은 아직 없다. 실제 로그인/게임 화면 수동 확인과 운영 배포는 미완료다.

기존 IRIS를 종료하고 아래 명령으로 재실행한다. 센터의 **생텀 연결 · 크로노스 → 새 읽기 연결 → 생텀 화면 열기**를 누른다. 로컬 `http://localhost:3000` 개발 서버와 로그인 세션이 필요하며 `/iris`에서 전달에 동의한 뒤 오버레이에서 현재 게임 캐릭터를 확인한다. 뒤에서 열림은 보장하지 않으므로 자동 열림 대신 직접 여는 버튼을 제공한다. 기존 소유 불명 서버는 종료/탈취하지 않고 연결 재시작 안내를 표시한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File iris/overlay.ps1
```

연결용 토큰은 메모리/소유한 child stdin pipe만 사용하며 브라우저 임시 토큰은 fragment를 읽은 즉시 지운다. 창 설정과 별개인 `last-character.json`은 버전/계정 구분값/생텀 캐릭터 ID만 저장한다. 현재 목록에서 마지막 선택을 제안할 뿐 자동 확정하지 않는다. 탭 닫힘/연결 중지 후 최대60초에 요약은 비워진다. 구형 완료 슬롯이 현재 요일 최대치를 넘는 기간 경계는 임의 초기화하지 않고 조회 실패로 남긴다.

게임이 켜져 있고 `MM AI 에이전트`가 활성화된 PC에서 `node iris/server.mjs`를 실행한 뒤 `http://127.0.0.1:4317`을 연다. 기본 게임 CLI 경로가 다르면 `MABINOGI_CLI_PATH` 환경 변수를 지정한다.

Codex의 제한된 실행 환경에서는 게임 CLI가 실제 게임 실행 여부와 관계없이 `game_off`를 반환할 수 있다. 이 PC에서는 일반 로컬 실행에서 정상 연결되었으므로, 연결 대기가 보이면 게임 설정을 바꾸기 전에 실행 환경의 접근 권한을 확인한다.

- `get_my_info`, `get_altering_works`, `get_daily_missions`, `get_weekly_missions`, `get_currencies`만 호출한다. 게임을 조작하는 CLI 명령은 허용 목록에 없다.

- 생텀 DB 동기화는 구현되지 않았다. 실제 데이터의 필드·의미를 확인한 뒤 별도 승인과 검증이 필요하다.
- 생텀 `/iris`는 로그인 세션에 속한 캐릭터 목록을 크로노스와 같은 선택 UI로 보여준다. 선택 확인은 화면 상태에만 남고 새로고침하면 사라진다. 게임 닉네임 자동 판별, 영구 계정 페어링, DB 저장·동기화는 아직 없다.

- 게임이 꺼져 있거나 에이전트 연결이 끊기면 연결 대기 상태가 표시된다.
- 이 미리보기는 개인 PC에서만 실행한다. 인터넷에 공개하거나 게임 CLI를 Vercel 서버에서 실행하지 않는다.

검증: `node --test` (Windows에서는 오버레이 C# 컴파일·표시/복구 로직·실제 PowerShell 타이머 코드도 검증한다. 게임이나 실제 창을 조작하는 검증은 아니다.)

## Windows 오버레이 알파

### 2026-10-03 독립 모듈창 후보

같은 실행 명령으로 작은 **커맨드센터**와 `스테이터스` / `가공 완료` / `게임 미션` 창이 따로 표시된다. 각 모듈은 제목을 끌어 이동하고 `−/+`로 접기/펼치기, `×`로 개별 숨기기를 한다. 센터의 `상태/가공/미션` 버튼이나 트레이에서 다시 표시한다. **센터 `×`와 Alt+F4도 센터만 숨긴다.** 센터를 숨겼다면 트레이를 더블클릭하거나 `Ctrl+Alt+I`를 한 번 눌러 복구한다. 별도 `IRIS 종료` 버튼/트레이 메뉴에서 확인하고 종료한다(기본 선택은 아니오). `Ctrl+Alt+I/O`는 전체 표시·통과를 제어하며 단축키 등록/게임 조회는 센터 하나만 소유한다. 전체 복구는 개별 숨긴 모듈을 강제로 켜지 않는다.

센터의 `테마 · 투명도`에서 생텀의 6개 테마와 불투명도 40~100%를 적용한다. 낮추면 배경과 글자가 함께 투명해진다. `display-settings.json`은 version/theme/opacityPercent만 별도로 원자 저장한다. 위치 파일은 기존 형식을 유지한다. 이 설정은 현재 모든 창에 함께 적용되고, 개별 위젯 투명도·배율·프리셋·자동 종료 설정은 후속이다.

가공 창은 금속/목재/가죽/옷감/약품/식재료를 3×2로 표시한다. **타원형 바 하나가 등록 작업 하나**이며 완료된 작업은 주황색, 나머지는 흐린색이다. 7개 등록 중5개 완료면7칸 중5칸이 밝다. 큰 목록은14칸까지 그리고 `추가 N개`와 정확한 전체/완료 개수를 표시해 긴 창이 되지 않게 한다. 시간 진행률이 아니다. 남은 시간은 해당 시설에서 가장 빨리 끝나는 진행 작업 기준이고 응답에 시간이 없으면 `시간 미상`이다(14개 초과 시 개수 요약 우선). 조회 실패와 정상 빈 목록의 `대기`를 구분한다. 실제 수령 명령/버튼은 아직 연결하지 않았다.

창별 `stats-window.json`, `processing-window.json`, `missions-window.json`은 기존 설정 폴더에 version/x/y/collapsed만 저장한다. 게임 미션은 CLI의 요약이며 생텀 크로노스 체크 저장 기능이 아니다. 새 모듈의 실제 게임 화면 배치·트레이·다중 DPI·장시간 사용 확인은 남아 있다. 설치형 배포·코드 서명·게임/음악 연동 규약 점검은 [배포 준비 문서](../docs/IRIS_DISTRIBUTION.md)를 따른다.

Windows PowerShell에서 저장소 루트로 이동한 뒤 `powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File iris/overlay.ps1`을 실행한다. 별도 PowerShell 7 설치는 필요 없다. `ExecutionPolicy Bypass`는 이 프로세스에만 적용되며 시스템 설정을 변경하지 않는다. 별도 설치 패키지는 아직 없으며, 확인 후 IRIS를 종료하면 오버레이가 시작한 로컬 서버도 함께 종료된다. 이미 실행 중이던 로컬 서버는 종료하지 않는다.

오버레이는 게임 위에 놓는 작은 항상 위 창이다. 제목 부분을 끌어 이동하고 `−`로 접거나 `×`로 닫을 수 있다. 직업·레벨, 전투력·생활력·매력·마도저항·데코점수, 가공기 및 일일·주간 숙제 요약을 읽는다. 게임 전체 화면의 표시 방식에 따라 항상 위 창이 보이지 않을 수 있으므로 창 모드/테두리 없는 창 모드에서 우선 확인한다.

### 2026-10-02 로컬 개선 후보 (실제 게임 위 검증 대기)

2026-10-03 사용자 확인: 한설이 게임 위 새 표시와 두 단축키의 숨김/표시·클릭 통과 켜기/끄기를 직접 정상 확인했다. 나머지 재실행/연결 해제/충돌/트레이/다중 화면/장시간 검증은 별도 남아 있다. 이는 아래 자동 테스트와 구분되는 사용자 실검증 결과다.

- 조회는 비동기로 실행하고 한 번에 하나만 유지한다. 성공 응답을 받은 뒤 5초 후 다음 조회를 시작한다. 연결 실패 시 5→10→20→30초로 대기 시간을 늘린다. CLI의 연속 읽기에 최대 40초가 걸릴 수 있어 HTTP 제한은 45초다. 숨긴 동안 새 조회는 하지 않으며, 숨기기 전 응답은 복원 후 표시하지 않는다.
- 연결 해제·잘못된 응답 또는 마지막 관측 후 30초 경과 시 모든 값을 `—`로 비운다. 조회 중/연결 대기를 구분하며 누락값을 0으로 만들지 않는다. 실제 게임 종료 감지는 다음 응답 또는 30초 경과 뒤 이뤄지므로 즉시 감지라고 약속하지 않는다.
- `Ctrl+Alt+I`: 표시/숨기기. 다시 표시하면 클릭 통과를 끄고 새 값을 읽는다. `Ctrl+Alt+O`: 클릭 통과 켜기/끄기. 다른 프로그램이 단축키를 차지해 두 키를 모두 확보하지 못하면 부분 등록을 해제하고 클릭 통과를 비활성화한다. 클릭 통과는 마우스를 창 뒤로 전달하는 모드다; 게임 키 입력을 주입하지 않는다.
- Windows 알림 영역의 IRIS 아이콘을 더블클릭하면 표시·입력을 복구한다. 우클릭 메뉴에서 숨기기/클릭 통과/종료도 가능하다. 단축키 충돌 시 트레이나 일반 창 버튼을 이용한다. 앱이 종료되면 전역 단축키와 트레이 아이콘을 해제한다.
- 창 위치와 접힘만 `%LOCALAPPDATA%\SanctumIRIS\overlay-settings.json`에 저장한다. 저장 항목은 `version`, `x`, `y`, `collapsed`뿐이다. 게임 수치·이름·로그인 코드·토큰·숨김·클릭 통과 상태는 저장하지 않는다. 잘못된 설정은 기본값으로 시작하고, 사라진 모니터의 위치는 현재 화면 작업 영역으로 복귀시킨다. 시작은 항상 표시·조작 가능한 상태다(저장된 접힘은 유지).
- `overlay-support.cs`는 조회/표시/창 설정, `overlay-native.cs`는 자기 창의 클릭 통과와 전역 단축키 등록만 담당한다. 서버·브리지 인증·CLI 허용 명령·웹 API·DB는 변경하지 않았다.

직접 확인할 순서: 기존 IRIS를 종료하고 새 명령으로 실행 → 센터 ×로 숨기기와 Ctrl+Alt+I 복구 → 테마·투명도 적용 → 종료에서 아니오/예 확인. 창 이동/접기 후 재실행과 게임 종료 후 값이 비워지는지도 확인한다. 실제 클릭 전달·게임 포커스·단축키 충돌·다중 모니터/DPI·장시간 사용은 자동 테스트 통과와 별개의 남은 검증이다.

이 알파는 읽기 전용 표시 도구다. 캐릭터 이름 자동 대조, 게임 조작, 생텀 DB 업로드, 자동 제작·채집은 포함하지 않는다.
