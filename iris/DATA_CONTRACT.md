# IRIS → SANCTUM 연결 검토 (2026-09-28)

현재 단계는 **읽기 전용 로컬 시제품**이다. 운영 DB 쓰기, 계정 연결, 게임 자동 조작은 구현하지 않았다.

2026-09-29 로컬 브리지 미리보기: 아이리스가 30분짜리 임의 토큰을 사용자의 명시적 클릭으로 발급한다. 생텀 개발 화면은 토큰과 캐릭터 직접 확인이 모두 있어야 요약 데이터를 브라우저에서 표시한다. 이 토큰은 생텀 로그인 권한이나 캐릭터 동일성의 증거가 아니며 DB 쓰기에 재사용하지 않는다. 허용 Origin·토큰이 없으면 브리지 요청은 403이다. 운영 배포용 연결/소유권 검증과 DB 동기화는 별도 설계·승인이 필요하다.

안전한 동기화 순서: 로컬에서 읽기 → 화면에서 사용자에게 값과 대상 캐릭터 제시 → 생텀 서버 세션으로 본인 계정 검증 → 변경 미리보기 → 승인된 필드만 서버에서 갱신 → 결과와 오류 표시. 계정명·캐릭터 이름만으로 자동 연결하거나, 비로그인 고권한 동기화 API를 재사용하지 않는다.

실측 진단: 제한된 Codex 작업 환경에서는 `get_my_info`/`get_activity`가 `pipe: disconnected`, `reason: game_off`를 반환하지만, 동일 PC의 샌드박스 밖에서 `get_my_info`와 `get_altering_works`는 성공했다. 게임·MM AI 설정 문제는 아니며 실행 환경의 접근 차이가 원인이다. 실측 필드 이름은 전투력·생활력·매력·마도저항과 가공 작업 배열을 포함한다. 개인정보가 든 원본 응답과 실제 수치는 파일·Git·채팅에 기록하지 않는다.

로컬 화면 `http://127.0.0.1:4317`에서 `게임 연결됨`, 직업·레벨·전투력·생활력·매력·마도저항 및 가공 시설 현황이 실제 데이터로 표시되는 것을 확인했다. 게임 CLI에서 일일/주간 숙제 배열과 각 항목의 완료·보상 수령 필드도 확인했고 로컬 요약을 추가했다. 화면 표시 검증에 사용한 값은 문서화하지 않는다. 아직 계정 연결, 자동 제작·채집, 생텀 DB 동기화는 미구현이다.

요청별 지원 여부의 근거와 제한은 [CAPABILITY_AUDIT.md](./CAPABILITY_AUDIT.md)에 기록한다. CLI 기능 목록에 없는 정보를 게임 화면·다른 사람 정보·보유 재화에서 억지로 역산해 완료 상태로 저장하지 않는다.

게임 내 `마비노기 모바일 AI 커넥터 Beta` 스위치와 별도 설치 프로그램 `AI(아님)커넥터` 오버레이는 다르다. 한설은 게임 내 스위치가 켜진 것을 확인했고, 별도 오버레이는 이 시점에 실행하지 않았다. 이 둘을 같은 연결 표시로 취급하지 않는다.
